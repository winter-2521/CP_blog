#グラフ #DFS #閉路

ライブラリ：[cycle_detection.hpp](https://github.com/winter-2521/cp-library/blob/main/graph/cycle_detection.hpp)

## 1. 概要

本記事では、グラフに **閉路**（同じ頂点に戻ってくる道）があるかを判定し、あれば 1 つ求める方法を、有向グラフと無向グラフのそれぞれについて解説します。どちらも深さ優先探索（DFS）1 回、$O(n + m)$ でできます。

>[!問題] 問題 1：Cycle Detection (Directed)（Library Checker）
>$N$ 頂点 $M$ 辺の有向グラフの閉路を 1 つ、使う辺の番号の列で出力してください（同じ辺は 2 回使わない）。なければ $-1$。（$N, M \le 5 \times 10^5$）

>[!問題] 問題 2：Cycle Detection (Undirected)（Library Checker）
>$N$ 頂点 $M$ 辺の無向グラフ（多重辺・自己ループあり）の閉路を 1 つ、頂点の列と辺の列で出力してください（頂点も辺も重複しない）。なければ $-1$。（$N, M \le 5 \times 10^5$）

## 2. 前提知識

- 深さ優先探索（DFS）と DFS 木
- スタック

## 3. 素朴な方法

各辺 $u \to v$ について「$v$ から $u$ に戻れるか」を BFS で調べれば、有向グラフの閉路が分かります。しかし辺ごとに $O(n + m)$ かかり、全体 $O(m(n + m))$ で間に合いません。DFS 1 回でまとめて調べます。

## 4. 有向グラフ

### 4.1. 頂点の 3 つの状態

DFS で、各頂点を次の 3 つの状態に分けます。

| 状態 | 意味 |
| --- | --- |
| 未訪問 | まだ来ていない |
| **探索中** | 訪問したが、まだ全部の辺を調べ終わっていない（今の DFS の道の上にある） |
| 終了 | 全部の辺を調べ終わった |

探索中の頂点は、ちょうど「根から今いる頂点までの DFS の道」に並んでいます。

### 4.2. 閉路の見つけ方

今いる頂点 $v$ から辺 $v \to w$ を調べたとき、

- $w$ が未訪問 → $w$ に進む。
- $w$ が **探索中** → $w$ は今の道の上（$v$ の祖先か $v$ 自身）にあるので、「道の $w$ から $v$ までの部分」＋「辺 $v \to w$」が閉路です。
- $w$ が終了 → 何もしない（$w$ から先はもう調べ終わっていて、閉路はなかった）。

閉路を出力するには、各頂点に「どの辺で来たか」（`par_edge`）を記録しておき、$v$ から $w$ まで逆にたどります。

### 4.3. 例で追う

辺 0: $0 \to 1$、辺 1: $1 \to 2$、辺 2: $2 \to 3$、辺 3: $3 \to 1$、辺 4: $3 \to 4$ のグラフ（閉路は $1 \to 2 \to 3 \to 1$）。

| 手順 | 今いる頂点 | 調べる辺 | 行き先の状態 | 動作 |
| --- | --- | --- | --- | --- |
| 1 | 0 | 辺 0 ($0 \to 1$) | 未訪問 | 1 へ（`par_edge[1] = 0`） |
| 2 | 1 | 辺 1 ($1 \to 2$) | 未訪問 | 2 へ（`par_edge[2] = 1`） |
| 3 | 2 | 辺 2 ($2 \to 3$) | 未訪問 | 3 へ（`par_edge[3] = 2`） |
| 4 | 3 | 辺 3 ($3 \to 1$) | **探索中** | 閉路発見 |

3 から `par_edge` をたどって 1 まで戻ると辺 2, 1、それに辺 3 を足して逆順にすると、閉路は **辺 1, 2, 3**（$1 \to 2 \to 3 \to 1$）です。ライブラリの出力も `1 2 3` です。

### 4.4. なぜ正しいか

- 見つけたものは確かに閉路です。
- 逆に閉路があれば、閉路上で最初に訪問される頂点を $w$ とすると、$w$ が探索中の間に閉路上の他の頂点が全部訪問され、閉路で $w$ の直前の頂点から $w$ への辺を調べるときに $w$ は探索中なので、必ず見つかります（終了した頂点からは閉路が出ていないことも同じ理由で分かります）。

## 5. 無向グラフ

### 5.1. 親への辺を区別する

無向グラフでは、辺 $\{v, w\}$ を $v$ から $w$ へ下ったあと、$w$ から同じ辺で $v$ に戻るのは閉路ではありません。そこで「$w$ に来た辺」は飛ばします。ここで **頂点ではなく辺の番号で** 区別するのが大事です。$v$ と $w$ の間に辺が 2 本（多重辺）あれば、それは長さ 2 の閉路だからです。

### 5.2. 閉路の見つけ方

DFS で各頂点の深さを記録します。今いる頂点 $v$ から、来た辺以外の辺 $\{v, w\}$ を調べたとき、

- $w$ が未訪問 → $w$ に進む。
- $w$ が訪問済みで **$v$ より浅い** → $w$ は $v$ の祖先なので（無向グラフの DFS では、木の辺以外の辺は必ず祖先と子孫を結びます）、「木の上の $w$ から $v$ までの道」＋「辺 $\{v, w\}$」が閉路です。

自己ループは、それだけで長さ 1 の閉路です。

### 5.3. 例

無向グラフ 辺 0: $\{0,1\}$、辺 1: $\{1,2\}$、辺 2: $\{2,3\}$、辺 3: $\{3,1\}$、辺 4: $\{3,4\}$。DFS は $0 \to 1 \to 2 \to 3$ と進み、3 から辺 3 で 1（深さ 1 < 3 の深さ 3）を見つけます。閉路は頂点 $1, 2, 3$、辺 $1, 2, 3$ です（ライブラリの出力と一致）。

## 6. 実装：再帰を使わない DFS

$N = 5 \times 10^5$ で一直線のグラフだと、再帰の深さが $5 \times 10^5$ になり、スタックが足りなくなることがあります。そこで「今どの辺まで調べたか」を頂点ごとに `it[v]` として持ち、自分でスタックを管理します。

```cpp
stk.push_back(s), state[s] = 1, it[s] = g.start[s];
while (!stk.empty()) {
    int v = stk.back();
    if (it[v] == g.start[v + 1]) {                  // v の辺を全部調べた
        state[v] = 2, stk.pop_back();
        continue;
    }
    int e = g.elist[it[v]++], to = edges[e].second;
    if (state[to] == 0) {                           // 未訪問
        par_edge[to] = e, state[to] = 1, it[to] = g.start[to];
        stk.push_back(to);
    } else if (state[to] == 1) {                    // 探索中 → 閉路
        vector<int> cyc{e};
        for (int x = v; x != to; x = edges[par_edge[x]].first) cyc.push_back(par_edge[x]);
        reverse(cyc.begin(), cyc.end());
        return cyc;
    }
}
```

隣接リストは `vector<vector<int>>` ではなく、1 本の配列（CSR：頂点 $v$ の隣接が `elist[start[v] .. start[v+1])`）で持つと速くなります。

## 7. 問題

【問題 1】は `find_cycle_directed(n, edges)`、【問題 2】は `find_cycle_undirected(n, edges)` で解けます。

【問題 3】有向グラフがトポロジカルソートできるか（閉路がないか）を判定し、できるならトポロジカル順を 1 つ出力してください。
（ヒント：4 節の DFS で、頂点が「終了」になった順を逆にするとトポロジカル順になります。）

## 8. まとめ

- 有向グラフ：DFS で「探索中」の頂点への辺を見つけたら閉路。
- 無向グラフ：来た辺（辺番号で区別）以外で祖先への辺を見つけたら閉路。多重辺・自己ループも閉路。
- 深いグラフでは再帰を使わず、頂点ごとの「次に調べる辺」とスタックで DFS する。
