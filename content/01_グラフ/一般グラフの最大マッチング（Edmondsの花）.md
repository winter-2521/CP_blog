#グラフ #マッチング

ライブラリ：[general_matching.hpp](https://github.com/winter-2521/cp-library/blob/main/graph/general_matching.hpp)

## 1. 概要

本記事では、**二部とは限らない** 無向グラフの最大マッチングを求める **Edmonds の花アルゴリズム**（blossom algorithm）を解説します。二部グラフと同じく「増加路を見つけて入れ替える」のですが、奇数長の閉路（**花**）があると増加路の探索が失敗することがあり、花を 1 頂点に **縮約** して対処します。$O(n^3)$ です。

>[!問題] 問題 1：Matching on General Graph（Library Checker）
>$N$ 頂点 $M$ 辺の無向グラフの最大マッチングを 1 つ出力してください。（$N \le 500$、$M \le N(N-1)/2$）

## 2. 前提知識

- [[二部マッチング（Hopcroft-Karp）]]（増加路と Berge の定理）
- BFS

## 3. 二部グラフのやり方がなぜ失敗するか

### 3.1. 交互木

空いている頂点 $r$ を根に、増加路を BFS で探すことを考えます。根から「外の辺（マッチングに入っていない辺）→ 内の辺（入っている辺）」を交互にたどって木（**交互木**）を作り、

- 根からの距離が偶数の頂点を **外側（even）**
- 奇数の頂点を **内側（odd）**

と呼びます。外側の頂点からは外の辺で、内側の頂点からは内の辺（相手）で進みます。外側の頂点から空いている頂点に着けば増加路です。

二部グラフでは、1 つの頂点が外側にも内側にもなることはないので、これで全ての増加路が見つかりました。

### 3.2. 失敗する例

6 頂点、辺 0–1, 1–2, 2–3, 3–4, 4–2, 3–5 のグラフで、今のマッチングが {1–2, 3–4} だとします。2, 3, 4 は三角形（奇閉路）です。

| 頂点 | 0 | 1 | 2 | 3 | 4 | 5 |
| --- | --- | --- | --- | --- | --- | --- |
| 相手 | なし | 2 | 1 | 4 | 3 | なし |

根 0 から交互木を作ると、

- 0（外側）→ 外の辺で 1（内側）→ 内の辺で 2（外側）
- 2 → 外の辺で 3（内側）→ 内の辺で 4（外側）

となり、3 は **内側** なので 3 から 5 へは進みません。ところが

$$
0 \xrightarrow{\text{外}} 1 \xrightarrow{\text{内}} 2 \xrightarrow{\text{外}} 4 \xrightarrow{\text{内}} 3 \xrightarrow{\text{外}} 5
$$

は増加路です。三角形を「2 → 4 → 3」と逆回りに通ると、3 が外側として現れるのです。奇閉路があると、頂点が外側にも内側にもなり得ます。

## 4. 花の縮約

### 4.1. 花

交互木を伸ばしている途中で、**外側の頂点どうしを結ぶ辺** $\{v, w\}$ を見つけたとします。$v$ と $w$ の最も近い共通祖先を $b$ とすると、木の上の $b \to v$、辺 $v$–$w$、木の上の $w \to b$ は奇数長の閉路です。これを **花**、$b$ を花の **根（base）** と呼びます。

例では、外側の 2 から辺を調べているときに辺 2–4 が見つかり、4 も外側です。共通祖先は 2 で、花は {2, 3, 4}、根は 2 です。

### 4.2. 縮約してよい理由

花の中のどの頂点 $x$ についても、根 $b$ から花の中を **どちらかの向きに回れば**、$x$ に「外側として」着けます（偶数長の向きを選ぶ）。だから **花全体を外側の 1 頂点 $b$ とみなして** 探索を続けてよく、縮約したグラフで増加路が見つかれば、花の中を適切な向きに回ることで元のグラフの増加路に戻せます（Edmonds の定理）。

### 4.3. 例で追う

| 手順 | 取り出す頂点 | 調べる辺 | 動作 |
| --- | --- | --- | --- |
| 1 | 0 | 0–1 | 1 を内側に（`par[1] = 0`）、相手 2 を外側としてキューへ |
| 2 | 2 | 2–3 | 3 を内側に（`par[3] = 2`）、相手 4 を外側としてキューへ |
| 3 | 2 | 2–4 | 4 は外側 → **花** {2, 3, 4}、根 2。花の頂点の `base` を 2 にし、内側だった 3 も外側としてキューへ。花の中を逆回りに戻れるよう `par[4] = 2` とする |
| 4 | 4 | 4–3, 4–2 | 同じ花の中なので飛ばす |
| 5 | 3 | 3–5 | 5 は空いている → **増加路発見** |

5 から `par` と相手をたどって入れ替えます。

| 入れ替え | 組む 2 頂点 | 次へ（元の相手） |
| --- | --- | --- |
| 1 | 5 – 3（`par[5] = 3`） | 3 の元の相手 4 |
| 2 | 4 – 2（`par[4] = 2`） | 2 の元の相手 1 |
| 3 | 1 – 0（`par[1] = 0`） | 0 は空いていた → 終わり |

マッチングは {0–1, 2–4, 3–5} の 3 本になりました（ライブラリの出力と一致）。

## 5. 実装

縮約は、グラフを作り直さず **各頂点の `base`（属している花の根）** を書き換えるだけで表します。

### 5.1. 共通祖先

```cpp
auto lca = [&](int a, int b) {
    stamp++;
    while (true) {                      // a から根まで登って印を付ける
        a = base[a];
        mark[a] = stamp;
        if (mate[a] < 0) break;         // 交互木の根 (空いている頂点)
        a = par[mate[a]];               // 外側 → 相手 (内側) → その親 (外側)
    }
    while (true) {                      // b から登って最初に印のある頂点
        b = base[b];
        if (mark[b] == stamp) return b;
        b = par[mate[b]];
    }
};
```

### 5.2. 花の道に印を付ける

```cpp
// v から花の根 b まで登りながら，花に入る頂点に印を付け，逆回りできるよう par を張り替える
auto mark_path = [&](int v, int b, int child) {
    while (base[v] != b) {
        in_blossom[base[v]] = in_blossom[base[mate[v]]] = 1;
        par[v] = child;
        child = mate[v];
        v = par[mate[v]];
    }
};
```

### 5.3. 探索の本体

```cpp
for (int to : g[v]) {
    if (base[v] == base[to] || mate[v] == to) continue;        // 同じ花の中・相手
    if (to == root || (mate[to] >= 0 && par[mate[to]] >= 0)) { // to が外側 → 花
        int cur = lca(v, to);
        fill(in_blossom.begin(), in_blossom.end(), 0);
        mark_path(v, cur, to), mark_path(to, cur, v);
        for (int x = 0; x < n; x++)
            if (in_blossom[base[x]]) {
                base[x] = cur;
                if (!used[x]) used[x] = 1, que[qt++] = x;      // 内側だった頂点も外側として探索
            }
    } else if (par[to] < 0) {                                  // to は未訪問
        par[to] = v;
        if (mate[to] < 0) return to;                           // 増加路
        used[mate[to]] = 1, que[qt++] = mate[to];
    }
}
```

最初に貪欲に（空いている隣と組ませて）マッチングを作っておくと、増加路の探索の回数が減って速くなります。

## 6. 正しさ・計算量

- **正しさ**：花を縮約しても増加路の有無は変わらない（Edmonds の定理）ので、各始点から増加路を探し、見つからなければその始点は以後も使えません。全ての始点を試せば Berge の定理から最大です。
- **計算量**：1 回の探索で、花の縮約は $O(n)$ 回、それぞれ全頂点を見るので $O(n^2)$。辺を見るのが $O(m) = O(n^2)$。探索は $n$ 回なので全体 $O(n^3)$ です。

## 8. まとめ

- 増加路を交互木の BFS で探す。外側どうしを結ぶ辺が見つかったら奇閉路（花）。
- 花は外側の 1 頂点とみなして（縮約して）探索を続けてよい。縮約は `base` の書き換えで表す。
- 増加路は花の中を逆回りしながら `par` と相手をたどって入れ替える。全体 $O(n^3)$。
