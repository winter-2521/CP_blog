#グラフ #最小全域木 #UnionFind

ライブラリ：[minimum_spanning_tree.hpp](https://github.com/winter-2521/cp-library/blob/main/graph/minimum_spanning_tree.hpp)

## 1. 概要

本記事では、重み付き無向グラフの **最小全域木**（全ての頂点をつなぐ辺の集合のうち、重みの和が最小のもの）を求める **Kruskal 法** を解説します。辺を重みの小さい順に見て「つないでも閉路ができないなら採用する」だけで、Union-Find を使うと $O(m \log m)$ です。

>[!問題] 問題 1：Minimum Spanning Tree（Library Checker）
>$N$ 頂点 $M$ 辺の連結な重み付き無向グラフが与えられます。最小全域木の重みの和と、使う辺の番号を出力してください。（$N, M \le 5 \times 10^5$、重みは $0$ 以上 $10^9$ 以下）

## 2. 前提知識

- **全域木**：$n$ 頂点の連結グラフから辺を選んで作った、全ての頂点を含む木。辺はちょうど $n - 1$ 本で、閉路がありません。
- Union-Find（素集合データ構造）：「2 つの頂点が同じグループか」「2 つのグループをまとめる」がほぼ $O(1)$ でできる（[[ポテンシャル付きUnion-Find]] の前半で解説しています）。

## 3. 素朴な方法

辺を $n - 1$ 本選ぶ組合せを全部試し、木になっているものの中で最小を取れば答えは出ます。しかし組合せは $\binom{m}{n-1}$ 通りあり、$n = 10$ でも使えません。

そこで「軽い辺から貪欲に取る」ことを考えます。

## 4. Kruskal 法

### 4.1. アルゴリズム

1. 辺を重みの小さい順に並べる。
2. 順に見ていき、その辺を加えても **閉路ができないなら** 採用する（閉路ができるなら捨てる）。
3. $n - 1$ 本採用したら終わり。

「閉路ができる」とは「両端がすでに（採用した辺で）つながっている」ことです。

### 4.2. 例で追う

5 頂点 7 辺のグラフで試します。

| 辺番号 | 両端 | 重み |
| --- | --- | --- |
| 0 | 0 – 1 | 4 |
| 1 | 0 – 2 | 3 |
| 2 | 1 – 2 | 1 |
| 3 | 1 – 3 | 2 |
| 4 | 2 – 3 | 4 |
| 5 | 3 – 4 | 2 |
| 6 | 2 – 4 | 5 |

重みの小さい順（同じ重みは番号順）に見ていきます。「グループ」は採用した辺でつながっている頂点の集まりです。

| 手順 | 辺 | 重み | 両端のグループ | 判定 | 採用後のグループ |
| --- | --- | --- | --- | --- | --- |
| 1 | 2 (1–2) | 1 | {1}, {2} | 採用 | {0} {1,2} {3} {4} |
| 2 | 3 (1–3) | 2 | {1,2}, {3} | 採用 | {0} {1,2,3} {4} |
| 3 | 5 (3–4) | 2 | {1,2,3}, {4} | 採用 | {0} {1,2,3,4} |
| 4 | 1 (0–2) | 3 | {0}, {1,2,3,4} | 採用 | {0,1,2,3,4} |
| 5 | 0 (0–1) | 4 | 同じ | 捨てる | |
| 6 | 4 (2–3) | 4 | 同じ | 捨てる | |
| 7 | 6 (2–4) | 5 | 同じ | 捨てる | |

採用した辺は 2, 3, 5, 1 で、重みの和は $1 + 2 + 2 + 3 = 8$ です（ライブラリの出力も `8` と `2 3 5 1`）。

### 4.3. なぜ正しいか（カット性質）

頂点を 2 つのグループ $S$ と $V \setminus S$ に分けたとき、間をまたぐ辺のうち **最も軽い辺** $e$ は、ある最小全域木に必ず含まれます。

理由：$e$ を含まない最小全域木 $T$ があったとします。$T$ に $e$ を足すと閉路が 1 つでき、その閉路は $S$ と $V \setminus S$ を行って帰ってくるので、$e$ 以外にもまたぐ辺 $f$ を含みます。$T$ から $f$ を抜いて $e$ を足すと、また全域木になり、重みは $w(e) - w(f) \le 0$ だけ変わります。つまり $e$ を含む最小全域木が作れます。

Kruskal 法が辺 $e = (u, v)$ を採用するとき、$S$ = 「$u$ のグループ」とすると、$e$ はまたぐ辺の中で最も軽い（もっと軽いまたぐ辺があれば、先に見たときに採用されていて $v$ も $S$ に入っているはず）ので、カット性質から採用して問題ありません。

## 5. 閉路の判定を速くする

### 5.1. 素朴な判定

「両端がつながっているか」を、採用した辺だけのグラフで毎回 DFS して調べると、1 回 $O(n)$、全体で $O(nm)$ かかります。$n, m = 5 \times 10^5$ では間に合いません。

### 5.2. Union-Find

グループを Union-Find で管理すれば、

- 判定：`find(u) == find(v)`
- 採用：`unite(u, v)`

がどちらもほぼ $O(1)$（正確には $O(\alpha(n))$）です。全体の計算量はソートの $O(m \log m)$ で決まります。

## 6. 実装

```cpp
template <class T>
pair<T, vector<int>> minimum_spanning_tree(int n, const vector<tuple<int, int, T>> &edges) {
    int m = edges.size();
    vector<pair<T, int>> ord(m);
    for (int i = 0; i < m; i++) ord[i] = {get<2>(edges[i]), i};
    sort(ord.begin(), ord.end());                 // (重み, 番号) の順
    vector<int> par(n, -1);                       // 根なら -(サイズ)
    auto find = [&](int x) {
        while (par[x] >= 0) {
            if (par[par[x]] >= 0) par[x] = par[par[x]];   // 経路を半分にする
            x = par[x];
        }
        return x;
    };
    T total = 0;
    vector<int> used;
    for (auto &[w, i] : ord) {
        int a = find(get<0>(edges[i])), b = find(get<1>(edges[i]));
        if (a == b) continue;                     // 閉路ができる
        if (par[a] > par[b]) swap(a, b);          // 大きい方に小さい方をつなぐ
        par[a] += par[b], par[b] = a;
        total += w, used.push_back(i);
    }
    return {total, used};
}
```

- 辺そのものを並べ替えるより、(重み, 番号) の組を並べ替えた方がコピーが軽く速くなります。
- `find` は再帰を使わず、たどりながら親を祖父に付け替える「経路半分化」にしています。

## 7. 問題

【問題 1】は `minimum_spanning_tree(n, edges)` の返り値をそのまま出力すれば解けます。

【問題 2】最小全域木の **最大の辺の重み** を最小にしたい（ボトルネック全域木）とき、どうすればよいでしょうか。
（ヒント：Kruskal 法で作った最小全域木は、最大の辺の重みも最小になっています。カット性質の証明と同じ交換で確かめられます。）

【問題 3】頂点 $u, v$ の間の道のうち「通る辺の重みの最大値」が最小になるものの、その最大値を、たくさんのクエリについて答えてください。
（ヒント：答えは最小全域木の上の $u$–$v$ パスの最大辺です。Kruskal 法で「この辺を採用した時点で $u$ と $v$ が初めてつながった」ときの重みでもあります。）

## 8. まとめ

- 辺を軽い順に見て、閉路ができなければ採用する（Kruskal 法）。
- 正しさは「またぐ辺のうち最も軽い辺は最小全域木に入れてよい」というカット性質から。
- 閉路の判定を Union-Find でやれば、全体はソートの $O(m \log m)$。
