#グラフ #マッチング #二部グラフ

ライブラリ：[bipartite_matching.hpp](https://github.com/winter-2521/cp-library/blob/main/graph/bipartite_matching.hpp)

## 1. 概要

本記事では、二部グラフの **最大マッチング**（端点を共有しない辺をできるだけ多く選ぶ）を求める方法を解説します。

1. **増加路** を 1 本ずつ探す素朴な方法（$O(nm)$）
2. 最短の増加路をまとめて探す **Hopcroft-Karp 法**（$O(m\sqrt{n})$）
3. 実用上さらに速くする工夫（Karp-Sipser の貪欲、全始点同時 BFS）

の順に説明します。

>[!問題] 問題 1：Matching on Bipartite Graph（Library Checker）
>左 $L$ 頂点・右 $R$ 頂点、$M$ 辺の二部グラフの最大マッチングを 1 つ出力してください。（$L, R \le 10^5$、$M \le 2 \times 10^5$）

## 2. 前提知識

- 二部グラフ（頂点を左右に分けて、辺は必ず左と右を結ぶ）
- BFS・DFS

## 3. 増加路

### 3.1. 定義

マッチング $M$ に対し、

- 両端が **どちらもマッチしていない** 頂点で、
- 「$M$ に入っていない辺」と「$M$ に入っている辺」を **交互に** たどる道

を **増加路** と呼びます。増加路の辺の「入っている／いない」を全部入れ替えると、マッチングの辺が 1 本増えます（入っていない辺の方が 1 本多いため）。

### 3.2. 例

左 4 頂点、右 4 頂点で、辺が

| 左 | 0 | 1 | 2 | 3 |
| --- | --- | --- | --- | --- |
| つながる右 | R0, R1 | R0 | R1, R2 | R2, R3 |

のグラフを考えます。貪欲に「左を順に見て、空いている右と組む」と、0–R0、1 は空きなし、2–R1、3–R2 でマッチング 3 本です。

ここで左 1 から

$$
1 \xrightarrow{\text{外}} \mathrm{R0} \xrightarrow{\text{内}} 0 \xrightarrow{\text{外}} \mathrm{R1} \xrightarrow{\text{内}} 2 \xrightarrow{\text{外}} \mathrm{R2} \xrightarrow{\text{内}} 3 \xrightarrow{\text{外}} \mathrm{R3}
$$

（外 = マッチングに入っていない辺、内 = 入っている辺）は増加路です。入れ替えると 1–R0、0–R1、2–R2、3–R3 の 4 本になります。

### 3.3. Berge の定理

**マッチングが最大 ⇔ 増加路が存在しない。** したがって「増加路を見つけて入れ替える」を見つからなくなるまで繰り返せば最大マッチングになります。

## 4. 素朴な方法：1 本ずつ DFS（Kuhn 法）

左の頂点を順に始点とし、DFS で増加路を探します。

- 左 $a$ から、まだ見ていない右 $b$ へ進む。
- $b$ が空いていれば増加路発見。
- $b$ が左 $a'$ とマッチしていれば、$a'$ から（別の右へ）DFS を続ける。

1 回の探索は $O(m)$、増加は最大 $\min(L, R)$ 回なので $O(nm)$ です。例では次のように進みます（空のマッチングから）。

| 始点 | 探索 | 結果 |
| --- | --- | --- |
| 0 | R0 が空き | 0–R0 |
| 1 | R0 は 0 と組んでいる → 0 から R1 が空き | 1–R0, 0–R1 |
| 2 | R1 は 0 → 0 から R0 は 1 → 1 から先なし。戻って 2 から R2 が空き | 2–R2 を追加 |
| 3 | R2 は 2 → 2 から R1 は 0 → 0 から R0 は 1 → 行き止まり。戻って 3 から R3 が空き | 3–R3 を追加 |

始点 3 の探索のように、行き止まりの長い道を何度も歩くのが遅さの原因で、$L, R = 10^5$ の意地悪なケースでは間に合いません。

## 5. Hopcroft-Karp 法

### 5.1. アイデア

1 本ずつではなく、**最短の増加路を、頂点を共有しないように極大にまとめて** 見つけて一度に入れ替えます。これを 1 フェーズとすると、

- フェーズのたびに最短増加路の長さが真に増える
- フェーズは $O(\sqrt{n})$ 回で終わる

ことが知られています（7 節）。

### 5.2. 1 フェーズの中身

1. **BFS**：左の空いている頂点を全部距離 0 として、「左 → 右（外の辺）→ その相手の左（内の辺）」と進み、各左頂点に距離（層）を付けます。空いている右に初めて届いた層で止めます。
2. **DFS**：左の空いている頂点から、**層が 1 つずつ増える方向にだけ** 進んで空いている右を探します。見つかったら入れ替え、行き止まりになった頂点は「このフェーズでは二度と使わない」印を付けます。

印を付けるおかげで、1 フェーズの DFS は全体で $O(m)$ です。

## 6. 実用上の高速化

Library Checker には、Hopcroft-Karp 法でも何十回もフェーズが必要な意地悪なケース（長い増加路が少しずつ現れる）があります。ライブラリでは次の 2 つを足しています。

### 6.1. Karp-Sipser の貪欲（初期マッチング）

**次数が 1 の頂点は、その唯一の相手と組ませてよい**（その頂点を使わない最大マッチングがあっても、相手の辺を付け替えれば同じ本数になる）ことを使います。

- 残りの次数が 1 の頂点があれば、それを相手と組ませて 2 頂点ともグラフから取り除く（隣の次数が減り、新たに次数 1 になる頂点が出る）。
- なければ、適当な頂点を適当な相手と組ませる。

3.2 節の例では、左 1（次数 1）と R3（次数 1）から連鎖的に 3–R3、2–R2、0–R1、1–R0 と決まり、この段階で最大マッチングになります。

### 6.2. 全始点同時の BFS

左の空いている頂点を **全部同時に** 始点とした BFS をし、各頂点に「どの始点から来たか（`root`）」と「1 つ前の左頂点（`prev`）」を付けます。

- 空いている右に着いたら、`prev` をたどって **その場で入れ替える**。
- その始点はもう増加したので、以後その `root` の頂点からは探索しない。

1 回の BFS は $O(m)$ で、互いに素な増加路がたくさん取れます。最短とは限らないので回数の保証はありませんが、実際にはとても少ない回数で終わります。そこで **$\sqrt{n}$ 回やっても終わらなければ Hopcroft-Karp 法に切り替え**、全体の $O(m\sqrt{n})$ を保証します。

3.2 節の貪欲（0–R0、2–R1、3–R2）から始めた場合を追います。空いている左は 1 だけです。

| キュー | 調べる辺 | 右の相手 | 動作 |
| --- | --- | --- | --- |
| 1 | 1–R0 | 0 | 0 を追加（root 1、prev 1） |
| 0 | 0–R0 | 0 | 自分自身（飛ばす） |
| 0 | 0–R1 | 2 | 2 を追加（prev 0） |
| 2 | 2–R1 | 0 | 訪問済み |
| 2 | 2–R2 | 3 | 3 を追加（prev 2） |
| 3 | 3–R2 | 2 | 訪問済み |
| 3 | 3–R3 | なし | **増加**：3–R3、prev をたどって 2–R2、0–R1、1–R0 |

ライブラリの出力（`4`、0–R1、1–R0、2–R2、3–R3）と一致します。Library Checker の最悪ケースでは、Hopcroft-Karp 法単体（約 620 ms）より約 3 倍速くなりました（約 210 ms）。

## 7. 正しさ・計算量

- **正しさ**：増加路がなくなるまで増加するので、Berge の定理から最大です。
- **Hopcroft-Karp 法のフェーズ数**：$\sqrt{n}$ フェーズ後は最短増加路の長さが $\sqrt{n}$ 以上です。今のマッチングと最大マッチングの差は互いに素な増加路に分解でき、それぞれ $\sqrt{n}$ 頂点以上使うので、残りは高々 $\sqrt{n}$ 本。あと $\sqrt{n}$ フェーズで終わります。各フェーズ $O(m)$ なので全体 $O(m\sqrt{n})$。
- ライブラリは「同時 BFS を最大 $\sqrt{n}$ 回（各 $O(m)$）」＋「Hopcroft-Karp 法」なので、やはり $O(m\sqrt{n})$ です。

## 8. 実装

全始点同時 BFS の部分です。

```cpp
vector<int> root(L, -1), prev(L), que(L);
while (rounds++ < lim_rounds) {                     // lim_rounds = √(L+R) + 1
    int qt = 0;
    for (int a = 0; a < L; a++)
        if (match_l[a] < 0) root[a] = a, prev[a] = -1, que[qt++] = a;
    bool updated = false;
    for (int qh = 0; qh < qt; qh++) {
        int a = que[qh];
        if (match_l[root[a]] >= 0) continue;        // この始点はもう増加した
        for (int i = start[a]; i < start[a + 1]; i++) {
            int b = adj[i], c = match_r[b];
            if (c < 0) {                            // 空いている右: その場で反転
                while (b >= 0) {
                    int t = match_l[a];
                    match_l[a] = b, match_r[b] = a;
                    b = t, a = prev[a];
                }
                res++, updated = true;
                break;
            }
            if (root[c] < 0) root[c] = root[a], prev[c] = a, que[qt++] = c;
        }
    }
    for (int k = 0; k < qt; k++) root[que[k]] = -1;  // 訪れた頂点だけ戻す
    if (!updated) return res;                       // 増加路なし → 最大
}
// ここに来たら Hopcroft-Karp 法
```

反転のループでは、`a` を `b` と組ませ、`a` の元の相手 `t` を 1 つ前の左頂点 `prev[a]` に渡す、を繰り返しています。隣接リストは 1 本の配列（CSR）で持っています。

## 10. まとめ

- マッチングが最大 ⇔ 増加路がない（Berge の定理）。増加路を見つけて入れ替えるのを繰り返す。
- 1 本ずつ DFS すると $O(nm)$。最短増加路をまとめて取る Hopcroft-Karp 法で $O(m\sqrt{n})$。
- 実用上は、次数 1 の頂点から組む貪欲と、全始点同時 BFS でその場で増加するのが速い。回数が多ければ Hopcroft-Karp 法に切り替えて計算量を保証する。
