## 1. 概要

本記事では、辺の重みが非負の有向グラフで、頂点 $s$ から $t$ への **ウォーク**（同じ頂点や辺を何度通ってもよい路）を **短い順に $K$ 個** 求める方法を解説します。Eppstein のアルゴリズムで、$O((n + m) \log m + K \log K)$ です。

>[!問題] 問題 1：K-Shortest Walk（Library Checker）
>$N$ 頂点 $M$ 辺の有向グラフ（重み $c_i \ge 0$）で、$s$ から $t$ への 1 番目から $K$ 番目に短いウォークの長さを出力してください（なければ $-1$）。長さが同じでも、通る辺の列が違えば別のウォークです。（$N, M, K \le 3 \times 10^5$）

## 2. 前提知識

- ダイクストラ法
- 優先度付きキュー（ヒープ）
- 永続データ構造の考え方（変わった部分だけ作り、残りは共有する）：[[永続キュー]]

## 3. 素朴な方法

「(ここまでの長さ, 今いる頂点)」を優先度付きキューに入れ、取り出すたびに全ての出ていく辺で伸ばしたものを入れる、を繰り返します。$t$ を $k$ 回目に取り出したときの長さが $k$ 番目に短いウォークです（ダイクストラ法で、同じ頂点を何度も取り出すことを許したもの）。

正しく求まりますが、キューに入る状態の数は、$K$ 番目のウォークより短いウォークの **途中の状態全部** なので、指数的に増えることがあり、間に合いません。ライブラリの単体テストでは、この方法を小さいグラフでの正解として使っています。

## 4. 例

3 頂点、辺 0: $0 \to 1$（重み 1）、1: $1 \to 2$（1）、2: $0 \to 2$（3）、3: $2 \to 0$（1）。$s = 0$, $t = 2$。

短い順のウォークは次の通りです。

| 順位 | ウォーク | 長さ |
| --- | --- | --- |
| 1 | $0 \to 1 \to 2$ | 2 |
| 2 | $0 \to 2$ | 3 |
| 3 | $0 \to 1 \to 2 \to 0 \to 1 \to 2$ | 5 |
| 4 | $0 \to 2 \to 0 \to 1 \to 2$ | 6 |
| 5 | $0 \to 1 \to 2 \to 0 \to 2$ | 6 |
| 6 | $0 \to 2 \to 0 \to 2$ | 7 |

## 5. 最短路木と「寄り道」

### 5.1. $t$ への最短路木

まず、辺を逆向きにしたグラフで $t$ からダイクストラ法をして、各頂点から $t$ への最短距離 $\mathrm{dist}[v]$ を求めます。各頂点 $v$ について、$\mathrm{dist}[v] = c_e + \mathrm{dist}[w]$ となる辺 $e = (v \to w)$ を 1 本選ぶと、それらは $t$ を根とする木になります（**最短路木**）。

例では $\mathrm{dist} = [2, 1, 0]$ で、最短路木の辺は辺 0（$0 \to 1$）と辺 1（$1 \to 2$）です。

### 5.2. 寄り道とそのコスト

最短路木に使わない辺 $e = (u \to w, c)$ を **寄り道** と呼び、

$$\delta(e) = c + \mathrm{dist}[w] - \mathrm{dist}[u] \ (\ge 0)$$

をその **追加コスト** とします。「$u$ にいるとき、最短路の代わりに $e$ を通ると、最短より $\delta(e)$ だけ長くなる」という意味です。

例では、

| 寄り道 | 辺 | $\delta$ |
| --- | --- | --- |
| 辺 2 | $0 \to 2$（3） | $3 + 0 - 2 = 1$ |
| 辺 3 | $2 \to 0$（1） | $1 + 2 - 0 = 3$ |

### 5.3. ウォーク = 寄り道の列

どのウォークも、「最短路木に沿って進み、ときどき寄り道をする」と見られます。逆に、寄り道の列 $e_1, e_2, \ldots, e_k$ が決まれば、

- $s$ から最短路木を進んで $e_1$ の始点へ（$e_1$ の始点は、$s$ から木で $t$ へ向かう途中になければならない）
- $e_1$ を通り、その行き先から木を進んで $e_2$ の始点へ（同様）
- …

とウォークが一意に決まり、長さは

$$\mathrm{dist}[s] + \delta(e_1) + \delta(e_2) + \cdots + \delta(e_k)$$

です。例えば $0 \to 2 \to 0 \to 1 \to 2$ は、寄り道 [辺 2, 辺 3] で、長さ $2 + 1 + 3 = 6$ です。

したがって問題は、「**正しくつながる寄り道の列を、$\delta$ の和の小さい順に $K$ 個列挙する**」になります。

## 6. 寄り道のヒープ

### 6.1. $H[v]$

頂点 $v$ にいるとき、次に使える寄り道は「$v$ から最短路木で $t$ に向かう途中の頂点（$v$ を含む）から出る寄り道」全部です。これを $\delta$ をキーとするヒープ $H[v]$ にまとめます。

$$H[v] = H[\text{木での } v \text{ の次の頂点}] + (v \text{ から出る寄り道})$$

なので、$H[v]$ は木の親の $H$ に $v$ の寄り道を足したものです。全部コピーすると $O(nm)$ になるので、**永続 leftist heap**（併合で変わったノードだけ新しく作り、残りは共有するヒープ）を使います。

例では $H[2] = \{\text{辺 3}(\delta=3)\}$、$H[1] = H[2]$（1 から出る寄り道はない）、$H[0] = H[1] + \{\text{辺 2}(\delta=1)\} = \{\text{辺 2}(1), \text{辺 3}(3)\}$ です。

### 6.2. 次の候補の作り方

寄り道の列を、「最後の寄り道 $x$ が、あるヒープの中のどのノードか」で表します。今の列（長さ $d$、最後の寄り道 $x$）から作る次の候補は 2 通りです。

1. **最後の寄り道を、ヒープの中の $x$ の子に替える**：長さ $d - \delta(x) + \delta(\text{子})$。ヒープなので子の方が $\delta$ が大きく、長さは増えるか同じ。
2. **最後に寄り道を 1 つ足す**：$x$ の行き先 $w$ から使えるヒープ $H[w]$ の最小（根）を足す。長さ $d + \delta(H[w] \text{ の根})$。

最初は「寄り道なし」（長さ $\mathrm{dist}[s]$）と、$H[s]$ の根を 1 つ使う候補（長さ $\mathrm{dist}[s] + \delta(H[s] \text{ の根})$）から始め、優先度付きキューで長さの小さい順に取り出していきます。どの寄り道の列も、ちょうど 1 通りの手順でたどり着くので、重複も漏れもありません。

### 6.3. 例で追う

| 取り出し | 長さ | 列 | キューに入れる候補 |
| --- | --- | --- | --- |
| 1 | 2 | 寄り道なし | （最初に）$H[0]$ の根 辺 2：$2 + 1 = 3$ |
| 2 | 3 | [辺 2] | 子に替える：辺 3 で $3 - 1 + 3 = 5$。足す：辺 2 の行き先 2 の $H[2]$ の根 辺 3 で $3 + 3 = 6$ |
| 3 | 5 | [辺 3] | 足す：辺 3 の行き先 0 の $H[0]$ の根 辺 2 で $5 + 1 = 6$ |
| 4 | 6 | [辺 2, 辺 3] | 足す：$H[0]$ の根で $6 + 1 = 7$ |
| 5 | 6 | [辺 3, 辺 2] | … |
| 6 | 7 | [辺 2, 辺 3, 辺 2] … | |

長さ $2, 3, 5, 6, 6, 7$ は 4 節の表と一致します（ライブラリの出力とも一致）。

## 7. 実装

```cpp
// 永続 leftist heap の併合 (変わるノードだけコピー)
auto merge = [&](auto self, int a, int b) -> int {
    if (!a || !b) return a ^ b;
    if (hp[b].key < hp[a].key) swap(a, b);
    Node nd = hp[a];                       // コピー
    nd.r = self(self, nd.r, b);
    if (hp[nd.l].rk < hp[nd.r].rk) swap(nd.l, nd.r);
    nd.rk = hp[nd.r].rk + 1;
    hp.push_back(nd);
    return hp.size() - 1;
};
// H[v] = H[木の次] + v の寄り道 (t に近い順に作る)
...
// 列挙
res.push_back(dist[s]);
if (H[s]) pq.push({dist[s] + hp[H[s]].key, H[s]});
while ((int)res.size() < K && !pq.empty()) {
    auto [d, x] = pq.top();
    pq.pop();
    res.push_back(d);
    for (int c : {hp[x].l, hp[x].r})                     // 1. 子に替える
        if (c) pq.push({d - hp[x].key + hp[c].key, c});
    int nh = H[hp[x].to];                                // 2. 行き先から 1 つ足す
    if (nh) pq.push({d + hp[nh].key, nh});
}
```

## 8. 計算量

- ダイクストラ法：$O((n + m) \log n)$
- ヒープの構築：寄り道 1 本につき永続ヒープの併合 $O(\log m)$
- 列挙：1 回取り出すごとに候補を 3 つまで入れるので、$O(K \log K)$

## 9. 問題

【問題 1】は `k_shortest_walks(n, edges, s, t, K)` で求めた長さを出力し、足りない分は $-1$ にすれば解けます。

【問題 2】同じ頂点を 2 回通らない「路」（パス）の中で $K$ 番目に短いものを求めてください。
（ヒント：ウォークではなくパスに限ると、Eppstein の方法は使えません。Yen のアルゴリズムで $O(Kn(m + n \log n))$ です。）

## 10. まとめ

- $t$ への最短路木を作り、木に使わない辺を「寄り道」、その追加コストを $\delta$ とすると、ウォークは寄り道の列と 1 対 1 に対応する。
- 各頂点から使える寄り道を、木の親と共有する永続ヒープにまとめる。
- 「最後の寄り道をヒープの子に替える」「寄り道を 1 つ足す」で次の候補を作り、優先度付きキューで小さい順に取り出す。
