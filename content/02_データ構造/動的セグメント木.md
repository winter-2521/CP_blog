## 何ができるアルゴリズムか？

添字の範囲 $n$ が $10^9$ や $10^{18}$ と大きくて配列を確保できないときのセグ木・遅延セグ木。**触った部分だけノードを作る**。座標圧縮と違い、クエリを先読みしなくてよい（オンライン）。

>[!問題] Point Set Range Composite (Large Array) (Library Checker)
>Point Set Range Composite で $N \le 10^9$、はじめ全て $f_i(x) = x$。$Q \le 5 \times 10^5$

>[!問題] Range Affine Range Sum (Large Array) (Library Checker)
>Range Affine Range Sum で $N \le 10^9$、はじめ全て $0$。$Q \le 10^5$

## 計算量

| | 一点更新 | 区間作用 | 区間積 | メモリ |
| --- | --- | --- | --- | --- |
| 動的セグ木 | $O(\log n)$ | - | $O(\log n)$ | $O(\text{更新回数})$ |
| 動的遅延セグ木 | $O(\log n)$ | $O(\log n)$ | $O(\log n)$ | $O(q \log n)$ |

## 具体例で理解する

### 配列が作れないときの 2 つの方法

$n = 10^9$ だと長さ $2n$ の配列は作れない。

1. **座標圧縮**：クエリを全部先に読んで、出てくる座標だけに番号を振り直す。速いが、先読みできないと使えない。
2. **動的セグ木**：必要になったノードだけその場で作る。先読み不要。

素朴な動的セグ木は「根だけ作っておき、降りるときに子がなければ作る」。1 回の一点更新で根から葉まで $\log_2 n \approx 30$ 個のノードを作るので、メモリが重い。

### 一点更新だけの場合：1 ノードに 1 要素

**各ノードが持っているもの**：

| 名前 | 意味 |
| --- | --- |
| `idx`, `val` | このノードが直接持つ 1 要素の位置と値 |
| `prod` | 部分木全体の積（左の部分木 · `val` · 右の部分木） |
| `l`, `r` | 子（なければ空） |

ノードの区間は普通のセグ木と同じ（根は $[0, n)$、子は半分ずつ）。各ノードは区間内のどこか 1 つの位置 `idx` を担当し、**左の子孫の位置 < `idx` < 右の子孫の位置** を保つ（二分探索木と同じ）。

**set(p, x) の手順**：根から、

1. ノードがなければ、`idx` = $p$ のノードを作って終わり。
2. `idx` = $p$ なら `val` を書き換える。
3. $p$ がノードの区間の左半分なら左へ降りる。ただしノードの `idx` が $p$ より左なら、そのままだと順序が崩れるので **ノードの (`idx`, `val`) と (p, x) を入れ替えて** から、元の要素を左に持って降りる。右半分なら左右反転。
4. 戻りながら `prod` を計算し直す。

### 例で追う（$n = 16$、位置 5, 12, 3, 7 に値を設定）

1. **set(5)**：木が空なので、根 `idx`=5。
2. **set(12)**：根の区間 $[0,16)$ の中央は 8。$12 \ge 8$ → 右へ。根の 5 < 12 で順序 OK。右の子 `idx`=12 を作る。
3. **set(3)**：$3 < 8$ → 左へ。根の 5 > 3 で順序 OK。左の子 `idx`=3 を作る。
4. **set(7)**：$7 < 8$ → 左へ行きたいが、根の 5 は 7 より左で、7 を左に置くと「左の子孫 < 自分」が崩れる。そこで **根を 7 に入れ替え、5 を左に持って降りる**。左の子（`idx`=3、区間 $[0,8)$、中央 4）では $5 \ge 4$ → 右へ。3 < 5 で順序 OK。右の子 `idx`=5 を作る。

```
             [7]          区間 [0,16)
            /   \
         [3]     [12]     区間 [0,8) / [8,16)
            \
            [5]           区間 [4,8)
```

左から順にたどると $3, 5, 7, 12$。ノード数は設定した位置の個数（4 個）と同じ。

**prod(l, r) の手順**：根から、ノードの区間が $[l, r)$ と重ならなければ $e$、完全に含まれれば `prod`。一部だけなら「左の子の結果 · (`idx` が $[l, r)$ に入っていれば `val`) · 右の子の結果」。左 < 自分 < 右の順に並んでいるので、非可換でも正しい。

### 区間作用がある場合

**各ノードが持っているもの**：区間の値（和なら和と長さ）、`lazy`、子（まだ作っていなければ空）。

ポイントは「まだ子を作っていないノード」の中身は **全て初期値 $x_0$**（に、そのノードの `lazy` がかかったもの）だということ。全体の大きさを 2 冪に切り上げておくと、ノードの区間の長さは必ず $1, 2, 4, \ldots$ なので、長さ $2^k$ の区間の値 $x_0^{2^k}$（和なら「$x_0 \times 2^k$」）を前計算しておけば、新しいノードの値がすぐ決まる。

**例**：$n = 8$、はじめ全て 0、$[2, 5)$ に $+5$。

- 根 $[0,8)$：一部だけ重なる → 子 $[0,4)$, $[4,8)$ を作って（値は和 0）lazy を下ろし、降りる。
- $[0,4)$：一部 → 子 $[0,2)$, $[2,4)$ を作る。$[0,2)$ は範囲外。$[2,4)$ は完全に含まれる → 和 $0 + 5 \times 2 = 10$、`lazy` = +5。
- $[4,8)$：一部 → 子 $[4,6)$, $[6,8)$ を作る。$[4,6)$ も一部 → 子 $[4,5)$, $[5,6)$ を作る。$[4,5)$ は完全に含まれる → 和 5。
- 戻りながら和を計算し直す：根の和 = 15。

作ったノードは 8 個（根を含めて 9 個）。$n = 10^9$ でも 1 回あたり $4 \log_2 n$ 個程度。

**区間和ではノードを作らない**：例えば $[3, 8)$ の和を聞かれたら、$[2,4)$ は子がないまま区間の一部 $[3, 4)$ だけ必要になる。このときは「子がない ＝ 中身は全部 $x_0$ に `lazy` をかけたもの」なので、長さ 1 ぶん $0 \times 1$ に $+5$ をかけて 5、と直接計算する。$[4,5)$ の 5 と合わせて答え 10。

## 証明・仕組み

### 素朴な動的セグ木

根だけ作っておき、降りるときに子がなければ作る。1 回の操作で $O(\log n)$ 個のノードを作るので、メモリ $O(q \log n)$。$q = 5 \times 10^5$、$\log n = 30$ だと $1.5 \times 10^7$ ノードで重い。

### 一点更新だけなら：1 ノード 1 要素

各ノードに「担当区間の中の **1 要素**（位置 idx と値）」と部分木全体の積を持たせ、

> 左の子の部分木の位置 $<$ idx $<$ 右の子の部分木の位置

という順序（二分探索木の条件）を保つ。挿入で降りる途中、新しい位置の方がノードの idx より内側にあれば **入れ替えて** から降りる（左に降りるとき、ノードの idx が新しい位置より左なら交換、など）。こうすると順序が保たれ、ノード数 ＝ 値を設定した位置の個数。

区間積は普通のセグ木と同じく区間で枝刈りしながら降り、各ノードでは「左の部分木の積・自分の要素（区間内なら）・右の部分木の積」を順に掛ける。順序が保たれているので非可換でも正しい。深さは $\log n$ なので $O(\log n)$。

### 区間作用があるとき：2 冪に切り上げて初期値の冪を前計算

遅延セグ木は「まだ作っていない区間」の値が必要。大きさを $2^K$ に切り上げると、ノードの区間の長さは全て 2 冪なので、初期値 $x_0$ について $x_0^{2^k}$ を前計算しておけば、作ったばかりのノードの値が $O(1)$ で決まる。

push で子を作る（なければ作ってから作用を下ろす）。区間積では子を作りたくないので、**上から作用を持ち越して** 降りる。子がないノードの区間の一部 $[a, b)$ の積は、$x_0^{b-a}$（$b-a$ の 2 進展開で $x_0^{2^k}$ を掛ける）に、それまでの作用を適用したもの。
