#データ構造 #セグ木 #区間をsetで管理

ライブラリ：[sortable_segment_tree.hpp](https://github.com/winter-2521/cp-library/blob/main/data_structure/sortable_segment_tree.hpp)

## 何ができるアルゴリズムか？

各位置に（キー, 値）を持つ列に対して、一点更新・区間積に加えて **「区間をキーの昇順（降順）にソートする」** を、全体でならし $O((n + q)(\log n + \mathrm{LOG}))$ で処理する（$\mathrm{LOG}$ はキーのビット数）。

>[!問題] Point Set Range Sort Range Composite (Library Checker)
>3 つ組の列 $(p_i, a_i, b_i)$ に対して、一点変更 / $f_{r-1}(\cdots f_l(x))$（$f_i(x) = a_i x + b_i$）/ $[l, r)$ を $p_i$ の昇順にソート / 降順にソート を $Q$ 回処理せよ。$p_i$ は相異なる。$N, Q \le 10^5$

## 計算量

各操作ならし $O(\log n + \mathrm{LOG})$。メモリ $O(n \cdot \mathrm{LOG})$。

## 証明・仕組み

### ランで管理する

ソートした区間は「キーの順に並んだ塊」になる。列を **ソート済みの連続部分（ラン）** に分けて持つ（[[区間代入セグメント木（区間をsetで管理）]] と同じ発想）。各ランは「昇順か降順か」と、要素の集合を持つ。

- ランの先頭位置の集合を [[64分木（FastSet）]] で持つ。
- セグ木の「ランの先頭の位置」にそのランの積を置く（それ以外は単位元）。

### ランの中身：キーの 2 分トライ

各ランの要素を、キーの 2 分トライ（深さ LOG）で持つ。各ノードに

- 要素数
- 部分木の要素を **キーの昇順** に並べたときの積
- **キーの降順** に並べたときの積

を持つ。昇順の積は「左の子（キーが小さい）→ 右の子」、降順の積は「右 → 左」の順で掛ける。ランの積は向きに応じてどちらかを使う。

**区間ソート** $[l, r)$：

1. 位置 $l$ と $r$ でランを切る。
2. $[l, r)$ の内側のランのトライを全て **マージ** して 1 つのランにする（向きはソートの向き）。

**ランを切る**：先頭から $k$ 個とそれ以外に分けるのは、トライを **要素数で分割**（キーの小さい方から $k$ 個）。降順のランなら、先頭 $k$ 個はキーの大きい方なので、小さい方から（長さ $- k$）個で分割する。トライを根から 1 本の経路に沿って割るので、作るノードは $O(\mathrm{LOG})$ 個。

**区間積**：両端でランを切ってから、セグ木の区間積。**一点更新**：その位置の前後でランを切り、長さ 1 のランを作り直す。

### マージのならし計算量

2 つのトライのマージは、**両方に存在するノード** でだけ再帰し（片方にしかなければその部分木をそのまま使う）、重なったノードは片方が消える。つまりマージにかかる時間は「消えるノードの数」に比例する。

ノードが作られるのは、初期化（$n \cdot \mathrm{LOG}$ 個）・一点更新（$\mathrm{LOG}$ 個）・ランの分割（$\mathrm{LOG}$ 個、1 回の操作で高々 2〜4 回）だけ。消えるノードの総数は作ったノードの総数以下なので、マージの総コストは $O((n + q) \mathrm{LOG})$。

セグ木の更新は、ランを切る・ランを消すごとに $O(\log n)$。ランの数も同様に（作った数）で抑えられるので、全体 $O((n + q) \log n)$。

キーを座標圧縮すれば LOG を $\log n$ にできるが、オンラインにするためキーのビット数（$p_i \le 10^9$ なら 30）のトライにしている。消えたノードは再利用するので、メモリは同時に存在するノード数 $O(n \cdot \mathrm{LOG})$ で済む。

## 例題・類題

- [Point Set Range Sort Range Composite (Library Checker)](https://judge.yosupo.jp/problem/point_set_range_sort_range_composite)
- [ABC237 G - Range Sort Query](https://atcoder.jp/contests/abc237/tasks/abc237_g)：順列の区間ソートを繰り返した後の $X$ の位置。「$X$ 以上かどうか」の 0/1 列に直せば区間代入の遅延セグ木でも解ける。
- [Codeforces 558E - A Simple Task](https://codeforces.com/contest/558/problem/E)：文字列（26 種類）の区間ソート。文字ごとの個数を遅延セグ木で持って区間代入で解くのが想定だが、このデータ構造ならキーの種類数によらない。
- 「区間ソート」と「区間の集計」が混ざる問題全般。値がモノイドなので、ソート後の並びでの区間の積（関数の合成など）も求まる。
