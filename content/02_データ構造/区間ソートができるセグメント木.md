#データ構造 #セグ木 #区間をsetで管理

ライブラリ：[sortable_segment_tree.hpp](https://github.com/winter-2521/cp-library/blob/main/data_structure/sortable_segment_tree.hpp)

## 何ができるアルゴリズムか？

各位置に（キー, 値）を持つ列に対して、一点更新・区間積に加えて **「区間をキーの昇順（降順）にソートする」** を、全体でならし $O((n + q)(\log n + \mathrm{LOG}))$ で処理する（$\mathrm{LOG}$ はキーのビット数）。

>[!問題] Point Set Range Sort Range Composite (Library Checker)
>3 つ組の列 $(p_i, a_i, b_i)$ に対して、一点変更 / $f_{r-1}(\cdots f_l(x))$（$f_i(x) = a_i x + b_i$）/ $[l, r)$ を $p_i$ の昇順にソート / 降順にソート を $Q$ 回処理せよ。$p_i$ は相異なる。$N, Q \le 10^5$

## 計算量

各操作ならし $O(\log n + \mathrm{LOG})$。メモリ $O(n \cdot \mathrm{LOG})$。

## 具体例で理解する

### アイデア：ソートした区間は「まとまり（ラン）」として扱う

キーと値の組の列 $[(6,F), (3,C), (5,E), (1,A), (4,D), (2,B)]$ で $[1, 5)$ を昇順にソートすると $[(6,F) \mid (1,A), (3,C), (4,D), (5,E) \mid (2,B)]$。真ん中は「キーの昇順に並んだまとまり（ラン）」になる。

ランの中身は「どのキー（と値）が入っているか」と「昇順か降順か」さえ分かれば並び順が決まる。そこで、

- ソート ＝「区間内のランを全部 1 つに合体させ、向きを決める」
- 区間の積 ＝「区間の端でランを切ってから、ランごとの積を掛ける」

とする。[[区間代入セグメント木（区間をsetで管理）]] と同じ「ランで管理する」発想。

### 持っているもの

| 名前 | 意味 |
| --- | --- |
| `starts` | ランの先頭位置の集合 |
| `root[s]` | 位置 $s$ から始まるランの要素を入れた 2 分トライ |
| `desc[s]` | そのランが降順か |
| `seg` | セグ木。ランの先頭の位置に「そのランの積」、それ以外は単位元 |

**2 分トライ**：キーを 2 進数にして、上のビットから 0 なら左・1 なら右に振り分ける木。各ノードは

| 名前 | 意味 |
| --- | --- |
| `cnt` | 部分木の要素数 |
| `fwd` | 部分木の値を **キーの昇順** に掛けた積（= 左の子の `fwd` · 右の子の `fwd`） |
| `bwd` | **キーの降順** に掛けた積（= 右の子の `bwd` · 左の子の `bwd`） |

を持つ（左の子の方がキーが小さいので）。ランの積は昇順なら根の `fwd`、降順なら根の `bwd`。

**例**：ラン $\{(1,A), (3,C), (4,D), (5,E)\}$ のトライ（キー 3 bit）

```
                      cnt=4 fwd=ACDE bwd=EDCA
                  0 /                       \ 1
       cnt=2 fwd=AC bwd=CA            cnt=2 fwd=DE bwd=ED
         0/        \1                  0/
      (1:A)       (3:C)          cnt=2 fwd=DE
                                   0/    \1
                                 (4:D)   (5:E)
```

（$1 = 001$, $3 = 011$, $4 = 100$, $5 = 101$。葉までの途中の 1 本道のノードは省略。）

### ランを切る：トライを要素数で分割する

**split_trie(v, k)**：トライ v を「キーの小さい方から $k$ 個」と「残り」に分ける。

1. 左の子の要素数を $c$ とする。
2. $k \le c$ なら：左の子を再帰的に $k$ 個と残りに分ける。「残り」と右の子をまとめた新しいノード w を作る。v には左の「$k$ 個」だけを残す。
3. $k > c$ なら：右の子を再帰的に $(k - c)$ 個と残りに分ける。w には右の「残り」だけ、v には左の子と右の「$(k-c)$ 個」を残す。
4. v と w の `cnt`・`fwd`・`bwd` を子から計算し直す。

1 段ごとに新しいノードを 1 個作るだけなので、作るノードはビット数個。

**例**：上のトライを $k = 2$ で分ける。根の左の子は $c = 2$ 個で $k \le c$。左の子を 2 個で分けると「全部」と「なし」。なので v（根）には左の子 $\{1, 3\}$ だけ、新しいノード w には右の子 $\{4, 5\}$ だけが入る。v は `cnt`=2・`fwd`=AC、w は `cnt`=2・`fwd`=DE。

ランが **降順** のときは、先頭 $k$ 個はキーの大きい方なので、「小さい方から（長さ − $k$）個」で分けて前後を入れ替える。

### ランを合体させる：トライのマージ

**merge(a, b)**：片方が空ならもう片方を返す。両方あれば、左の子同士・右の子同士を再帰的にマージして a につけ、b は捨てる。a の値を計算し直す。

キーが重ならない部分は「片方が空」になってすぐ終わるので、再帰するのは **両方にノードがある所だけ**。

### 例で追う

はじめ、各要素が長さ 1 のラン：`starts` = $\{0,1,2,3,4,5\}$。

**sort_asc(1, 5)**：位置 1, 5 は既にランの先頭なので切らなくてよい。位置 2, 3, 4 から始まるランのトライを、位置 1 のトライに順にマージする（上の図のトライになる）。2, 3, 4 を `starts` から消し、`seg` のその位置を $e$ に。`desc[1]` = 昇順、`seg[1]` = 根の `fwd` = ACDE。
`starts` = $\{0, 1, 5\}$、列は $[6F \mid 1A, 3C, 4D, 5E \mid 2B]$。

**prod(0, 3)**（答えは F·A·C）：区間の端 3 がランの途中なので切る。ラン（先頭 1、昇順）の先頭から $3 - 1 = 2$ 個で split_trie → 上の例の通り $\{1, 3\}$ と $\{4, 5\}$ に分かれる。`starts` に 3 を追加し、`seg[1]` = AC、`seg[3]` = DE。
`seg.prod(0, 3)` = $F \cdot AC \cdot e$ = **FAC**。

**sort_desc(0, 3)**：位置 0 のトライ $\{6\}$ と位置 1 のトライ $\{1, 3\}$ をマージ。6 = 110 は根から右、$\{1, 3\}$ は根から左なので、根で 2 つのトライが「右の子」と「左の子」として合わさるだけ（再帰はすぐ終わる）。`desc[0]` = 降順、`seg[0]` = 根の `bwd` = 右の `bwd` · 左の `bwd` = F · CA = FCA。
列は $[6F, 3C, 1A \mid 4D, 5E \mid 2B]$。

### なぜ速いのか

マージにかかる時間は「両方にノードがあった所の数」で、そこでは片方のノードが捨てられる。つまり **マージの時間 ≤ 捨てられるノードの数**。ノードを作るのは初期化（$n \times$ ビット数）・一点更新（ビット数）・分割（ビット数）だけで、捨てられるノードの合計は作ったノードの合計を超えない。だから 1 回のソートで大量にマージしても、全体ではならして 1 回あたり $O(\text{ビット数})$。

## 証明・仕組み

### ランで管理する

ソートした区間は「キーの順に並んだ塊」になる。列を **ソート済みの連続部分（ラン）** に分けて持つ（[[区間代入セグメント木（区間をsetで管理）]] と同じ発想）。各ランは「昇順か降順か」と、要素の集合を持つ。

- ランの先頭位置の集合を [[64分木（FastSet）]] で持つ。
- セグ木の「ランの先頭の位置」にそのランの積を置く（それ以外は単位元）。

### ランの中身：キーの 2 分トライ

各ランの要素を、キーの 2 分トライ（深さ LOG）で持つ。各ノードに

- 要素数
- 部分木の要素を **キーの昇順** に並べたときの積
- **キーの降順** に並べたときの積

を持つ。昇順の積は「左の子（キーが小さい）→ 右の子」、降順の積は「右 → 左」の順で掛ける。ランの積は向きに応じてどちらかを使う。

**区間ソート** $[l, r)$：

1. 位置 $l$ と $r$ でランを切る。
2. $[l, r)$ の内側のランのトライを全て **マージ** して 1 つのランにする（向きはソートの向き）。

**ランを切る**：先頭から $k$ 個とそれ以外に分けるのは、トライを **要素数で分割**（キーの小さい方から $k$ 個）。降順のランなら、先頭 $k$ 個はキーの大きい方なので、小さい方から（長さ $- k$）個で分割する。トライを根から 1 本の経路に沿って割るので、作るノードは $O(\mathrm{LOG})$ 個。

**区間積**：両端でランを切ってから、セグ木の区間積。**一点更新**：その位置の前後でランを切り、長さ 1 のランを作り直す。

### マージのならし計算量

2 つのトライのマージは、**両方に存在するノード** でだけ再帰し（片方にしかなければその部分木をそのまま使う）、重なったノードは片方が消える。つまりマージにかかる時間は「消えるノードの数」に比例する。

ノードが作られるのは、初期化（$n \cdot \mathrm{LOG}$ 個）・一点更新（$\mathrm{LOG}$ 個）・ランの分割（$\mathrm{LOG}$ 個、1 回の操作で高々 2〜4 回）だけ。消えるノードの総数は作ったノードの総数以下なので、マージの総コストは $O((n + q) \mathrm{LOG})$。

セグ木の更新は、ランを切る・ランを消すごとに $O(\log n)$。ランの数も同様に（作った数）で抑えられるので、全体 $O((n + q) \log n)$。

キーを座標圧縮すれば LOG を $\log n$ にできるが、オンラインにするためキーのビット数（$p_i \le 10^9$ なら 30）のトライにしている。消えたノードは再利用するので、メモリは同時に存在するノード数 $O(n \cdot \mathrm{LOG})$ で済む。

- [Point Set Range Sort Range Composite (Library Checker)](https://judge.yosupo.jp/problem/point_set_range_sort_range_composite)
- [ABC237 G - Range Sort Query](https://atcoder.jp/contests/abc237/tasks/abc237_g)：順列の区間ソートを繰り返した後の $X$ の位置。「$X$ 以上かどうか」の 0/1 列に直せば区間代入の遅延セグ木でも解ける。
- [Codeforces 558E - A Simple Task](https://codeforces.com/contest/558/problem/E)：文字列（26 種類）の区間ソート。文字ごとの個数を遅延セグ木で持って区間代入で解くのが想定だが、このデータ構造ならキーの種類数によらない。
- 「区間ソート」と「区間の集計」が混ざる問題全般。値がモノイドなので、ソート後の並びでの区間の積（関数の合成など）も求まる。
