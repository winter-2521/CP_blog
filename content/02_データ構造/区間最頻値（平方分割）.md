ライブラリ：[static_range_mode.hpp](https://github.com/winter-2521/cp-library/blob/main/data_structure/static_range_mode.hpp)

## 1. 概要

本記事では、静的な数列 $a$ について、区間 $[l, r)$ の **最頻値**（一番多く出てくる値）とその個数を $O(\sqrt n)$ で答える方法を解説します。クエリを先読みしなくてよい（オンライン）方法です。

>[!問題] 問題 1：Static Range Mode Query（Library Checker）
>長さ $N$ の数列に「$a_l, \ldots, a_{r-1}$ の最頻値とその個数」を $Q$ 回答えてください。（$N, Q \le 10^5$）

## 2. 前提知識

- 平方分割（列を長さ $B$ のブロックに分け、区間を「端数 + 完全なブロック」に分ける考え方）
- 値ごとの出現位置のリスト：[[区間の値の個数（Range Frequency）]]

## 3. 素朴な方法と、セグ木が使えない理由

区間を左から見て、値ごとの個数を数えながら最大を更新すれば、1 回 $O(r - l)$ です。全体 $O(nq) = 10^{10}$ で間に合いません。

和や最小値のようにセグメント木に乗せられないかと考えると、最頻値は **2 つの区間の答えから、つなげた区間の答えが作れません**。例えば

- 左の区間 $[1, 1, 2, 3]$ の最頻値は 1（2 個）
- 右の区間 $[2, 3, 3, 2]$ の最頻値は 2 か 3（2 個）

ですが、つなげた $[1, 1, 2, 3, 2, 3, 3, 2]$ の最頻値は 2 と 3（3 個）で、左の答え 1 は関係ありません。左右の最頻値以外の値が、合わせると最頻値になることもあります。

## 4. 平方分割

列を長さ $B$ のブロックに分けます。区間 $[l, r)$ は

- **左の端数**（$l$ を含むブロックの、$l$ から右の部分）
- **間の完全なブロックたち**
- **右の端数**（$r - 1$ を含むブロックの、$r - 1$ までの部分）

に分かれます。端数の要素は合わせて $2B$ 個以下です。

### 4.1. 最頻値の候補

次のことが言えます。

> 区間の最頻値は、「間の完全なブロックたちの最頻値」か「端数に出てくる値」のどれか。

端数に出てこない値の個数は、完全なブロックの中での個数と同じなので、完全なブロックの最頻値の個数を超えないからです。

そこで、

1. 完全なブロックの区間 $[b_i, b_j]$ の最頻値と個数は、**全ての $(b_i, b_j)$ の組について前計算** しておく（組は $(n/B)^2$ 個）。
2. 端数の各要素について、「その値を候補にしたら個数がいくつになるか」を調べる。

とします。2. を速くやる方法が次の節です。

## 5. 個数を 1 ずつ伸ばす

端数の要素の値ごとに個数を数え直すと、1 つあたり $O(\log n)$（二分探索）かかります。ここでは、もっと速い「**今の候補の個数 $c$ を 1 増やせるか**」だけを調べる方法を使います。

### 5.1. 持っているもの

| 名前 | 意味 |
| --- | --- |
| `mode[bi][bj]` | ブロック $b_i$ 〜 $b_j$ の最頻値と個数 |
| `pos[v]` | 値 $v$ が出てくる位置のリスト（昇順） |
| `rank_in[i]` | 位置 $i$ が `pos[a[i]]` の何番目か |

### 5.2. 判定

今の候補の個数を $c$ とします。左の端数の要素 $a_i = v$（$i \ge l$）について、「$v$ は $[l, r)$ に $c + 1$ 個以上あるか」を知りたいとします。`pos[v]` の中で $i$ から数えて $c + 1$ 個目、すなわち `pos[v][rank_in[i] + c]` が $r$ 未満なら、$[i, r)$ に $v$ が $c + 1$ 個以上あります。そうなら $c$ を 1 増やして候補を $v$ にし、もう一度同じことを調べます。

右の端数の要素 $a_j = v$ なら、逆向きに「$j$ から左に数えて $c + 1$ 個目（`pos[v][rank_in[j] - c]`）が $l$ 以上か」を調べます。

各判定は配列を 1 回見るだけなので $O(1)$ です。$c$ が増える回数の合計は、端数の要素数以下です（各要素で増やすたびに、その要素の値の個数が $c$ を超えていることが確定するので、最終的な $c$ は「完全なブロックの最頻値の個数 + 端数の要素数」以下）。よって 1 クエリ $O(B)$ です。

### 5.3. 手順

1. $l$ のブロック $l_b$、$r - 1$ のブロック $r_b$ を求める。
2. $r_b - l_b \le 1$（完全なブロックがない）なら、候補なし・$c = 0$ から始め、区間の全要素を「左の端数」として扱う。
3. そうでなければ、`mode[l_b + 1][r_b - 1]` を候補と $c$ の初期値にする。
4. 左の端数 $[l, (l_b + 1) B)$ の各要素で、「右に $c + 1$ 個目が $r$ 未満か」を成り立つ間くり返す。
5. 右の端数 $[r_b B, r)$ の各要素で、「左に $c + 1$ 個目が $l$ 以上か」を成り立つ間くり返す。

## 6. 例で追う

$a = [1, 2, 1, 3, 3, 1, 2, 3, 3]$（$n = 9$）、$B = 3$ とします。

```
位置   0 1 2 | 3 4 5 | 6 7 8
a      1 2 1 | 3 3 1 | 2 3 3
     ブロック0  ブロック1  ブロック2
```

### 6.1. 前計算

`mode` は、左端のブロック $b_i$ を決めて、右に 1 ブロックずつ広げながら値の個数を数えれば作れます（ライブラリで出力した値）。

| `mode` | $b_j = 0$ | $b_j = 1$ | $b_j = 2$ |
| --- | --- | --- | --- |
| $b_i = 0$ | 1 が 2 個 | 1 が 3 個 | 3 が 4 個 |
| $b_i = 1$ | | 3 が 2 個 | 3 が 4 個 |
| $b_i = 2$ | | | 3 が 2 個 |

```
pos[1] = [0, 2, 5]      pos[2] = [1, 6]      pos[3] = [3, 4, 7, 8]
rank_in = [0, 0, 1, 0, 1, 2, 1, 2, 3]
```

### 6.2. query(1, 8)

中身は $2, 1, 3, 3, 1, 2, 3$ で、答えは 3 が 3 個です。

- $l_b = 0$、$r_b = 2$。間の完全なブロックはブロック 1 だけ → `mode[1][1]` = 「3 が 2 個」。$c = 2$。
- 左の端数（位置 1, 2）：

| 位置 | 値 | `rank_in` | 調べる場所 | 結果 |
| --- | --- | --- | --- | --- |
| 1 | 2 | 0 | `pos[2][0 + 2]` | ない → 増やせない |
| 2 | 1 | 1 | `pos[1][1 + 2]` | ない → 増やせない |

- 右の端数（位置 6, 7）：

| 位置 | 値 | `rank_in` | 調べる場所 | 結果 |
| --- | --- | --- | --- | --- |
| 6 | 2 | 1 | `pos[2][1 - 2]` | 範囲外 → 増やせない |
| 7 | 3 | 2 | `pos[3][2 - 2]` = 3 | $3 \ge 1$ → **$c = 3$、候補 3** |
| 7（続き） | 3 | 2 | `pos[3][2 - 3]` | 範囲外 → 終わり |

答えは **3 が 3 個** です。

## 7. 実装

```cpp
pair<T, int> query(int l, int r) const {
    int lb = l / B, rb = (r - 1) / B;
    int best = -1, bc = 0;
    auto extend_right = [&](int i) {         // i から右に数えて bc + 1 個目が r 未満なら伸ばす
        int v = c[i], k = rank_in[i];
        const auto &p = pos[v];
        while (k + bc < (int)p.size() && p[k + bc] < r) bc++, best = v;
    };
    if (rb - lb <= 1) {                      // 完全なブロックがない
        for (int i = l; i < r; i++) extend_right(i);
        return {vals[best], bc};
    }
    best = mode_val[(lb + 1) * nb + rb - 1], bc = mode_cnt[(lb + 1) * nb + rb - 1];
    for (int i = l; i < (lb + 1) * B; i++) extend_right(i);
    for (int i = rb * B; i < r; i++) {       // 左に数えて bc + 1 個目が l 以上なら伸ばす
        int v = c[i], k = rank_in[i];
        const auto &p = pos[v];
        while (k - bc >= 0 && p[k - bc] >= l) bc++, best = v;
    }
    return {vals[best], bc};
}
```

値は最初に座標圧縮して $0, 1, \ldots$ の番号（`c`）にしています。

## 8. 計算量

- 前計算：`mode` は左端のブロックごとに右へ 1 回なめるので $O(n \cdot n/B)$。
- クエリ：端数の要素 $O(B)$ と、$c$ を増やす回数（端数の要素数以下）で $O(B)$。
- $B = \sqrt n$ とすると、前計算 $O(n \sqrt n)$、クエリ $O(\sqrt n)$。メモリは `mode` の $(n/B)^2 = n$ 個と、`pos` の $n$ 個で $O(n)$。

（ヒント：最頻値の個数が長さの半分より多いか見ればよいですが、過半数だけならもっと速い方法があります。区間からランダムに要素を 1 つ選ぶと、過半数の値なら $1/2$ 以上の確率で選ばれます。選んだ値の個数を位置のリストの二分探索で数えましょう。）

## 10. まとめ

- 最頻値はセグメント木に乗らないので、平方分割する。
- 最頻値の候補は「間の完全なブロックの最頻値」と「端数の値」だけ。完全なブロックの組の答えを前計算しておく。
- 端数の要素は「個数を $c + 1$ に伸ばせるか」を位置のリストで $O(1)$ ずつ判定する。$c$ が増える回数は端数の要素数以下。
