## 何ができるアルゴリズムか？

静的な数列 $a$ について、区間 $[l, r)$ の **最頻値**（一番多く出てくる値）とその個数を $O(\sqrt n)$ で答える。クエリを先読みしなくてよい（オンライン）。

最頻値は「2 つの区間の答えから合わせた区間の答えが作れない」（左の最頻値と右の最頻値のどちらでもない値が、合わせると最頻値になりうる）ので、セグ木には乗らない。

>[!問題] Static Range Mode Query (Library Checker)
>長さ $N$ の数列に「$a_l, \ldots, a_{r-1}$ の最頻値とその個数」を $Q$ 回答えよ。$N, Q \le 10^5$

## 計算量

構築 $O(n \sqrt n)$、クエリ $O(\sqrt n)$、メモリ $O(n)$。

## 具体例で理解する

例：$a = [1, 2, 1, 3, 3, 1, 2, 3, 3]$（$n = 9$）、ブロックの大きさ $B = 3$。

```
位置   0 1 2 | 3 4 5 | 6 7 8
a      1 2 1 | 3 3 1 | 2 3 3
       ブロック0  ブロック1  ブロック2
```

### まず遅い方法

区間を左から見て、値ごとの個数を数えながら最大を更新する。1 回 $O(r - l)$、全体 $O(nq) = 10^{10}$ で間に合わない。

### アイデア：ブロックの区間の答えは前計算、端数だけ調べる

区間 $[l, r)$ を「左の端数」＋「間の完全なブロックたち」＋「右の端数」に分ける。

- 完全なブロックの区間 $[b_i, b_j]$ の最頻値と個数は、全ての $(b_i, b_j)$ の組について前計算しておく（組は $(n/B)^2$ 個）。
- 最頻値の候補は「完全なブロックの最頻値」か「端数に出てくる値」のどれか（端数に出てこない値の個数は、完全なブロックの中の個数と同じなので、完全なブロックの最頻値を超えない）。
- 端数の要素は $2B$ 個以下なので、その値の個数をうまく調べられればよい。

### 持っているもの

| 名前 | 意味 |
| --- | --- |
| `mode[bi][bj]` | ブロック $b_i$ 〜 $b_j$ の最頻値と個数 |
| `pos[v]` | 値 $v$ が出てくる位置のリスト（昇順） |
| `rank_in[i]` | 位置 $i$ が `pos[a[i]]` の何番目か |

例：

| `mode` | $b_j = 0$ | $b_j = 1$ | $b_j = 2$ |
| --- | --- | --- | --- |
| $b_i = 0$ | 1 が 2 個 | 1 が 3 個 | 3 が 4 個 |
| $b_i = 1$ | | 3 が 2 個 | 3 が 4 個 |
| $b_i = 2$ | | | 3 が 2 個 |

```
pos[1] = [0, 2, 5]      pos[2] = [1, 6]      pos[3] = [3, 4, 7, 8]
```

`mode` は、左端のブロック $b_i$ を決めて右に 1 ブロックずつ広げながら個数を数えれば、$b_i$ ごとに $O(n)$、全体 $O(n \cdot n / B)$ で作れる。

### 「個数を 1 増やせるか」を $O(1)$ で調べる

今の候補の個数を $c$ とする。左の端数の要素 $a_i = v$ について「$v$ は $[l, r)$ に $c + 1$ 個以上あるか」を知りたい。$i \ge l$ なので、`pos[v]` の中で $i$ から数えて $c + 1$ 個目（`pos[v][rank_in[i] + c]`）が $r$ 未満なら、$[i, r)$ に $c + 1$ 個以上ある。そうなら $c$ を 1 増やして候補を $v$ にし、もう一度同じことを調べる。

右の端数の要素 $a_j = v$ なら、逆向きに「$j$ から左に数えて $c + 1$ 個目（`pos[v][rank_in[j] - c]`）が $l$ 以上か」を調べる。

$c$ が増えるのは全部で「端数の要素数」回以下なので、1 クエリ $O(B)$。

### 操作の手順：query(l, r)

1. $l$ のブロック $l_b$、$r - 1$ のブロック $r_b$ を求める。$r_b - l_b \le 1$ なら（完全なブロックがないなら）候補なし・$c = 0$ から始め、区間の全要素を左の端数として扱う。
2. そうでなければ、`mode[l_b + 1][r_b - 1]` を候補と $c$ の初期値にする。
3. 左の端数 $[l, (l_b + 1) B)$ の各要素で「右に $c + 1$ 個目が $r$ 未満か」を、成り立つ間くり返す。
4. 右の端数 $[r_b B, r)$ の各要素で「左に $c + 1$ 個目が $l$ 以上か」を、成り立つ間くり返す。

### 例で追う：query(1, 8)（中身 2, 1, 3, 3, 1, 2, 3 → 3 が 3 個）

- $l_b = 0$、$r_b = 2$。間の完全なブロックは 1 だけ → `mode[1][1]` = 「3 が 2 個」。$c = 2$。
- 左の端数（位置 1, 2）：
  - 位置 1（値 2、`pos[2]` の 0 番目）：0 + 2 = 2 番目は `pos[2]` にない → 増やせない。
  - 位置 2（値 1、`pos[1]` の 1 番目）：1 + 2 = 3 番目はない → 増やせない。
- 右の端数（位置 6, 7）：
  - 位置 6（値 2、`pos[2]` の 1 番目）：1 − 2 < 0 → 増やせない。
  - 位置 7（値 3、`pos[3]` の 2 番目）：2 − 2 = 0 番目 = 位置 3 ≥ 1 → **$c = 3$、候補 3**。続けて 2 − 3 < 0 → 終わり。
- 答え：**3 が 3 個**。

## 証明・仕組み

### 候補が正しい理由

最頻値 $v^*$ が端数に出てこなければ、$v^*$ の個数は完全なブロックの中の個数と等しく、`mode` の個数以下。よって `mode` の値も最頻値（個数が等しい）。$v^*$ が端数に出てくるなら、その要素を調べたときに個数が $v^*$ の個数まで伸びる（候補の個数 $c$ は常に「ある値の区間内の個数」以下なので、伸ばしすぎることもない）。

### 計算量

- 前計算：ブロックの組ごとではなく、左端のブロックごとに右へ 1 回なめるので $O(n \cdot n/B)$。
- クエリ：端数の要素数 $O(B)$ ＋ $c$ を増やす回数（端数の要素数以下）。
- $B = \sqrt n$ で、構築 $O(n \sqrt n)$、クエリ $O(\sqrt n)$。メモリは `mode` の $(n/B)^2 = n$ 個と、`pos` の $n$ 個。
