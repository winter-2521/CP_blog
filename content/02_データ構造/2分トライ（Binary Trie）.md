#データ構造 #xor #トライ

ライブラリ：[binary_trie.hpp](https://github.com/winter-2521/cp-library/blob/main/data_structure/binary_trie.hpp)

## 何ができるアルゴリズムか？

非負整数の（多重）集合 $S$ を持ち、追加・削除をしながら、与えられた $x$ に対して

- $\min_{y \in S} (x \oplus y)$、$\max_{y \in S} (x \oplus y)$（$\oplus$ は bitwise xor）
- $\{x \oplus y : y \in S\}$ の $k$ 番目に小さい値
- $x \oplus y < a$ となる $y$ の個数

を、どれも **ビット数 $\mathrm{LOG}$ に比例する時間** で求める。

>[!問題] Set Xor-Min (Library Checker)
>空の集合 $S$ に「$x$ を追加」「$x$ を削除」「$\min_{i \in S} (i \oplus x)$ を出力」の $Q$ 個のクエリを処理せよ。$Q \le 5 \times 10^5$、$0 \le x < 2^{30}$

## 計算量

各操作 $O(\mathrm{LOG})$（$\mathrm{LOG}$ は値のビット数。上の問題では 30）。メモリは「入れた値の種類数 × LOG」個のノード。

## 具体例で理解する

### まず遅い方法

xor の最小値は、$S$ の全要素 $y$ について $x \oplus y$ を計算して最小を取れば求まる。1 回 $O(|S|)$ なので、$Q = 5 \times 10^5$ だと最悪 $10^{11}$ 回程度で間に合わない。

「$S$ をソートしておいて二分探索」も考えたくなるが、xor は大小関係を保たない（$x$ に近い値の $y$ が $x \oplus y$ を小さくするとは限らない。例えば $x = 4 = 100_{(2)}$ に対して $y = 3 = 011_{(2)}$ は値としては近いが $x \oplus y = 7$ で、$y = 5$ だと $x \oplus y = 1$）ので使えない。

### xor の最小値は「上のビットから貪欲」で決まる

$x \oplus y$ を小さくしたいとき、**一番上のビットが 0 になること** が何より大事（一番上のビットが 1 だと、下のビットがどうであれ、一番上のビットが 0 のものより大きい）。

なので上のビットから順に「$x$ と同じビットを持つ $y$ がまだ残っていれば、そちらだけに絞る」を繰り返せばよい。これを素早く行うために、$S$ の要素を **上のビットから見た 2 分木（トライ）** で持つ。

### 持っているもの

各ノードは「ここまでのビット列（上位ビットの並び）」を表し、次を持つ。

| 名前 | 意味 |
| --- | --- |
| `ch[0]`, `ch[1]` | 次のビットが 0 / 1 の子（なければ 0） |
| `cnt` | このノードの下にある要素の個数 |

例：LOG = 3、$S = \{1, 4, 6\}$（2 進で $001, 100, 110$）

```
                    根 (cnt=3)
              0 /             \ 1
        [0..] (cnt=1)       [1..] (cnt=2)
           0 |              0 /       \ 1
        [00.] (cnt=1)   [10.] (cnt=1)  [11.] (cnt=1)
           1 |              0 |           0 |
        [001]=1 (cnt=1) [100]=4 (cnt=1) [110]=6 (cnt=1)
```

根から葉までの道が 1 つの値を表し、道の途中のノードの `cnt` は「その上位ビットで始まる値がいくつあるか」。

### 操作の手順

- **insert(x)**：根から $x$ のビットを上から順にたどる。子がなければ作る。通ったノード（根と葉も含む）の `cnt` を 1 増やす。
- **erase(x)**：同じ道をたどって `cnt` を 1 減らす（ノードは消さずに `cnt = 0` のまま残す）。
- **xor_min(x)**：根から始め、上のビットから順に
  1. $x$ のそのビットを $c$ とする。
  2. 子 `ch[c]` があって `cnt > 0` なら、そちらに進む（xor のこのビットは 0）。
  3. なければ `ch[1-c]` に進み、答えのこのビットを 1 にする。
- **kth(k, x)**：上のビットから、「xor のこのビットが 0 になる側の子」（＝ `ch[c]`）の `cnt` を見て、$k$ がそれより小さければそちらへ、そうでなければ $k$ から `cnt` を引いて反対側へ（答えのビットを 1 に）。
- **count_less(a, x)**：上のビットから、$a$ のそのビットが 1 なら「xor のこのビットが 0 になる側」の `cnt` を全部答えに足してから反対側へ進む。0 なら 0 になる側へ進むだけ。

$x$ を xor するのは「ビット $c$ が 1 の段では左右の子を入れ替えて見る」のと同じなので、木を作り直す必要はない。

### 例で追う

$S = \{1, 4, 6\}$ で $x = 5 = 101_{(2)}$。実際の値は $1 \oplus 5 = 4$、$4 \oplus 5 = 1$、$6 \oplus 5 = 3$。

**xor_min(5)**：

| 段（ビット） | $x$ のビット $c$ | `ch[c]` | 進む先 | 答えのビット |
| --- | --- | --- | --- | --- |
| ビット 2 | 1 | [1..] (cnt=2) あり | [1..] | 0 |
| ビット 1 | 0 | [10.] (cnt=1) あり | [10.] | 0 |
| ビット 0 | 1 | [101] なし | [100] | 1 |

答え $001_{(2)} = 1$（$y = 4$ のとき）。

**kth(1, 5)**（$\{4, 1, 3\}$ を並べた $1, 3, 4$ の 1 番目 = 3）：

| 段 | $c$ | `ch[c]` の cnt | $k$ | 進む先 | 答えのビット |
| --- | --- | --- | --- | --- | --- |
| ビット 2 | 1 | [1..] は 2 | 1 < 2 | [1..] | 0 |
| ビット 1 | 0 | [10.] は 1 | 1 ≥ 1 → $k = 0$ | [11.] | 1 |
| ビット 0 | 1 | [111] なし（0） | 0 ≥ 0 → $k = 0$ | [110] | 1 |

答え $011_{(2)} = 3$ ✓。

**count_less(3, 5)**（$x \oplus y < 3 = 011_{(2)}$ となる $y$ の個数。$\{4, 1, 3\}$ のうち 3 未満は 1 個）：

- ビット 2：$a$ のビットは 0 → $c = 1$ 側の [1..] へ進むだけ。
- ビット 1：$a$ のビットは 1 → 「xor が 0 になる側」[10.] の cnt = 1 を足す（このビットで $a$ より小さくなることが確定する）。反対側 [11.] へ。
- ビット 0：$a$ のビットは 1 → [11.] の 0 になる側（[111]）はないので 0 を足す。

答え 1 ✓。

## 証明・仕組み

### 貪欲が正しい理由

2 進数の大小は「上から見て最初に異なるビット」で決まる。xor の上位ビットを 0 にできるならそうした方が、下位ビットをどうしても必ず小さい。各段で「0 にできるか」は「その上位ビット列を持つ要素が残っているか」＝ 子の `cnt > 0` で判定できる。

### k 番目・count_less

`ch[c]` の部分木の要素は「このビットまでで xor が小さい側」に全部まとまっていて、その個数が `cnt` で分かる。なので二分探索木で $k$ 番目を探すのと同じ要領で 1 本降りれば求まる。

### 計算量とメモリ

どの操作も根から葉まで 1 本降りるだけなので $O(\mathrm{LOG})$。ノードは追加した値の種類ごとに最大 LOG 個増えるので、$5 \times 10^5$ 回追加すると最大 $1.5 \times 10^7$ 個（1 個 12 バイトで 180 MB 程度）。削除でノードを消さないのは、消す処理の手間を省いて速くするため。

## 例題・類題

- [Set Xor-Min (Library Checker)](https://judge.yosupo.jp/problem/set_xor_min)
- **区間の xor の最大値**：累積 xor $s_i$ を作ると $a_l \oplus \cdots \oplus a_{r-1} = s_r \oplus s_l$ なので、「$s_r$ と、それより前の $s_l$ たちとの xor の最大」をトライで求めればよい。
- [ABC308 G - Minimum Xor Pair Query](https://atcoder.jp/contests/abc308/tasks/abc308_g)：集合への追加・削除と「2 要素の xor の最小値」。最小値を取る 2 要素はソート順で隣り合うという性質と組み合わせる（トライでも解ける）。
- **xor で $k$ 番目**：全要素に $x$ を xor した集合の $k$ 番目、xor が $a$ 未満のものの個数、などは `kth` / `count_less` がそのまま使える。
