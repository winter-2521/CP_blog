#データ構造 #永続 #木 #祖先

ライブラリ：[persistent_queue.hpp](https://github.com/winter-2521/cp-library/blob/main/data_structure/persistent_queue.hpp)

## 1. 概要

本記事では、**永続キュー** を解説します。永続データ構造とは、操作するたびに新しい「版」を作り、**過去のどの版もそのまま残る** データ構造です。過去の版から別の操作をして、枝分かれさせることもできます。

永続キューでは、どの版に対しても push（末尾に追加）と pop（先頭を削除）ができ、それぞれ新しい版を作ります。push・pop は $O(1)$、先頭の取得は $O(\log n)$ です。

>[!問題] 問題 1：Persistent Queue（Library Checker）
>$S_{-1}$ は空の列です。$i = 0, 1, \ldots, Q-1$ について、次のどちらかで $S_i$ を作ってください。（$Q \le 5 \times 10^5$）
>- `0 t x`：$S_t$ の末尾に $x$ を追加したものを $S_i$ とする
>- `1 t`：$S_t$ の先頭を取り出して出力し、残りを $S_i$ とする

## 2. 前提知識

- 根付き木、深さ、祖先
- ダブリング（$2^k$ 個上の祖先を持って $O(\log n)$ で祖先を求める方法）

## 3. 素朴な方法：版ごとに全部コピー

版を作るたびにキュー全体をコピーすれば、どんなデータ構造でも永続にできます。しかし 1 回 $O(n)$ の時間とメモリがかかり、$Q = 5 \times 10^5$ では最悪 $10^{11}$ 程度になって無理です。

永続化の基本は、「**変わった部分だけ新しく作り、変わらない部分は前の版と共有する**」ことです。

## 4. キューを木で表す

### 4.1. push した要素を木に置く

push した要素を、**その時の末尾の要素を親とする木** に置きます。根は要素を持たない特別なノード（深さ 0）です。

- 版は「末尾のノード」と「先頭の深さ」の組で表します。
- 版の中身は、末尾のノードから根への道のうち、深さが「先頭の深さ + 1」以上の部分（を根の側から読んだもの）です。

### 4.2. 操作

- **push(x)**：末尾のノードの子として、$x$ を持つ新しいノードを作る。新しい版 ＝（新しいノード, 同じ先頭の深さ）。
- **pop**：新しい版 ＝（同じ末尾のノード, 先頭の深さ + 1）。ノードは作りません。
- **front**：末尾のノードの **祖先のうち、深さが（先頭の深さ + 1）のもの** の要素。

push・pop は既存のノードを一切変えないので、過去の版はそのまま残ります。

### 4.3. 例

空の版から 10, 20, …, 80 を順に push すると、根から一本道ができます。

```
根 ─ 10 ─ 20 ─ 30 ─ 40 ─ 50 ─ 60 ─ 70 ─ 80
深さ0  1    2    3    4    5    6    7    8
```

この版は（末尾 = 80 のノード, 先頭の深さ = 0）で、中身は深さ 1〜8 の 10, 20, …, 80 です。

ここから 2 回 pop した版は（末尾 = 80, 先頭の深さ = 2）で、中身は 30, …, 80 です。front は「80 の祖先で深さ 3」= **30** です。

また、10, 20, 30 を push した版（末尾 = 30）から別に 99 を push すると、30 の子にもう 1 つノードができて木が枝分かれします。80 を末尾とする版には影響しません。

## 5. 祖先を求める

### 5.1. 遅い方法 1：親を 1 つずつたどる

親を 1 つずつたどると、1 回 $O(\text{深さ})$ = $O(n)$ かかります。

### 5.2. 遅い方法 2：ダブリング

各ノードに $2^0, 2^1, 2^2, \ldots$ 個上の祖先を全部持てば $O(\log n)$ で求まりますが、ノードごとに $\log n$ 個の値を持つので、$5 \times 10^5$ ノードで約 1000 万個になり、メモリも時間もかかります。

### 5.3. 高速化：skew-binary の跳び先

各ノードに **跳び先を 1 つだけ** 持たせます。新しいノード $v$（親 $p$）の跳び先 $\mathrm{jump}(v)$ は、

- 「$p$ と $\mathrm{jump}(p)$ の深さの差」＝「$\mathrm{jump}(p)$ と $\mathrm{jump}(\mathrm{jump}(p))$ の深さの差」なら、$\mathrm{jump}(\mathrm{jump}(p))$
- そうでなければ $p$

と決めます（根の跳び先は根自身）。4.3 の一本道では、ライブラリで作った跳び先は次の通りです。

| 要素 | 10 | 20 | 30 | 40 | 50 | 60 | 70 | 80 |
| --- | --- | --- | --- | --- | --- | --- | --- | --- |
| 深さ | 1 | 2 | 3 | 4 | 5 | 6 | 7 | 8 |
| 跳び先の深さ | 0 | 1 | 0 | 3 | 4 | 3 | 0 | 7 |
| 跳ぶ幅 | 1 | 1 | 3 | 1 | 1 | 3 | 7 | 1 |

跳ぶ幅は $1, 3, 7, 15, \ldots$（$2^k - 1$）の形になっています。これは「skew-binary（歪 2 進数）」という数の表し方に対応していて、この名前がついています。

祖先を探すときは、

> 跳び先の深さが目標以上なら跳ぶ、そうでなければ親へ進む

を、目標の深さに着くまで繰り返します。

**例：80（深さ 8）から深さ 3 の祖先を探す**

| 今のノード | 深さ | 跳び先（深さ） | 判定 | 次 |
| --- | --- | --- | --- | --- |
| 80 | 8 | 70（7） | $7 \ge 3$ → 跳ぶ | 70 |
| 70 | 7 | 根（0） | $0 < 3$ → 親へ | 60 |
| 60 | 6 | 30（3） | $3 \ge 3$ → 跳ぶ | 30 |
| 30 | 3 | — | 着いた | — |

3 回で着きました（親だけなら 5 回）。

このジャンプポインタで祖先探しが $O(\log n)$ になることが知られています（Myers による）。メモリはノードごとに跳び先 1 つだけです。

### 5.4. 実装

```cpp
int push(int v, const T &x) {
    auto [tail, head] = versions[v];
    int p = tail;
    int j = p, pj = nodes[p].jump, dep = nodes[p].depth;
    // 深さの差がそろっていれば，跳び先の跳び先へ
    if (dep - nodes[pj].depth == nodes[pj].depth - nodes[nodes[pj].jump].depth) j = nodes[pj].jump;
    nodes.push_back({x, p, j, dep + 1});
    versions.push_back({(int)nodes.size() - 1, head});
    return versions.size() - 1;
}

int ancestor(int x, int dep) const {           // ノード x の祖先で深さ dep のもの
    while (nodes[x].depth > dep) {
        int j = nodes[x].jump;
        x = nodes[j].depth >= dep ? j : nodes[x].par;
    }
    return x;
}

T front(int v) const {
    auto [tail, head] = versions[v];
    return nodes[ancestor(tail, head + 1)].val;
}
```

## 6. 計算量

push・pop は $O(1)$、front は $O(\log n)$、メモリはノード 1 つあたり $O(1)$ です。

【問題 2】永続スタック（どの版にも push / pop でき、top を取得できる）を作ってください。

## 8. まとめ

- 永続化の基本は「変わった部分だけ新しく作り、残りは共有」。
- キューは「push した要素を、その時の末尾を親とする木」に置き、版を（末尾のノード, 先頭の深さ）で表せる。push・pop は既存のノードを変えない。
- 先頭は末尾の祖先なので、skew-binary の跳び先で $O(\log n)$、メモリ $O(1)$/ノードで求まる。
