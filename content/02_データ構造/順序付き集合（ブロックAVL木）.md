ライブラリ：[ordered_set.hpp](https://github.com/winter-2521/cp-library/blob/main/data_structure/ordered_set.hpp)

## 何ができるアルゴリズムか？

値の集合に対して、挿入・削除・$k$ 番目の値・$x$ 以下の個数・$x$ 以下の最大値・$x$ 以上の最小値 を $O(\log n)$ で処理する。`std::set` と違い **$k$ 番目と順位も** 求まり、しかも速い。値を先読みする必要はない（オンライン）。

>[!問題] Ordered Set (Library Checker)
>非負整数の集合 $S$ に対して $Q$ 個のクエリを処理せよ。
>挿入 / 削除 / $x$ 番目に小さい値 / $x$ 以下の要素数 / $x$ 以下の最大値 / $x$ 以上の最小値
>$N, Q \le 5 \times 10^5$

## 計算量

各操作 $O(\log n + B)$（$B$ はノードあたりの要素数、`int` で 28）。

## 具体例で理解する

### 基本形：部分木の要素数を持った二分探索木

二分探索木（左の子孫 < 自分 < 右の子孫）の各ノードに「部分木の要素数」を持たせると、$k$ 番目（0-indexed）を根から探せる。

```
            (8) 要素数7
          /          \
     (4) 要素数3     (12) 要素数3
     /     \        /     \
   (2)    (6)    (10)    (14)
```

**$k = 4$ の手順**（各ノードで「左の部分木の要素数 $s$」と比べる）：

1. 根 (8)：$s = 3$。$k = 4 > 3$ → 左の 3 個と自分 1 個を飛ばして右へ。$k = 4 - 3 - 1 = 0$。
2. (12)：$s = 1$。$k = 0 < 1$ → 左へ。
3. (10)：$s = 0$。$k = 0 = s$ → 自分が答え → **10**。

昇順に並べると $2, 4, 6, 8, 10, 12, 14$ で、0-indexed の 4 番目は 10。「$x$ 以下の個数」も、降りながら「右に進むとき、左の部分木と自分の個数を足す」で求まる。

### 1 ノードに複数の値を入れる

1 ノード 1 要素だと高さが 20 くらいになり、1 段ごとにキャッシュミスが起きて遅い。そこで **1 ノードにソート済み配列で最大 $B$ 個** の値を入れる（実際は $B = 28$、ここでは $B = 4$ で説明）。

**各ノードが持っているもの**：

| 名前 | 意味 |
| --- | --- |
| `data` | ソート済みの値（最大 $B$ 個） |
| `left`, `right` | 子。左の部分木の値は全て `data` より小さく、右は全て大きい |
| `total` | 部分木全体の要素数 |
| `height` | 部分木の高さ（AVL の平衡に使う） |

**挿入 $x$ の手順**：

1. 根から、$x$ が `data` の最小値より小さく左の子があれば左へ、最大値より大きく右の子があれば右へ降りる。それ以外ならこのノードの `data` に挿入する。
2. `data` が $B$ 個になったら：右の子があれば、最大値を右の部分木の一番左のノードへ移す。なければ後半を新しいノードに分けて右の子にする。
3. 戻りながら `total`・`height` を更新し、左右の高さの差が 2 になったら **回転** で直す。

### 例で追う（$B = 4$ で 10, 20, …, 60 を挿入）

1. 10, 20, 30 を挿入：根 `[10, 20, 30]`。
2. 40 を挿入：根が `[10, 20, 30, 40]` で 4 個になった。右の子がないので後半を分ける → 根 `[10, 20]`、右の子 `[30, 40]`。
3. 50 を挿入：50 > 根の最大値 20 で右の子があるので右へ → `[30, 40, 50]`。
4. 60 を挿入：右へ → `[30, 40, 50, 60]` で 4 個 → 後半を分ける → `[30, 40]` の右の子 `[50, 60]`。

```
   [10,20]                         [30,40]
        \         左回転 →         /      \
       [30,40]                 [10,20]  [50,60]
            \
           [50,60]
```

左の図では根の左の高さ 0、右の高さ 2 で差が 2 になったので、**左回転**（右の子 `[30,40]` を根にし、元の根 `[10,20]` をその左の子にする）で右の図にする。回転しても「左 < 自分 < 右」の順序は変わらない。

**kth(3)**：根 `[30,40]` の左の部分木は 2 個。$k = 3 \ge 2$ で、$3 < 2 + 2$（左 + 自分の配列の個数）なので、自分の配列の $3 - 2 = 1$ 番目 → **40**。実際 $10, 20, 30, 40, 50, 60$ の 3 番目は 40。

木の高さは $\log_2(n / B)$ 程度に減り、ノード内の配列は連続したメモリなので線形探索も速い。

## 証明・仕組み

### オフラインならセグ木 / BIT で解ける

値を先読みできるなら、座標圧縮して「値 $v$ が入っているか」の 0/1 列を Fenwick Tree で持てば、$x$ 以下の個数は累積和、$k$ 番目は累積和の二分探索で求まる。前後の値は [[64分木（FastSet）]] で求まる。これでも十分速い（手元 0.17 秒）。

### オンラインにするには平衡二分木

先読みできない場合は平衡二分木に「部分木の要素数」を持たせる。$k$ 番目は、根から「左の部分木の要素数と $k$ を比べて左右に降りる」ことで $O(\text{高さ})$。

ただし 1 ノード 1 要素の平衡二分木はポインタ追跡が $\log_2 n \approx 19$ 回あり遅い。

### ブロック化：1 ノードに最大 $B$ 個

各ノードに **ソート済みの配列で最大 $B$ 個の値** を持たせた AVL 木にする（B木に近い）。

- ノードが表す値の範囲は「左の部分木 $<$ ノードの配列 $<$ 右の部分木」。
- 挿入：値が入るべきノードを探して配列に挿入。満杯（$B$ 個）になったら、最大値を右の部分木の最も左のノードに押し出すか、半分に割って新しいノードを右の子に作る。
- 削除：配列から消し、空になったらノードを木から外す（右の部分木の最も左のノードと付け替える）。
- 回転で高さを $O(\log(n/B))$ に保つ（AVL）。

1 ノードを約 128 バイト（キャッシュライン 2 本）にすると、ノード内の線形探索は事実上タダで、木の高さは $\log_2(n / B)$ になるので速い（手元 0.13 秒で、オフライン解法より速い）。

### 正しさ

木の各ノードについて「左の部分木の全ての値 $<$ 配列の値 $<$ 右の部分木の全ての値」が保たれていれば、中順走査が昇順になり、部分木の要素数から順位が計算できる。押し出し・分割・付け替えはどれもこの順序を保つ。
