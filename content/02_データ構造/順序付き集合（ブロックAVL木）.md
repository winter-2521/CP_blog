#データ構造 #平衡二分木 #高速化

ライブラリ：[ordered_set.hpp](https://github.com/winter-2521/cp-library/blob/main/data_structure/ordered_set.hpp)

## 何ができるアルゴリズムか？

値の集合に対して、挿入・削除・$k$ 番目の値・$x$ 以下の個数・$x$ 以下の最大値・$x$ 以上の最小値 を $O(\log n)$ で処理する。`std::set` と違い **$k$ 番目と順位も** 求まり、しかも速い。値を先読みする必要はない（オンライン）。

>[!問題] Ordered Set (Library Checker)
>非負整数の集合 $S$ に対して $Q$ 個のクエリを処理せよ。
>挿入 / 削除 / $x$ 番目に小さい値 / $x$ 以下の要素数 / $x$ 以下の最大値 / $x$ 以上の最小値
>$N, Q \le 5 \times 10^5$

## 計算量

各操作 $O(\log n + B)$（$B$ はノードあたりの要素数、`int` で 28）。

## 証明・仕組み

### オフラインならセグ木 / BIT で解ける

値を先読みできるなら、座標圧縮して「値 $v$ が入っているか」の 0/1 列を Fenwick Tree で持てば、$x$ 以下の個数は累積和、$k$ 番目は累積和の二分探索で求まる。前後の値は [[64分木（FastSet）]] で求まる。これでも十分速い（手元 0.17 秒）。

### オンラインにするには平衡二分木

先読みできない場合は平衡二分木に「部分木の要素数」を持たせる。$k$ 番目は、根から「左の部分木の要素数と $k$ を比べて左右に降りる」ことで $O(\text{高さ})$。

ただし 1 ノード 1 要素の平衡二分木はポインタ追跡が $\log_2 n \approx 19$ 回あり遅い。

### ブロック化：1 ノードに最大 $B$ 個

各ノードに **ソート済みの配列で最大 $B$ 個の値** を持たせた AVL 木にする（B木に近い）。

- ノードが表す値の範囲は「左の部分木 $<$ ノードの配列 $<$ 右の部分木」。
- 挿入：値が入るべきノードを探して配列に挿入。満杯（$B$ 個）になったら、最大値を右の部分木の最も左のノードに押し出すか、半分に割って新しいノードを右の子に作る。
- 削除：配列から消し、空になったらノードを木から外す（右の部分木の最も左のノードと付け替える）。
- 回転で高さを $O(\log(n/B))$ に保つ（AVL）。

1 ノードを約 128 バイト（キャッシュライン 2 本）にすると、ノード内の線形探索は事実上タダで、木の高さは $\log_2(n / B)$ になるので速い（手元 0.13 秒で、オフライン解法より速い）。

### 正しさ

木の各ノードについて「左の部分木の全ての値 $<$ 配列の値 $<$ 右の部分木の全ての値」が保たれていれば、中順走査が昇順になり、部分木の要素数から順位が計算できる。押し出し・分割・付け替えはどれもこの順序を保つ。

- [Ordered Set (Library Checker)](https://judge.yosupo.jp/problem/ordered_set)
- [ABC217 D - Cutting Woods](https://atcoder.jp/contests/abc217/tasks/abc217_d)：切れ目の集合を持ち、$x$ の前後の切れ目を求める（`max_lt` と `min_gt`）。

- 「$k$ 番目」「順位」が欲しくて値が先読みできない問題（インタラクティブ・前の答えで次のクエリが決まる問題）。
