#データ構造 #キュー #ならし計算量

ライブラリ：[foldable_queue.hpp](https://github.com/winter-2521/cp-library/blob/main/data_structure/foldable_queue.hpp)、[foldable_deque.hpp](https://github.com/winter-2521/cp-library/blob/main/data_structure/foldable_deque.hpp)

## 何ができるアルゴリズムか？

キュー（末尾に入れて先頭から出す）に入っている要素 **全体の積** を、いつでも $O(1)$ で答えられるようにする。「積」はモノイドなら何でもよく、**非可換でもよい**（1 次関数の合成、文字列の連結、行列の積など）。積の順番は「先頭から末尾の順」。

Sliding Window Aggregation（SWAG）とも呼ばれる。両端から出し入れできるデック版もある。

>[!問題] Queue Operate All Composite (Library Checker)
>1 次関数の列 $f$ に対して「末尾に $ax+b$ を追加」「先頭を削除」「$f_{\text{末尾}}(\cdots f_{\text{先頭}}(x) \cdots)$ を求める」を $Q$ 回処理せよ。$Q \le 5 \times 10^5$

>[!問題] Deque Operate All Composite (Library Checker)
>上の問題で、先頭への追加・末尾の削除もある。

## 計算量

| 操作 | キュー | デック |
| --- | --- | --- |
| 追加 | $O(1)$ | $O(1)$ |
| 削除 | ならし $O(1)$ | ならし $O(1)$ |
| 全体の積 | $O(1)$ | $O(1)$ |

## 具体例で理解する

例では、モノイドを **文字列の連結** にする（`op(a, b) = a + b`、単位元は空文字列）。連結は順番を変えると結果が変わる（非可換）ので、「先頭から末尾の順に掛けているか」が目で見て分かる。

### まず遅い方法

**方法 1：毎回全部掛ける。** 積を聞かれるたびに先頭から末尾まで掛ける。1 回 $O(n)$ なので、$Q = 5 \times 10^5$ 回だと最悪 $10^{11}$ 回くらいの計算になって間に合わない。

**方法 2：セグメント木。** 要素に通し番号を振り（$i$ 番目に追加した要素を位置 $i$ に置く）、削除された位置は単位元にしておけば、全体の積はセグ木の区間積で $O(\log Q)$。これで十分間に合うが、削除・追加のたびに $O(\log Q)$ かかり、配列も $Q$ 個分必要。

ここから「積を求める向きを工夫して、ほぼ $O(1)$ にする」のが SWAG。

### キュー版：持っているもの

**スタックを 2 本** 使う。キューの中身を「前半（先頭側）」と「後半（末尾側）」に分けて持つ。

| 名前 | 意味 |
| --- | --- |
| `back_val` | 後半の要素を **追加された順** に積んだスタック |
| `back_prod` | 後半の要素 **全体の積**（1 個の値） |
| `front_val` | 前半の要素を、**先頭がスタックの一番上** に来るように積んだスタック |
| `front_prod` | `front_val` の各段について「**その要素から、スタックの底まで** の積」 |

ポイントは `front_prod` の向き。`front_val` は上から「先頭, 2 番目, 3 番目, …」と並んでいるので、一番上の `front_prod` は「先頭から前半の最後までの積」＝ **前半全体の積** になっている。

全体の積 = `front_prod` の一番上 × `back_prod`（前半の積 × 後半の積）。

### キュー版：操作の手順

- **push(x)**：`back_val` に x を積み、`back_prod = back_prod × x`。
- **pop()**：
  1. `front_val` が空なら、**`back_val` を全部 `front_val` に移す**。このとき `back_val` の上（＝末尾）から順に取り出して積み、`front_prod` を「取り出した要素 × それまでの積」で作る。移し終わったら `back_val` を空、`back_prod` を単位元にする。
  2. `front_val` と `front_prod` の一番上を捨てる。
- **all_prod()**：`front_prod` の一番上（前半が空なら単位元）× `back_prod`。

### キュー版：例で追う

`push(a)`, `push(b)`, `push(c)` の後：

```
front_val = []           front_prod = []
back_val  = [a, b, c]    back_prod  = "abc"
全体の積 = "" + "abc" = "abc"
```

**pop()**：`front_val` が空なので移し替える。`back_val` の上から c, b, a の順に取り出す。

| 取り出した要素 | 積み終わった `front_val` | 作った `front_prod` の値 |
| --- | --- | --- |
| c | [c] | "c" |
| b | [c, b] | "b" + "c" = "bc" |
| a | [c, b, a] | "a" + "bc" = "abc" |

（`front_val` は右端がスタックの一番上。一番上の a が先頭。）
それから一番上の a を捨てる：

```
front_val = [c, b]       front_prod = ["c", "bc"]
back_val  = []           back_prod  = ""
全体の積 = "bc" + "" = "bc"
```

**push(d)**：

```
front_val = [c, b]       front_prod = ["c", "bc"]
back_val  = [d]          back_prod  = "d"
全体の積 = "bc" + "d" = "bcd"     ← キューの中身 b, c, d の順に連結されている
```

**pop()**：`front_val` は空でないので一番上（b）を捨てるだけ。`front_prod` の一番上は "c" になり、全体の積は "c" + "d" = "cd"。

移し替えのとき `front_prod` を「新しく積む要素 × 下の積」の順で作っているので、非可換でも正しい順番になる。

### デック版：何が困るか

両端から削除できると、キュー版の「空になったら全部移す」が遅くなる。例えば要素が全部末尾側のスタックにあるとき、

1. 先頭を削除 → 末尾側を **全部** 先頭側に移す（$n$ 回）
2. 末尾を削除 → 末尾側が空なので先頭側を **全部** 末尾側に移す（$n$ 回）
3. 先頭を削除 → また全部移す …

と、削除のたびに $O(n)$ かかってしまう。

### デック版：持っているもの

先頭側・末尾側のスタックを対称に持つ。

| 名前 | 意味 |
| --- | --- |
| `fv` | 先頭側の要素（一番上が先頭） |
| `fp` | `fp[i]` = `fv[i]` から `fv` の底までの積（＝その要素から内側に向かっての積） |
| `bv` | 末尾側の要素（一番上が末尾） |
| `bp` | `bp[i]` = `bv` の底から `bv[i]` までの積 |

全体の積 = `fp` の一番上 × `bp` の一番上。追加は片側に積むだけで $O(1)$。

### デック版：操作の手順

- **push_front(x)**：`fv` に x を積み、`fp` に「x × 直前の一番上」を積む。push_back も対称。
- **pop_front()**：
  1. `fv` が空なら **作り直し**：全要素を先頭から順に並べ、**前半を先頭側、後半を末尾側** に入れ直す（それぞれ累積積も作り直す）。
  2. `fv` の一番上を捨てる。
- pop_back も対称（作り直しで末尾側に少なくとも 1 個入るように分ける）。

### デック版：例で追う

`push_back` で a, b, c, d を入れた後：

```
fv = []  fp = []
bv = [a, b, c, d]   bp = ["a", "ab", "abc", "abcd"]
全体の積 = "abcd"
```

**pop_front()**：`fv` が空なので作り直す。並べると a, b, c, d。前半 a, b を先頭側、後半 c, d を末尾側に入れる。

```
fv = [b, a]  fp = ["b", "ab"]       ← 一番上が先頭 a
bv = [c, d]  bp = ["c", "cd"]
```

それから a を捨てる：`fv = [b]`、`fp = ["b"]`。全体の積 = "b" + "cd" = "bcd"。

**push_front(x)**：`fv = [b, x]`、`fp = ["b", "xb"]`。全体の積 = "xb" + "cd" = "xbcd"。

**pop_back() を 2 回**：`bv` から d, c を捨てる。全体の積 = "xb"。

**pop_back() をもう 1 回**：`bv` が空なので作り直す。並べると x, b。末尾側に少なくとも 1 個入るように、先頭側に x、末尾側に b を入れてから b を捨てる。全体の積 = "x"。

### なぜ半分に分けると速いのか

作り直しには「そのときの要素数 $m$」に比例する時間がかかる。作り直した直後は両側に約 $m/2$ 個ずつあるので、次に作り直しが起きる（どちらかが空になる）までには、少なくとも約 $m/2$ 回の削除が必要。つまり作り直しの $O(m)$ を、その前の $m/2$ 回の操作に 2 ずつ割り振れば払える。全部移す方法ではこの「次の作り直しまでの猶予」がないので遅くなる。

## 証明・仕組み

### キュー版の正しさ

キューの中身を先頭から $x_1, x_2, \ldots, x_n$ とし、前半が $x_1, \ldots, x_k$、後半が $x_{k+1}, \ldots, x_n$ のとき、

- `front_prod` の一番上 $= x_1 x_2 \cdots x_k$（移し替えのとき、外側の要素を左から掛けて作っている）
- `back_prod` $= x_{k+1} \cdots x_n$（追加のたびに右から掛けている）

なので積は $x_1 \cdots x_n$。結合法則だけを使っていて、交換法則は使っていない。

### キュー版の計算量

各要素は「後半に積まれる → 前半に移される → 捨てられる」の 3 回しか動かない。移し替えの総コストは要素数の合計なので、$Q$ 回の操作全体で $O(Q)$、ならし $O(1)$。

### デック版の計算量

ポテンシャル $\Phi = |\,|fv| - |bv|\,|$（2 本のスタックの大きさの差）とする。

- 追加・作り直しなしの削除：$\Phi$ は高々 1 しか変わらない。
- 作り直し：その直前は片方が空なので $\Phi = m$。作り直し後は $\Phi \le 1$。コスト $O(m)$ を $\Phi$ の減少 $m - 1$ で払える。

よって $Q$ 回の操作全体で $O(Q)$。

## 例題・類題

- [Queue Operate All Composite (Library Checker)](https://judge.yosupo.jp/problem/queue_operate_all_composite)
- [Deque Operate All Composite (Library Checker)](https://judge.yosupo.jp/problem/deque_operate_all_composite)
- **スライド最小値・スライド GCD**：長さ $k$ の窓をずらしながら窓内の min / gcd を求める。窓を右にずらす = 末尾に追加 + 先頭を削除なので、SWAG がそのまま使える（min なら単調デックでもできるが、gcd や非可換な積は SWAG が便利）。
- **尺取り法の「区間の積」版**：尺取りで $[l, r)$ を動かしながら区間の積を見たいとき、右端を伸ばす = push、左端を縮める = pop。
