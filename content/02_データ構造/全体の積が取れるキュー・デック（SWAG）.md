#データ構造 #キュー #ならし計算量

ライブラリ：[foldable_queue.hpp](https://github.com/winter-2521/cp-library/blob/main/data_structure/foldable_queue.hpp)、[foldable_deque.hpp](https://github.com/winter-2521/cp-library/blob/main/data_structure/foldable_deque.hpp)

## 1. 概要

本記事では、キュー（待ち行列）に入っている要素 **全体の積** を、いつでもすぐに答えられるようにするデータ構造 **SWAG（Sliding Window Aggregation）** を解説します。さらに、両端から出し入れできる **デック版** も扱います。

ここでいう「積」は掛け算に限りません。和、最小値、GCD、行列の積、関数の合成、文字列の連結など、**結合法則** $(a \cdot b) \cdot c = a \cdot (b \cdot c)$ が成り立つ演算なら何でも構いません。特に、**交換法則が成り立たない（順番を入れ替えると結果が変わる）演算でもよい** のが重要な点です。

扱う問題は次の 2 つです。

>[!問題] 問題 1：Queue Operate All Composite（Library Checker）
>最初は空の 1 次関数の列 $f$ があります。次のクエリを $Q$ 回処理してください（$Q \le 5 \times 10^5$）。
>- `0 a b`：列の末尾に関数 $x \mapsto ax + b$ を追加する
>- `1`：列の先頭の関数を削除する
>- `2 x`：列を $f_l, \ldots, f_{r-1}$ として、$f_{r-1}(\cdots f_{l+1}(f_l(x)) \cdots) \bmod 998244353$ を出力する

>[!問題] 問題 2：Deque Operate All Composite（Library Checker）
>問題 1 に「先頭に追加」「末尾を削除」が加わります。

どちらも、1 回の操作をならし $O(1)$ で処理できます。

## 2. 前提知識

- スタック（後から入れたものを先に出す）とキュー（先に入れたものを先に出す）
- モノイド（結合法則が成り立ち、単位元がある演算）。[[セグメント木（モノイド）]] の前半で説明しています。
- ならし計算量（1 回 1 回は遅いことがあっても、合計すると速い、という考え方）

## 3. 例に使う演算：文字列の連結

1 次関数の合成は計算が大変なので、この記事の例では演算を **文字列の連結** にします。

$$\mathrm{op}(a, b) = a + b \quad (\text{例：} \mathrm{op}(\texttt{"ab"}, \texttt{"c"}) = \texttt{"abc"})$$

単位元は空文字列 `""` です。連結は順番を変えると結果が変わる（`"ab" + "c"` と `"c" + "ab"` は違う）ので、「正しい順番で掛けているか」が目で見て確認できます。キューの中身が先頭から `a`, `b`, `c` なら、全体の積は `"abc"` です。

問題 1 の関数の合成も、「先に $f$、次に $g$」を $\mathrm{op}(f, g)$ とすれば同じ形になります（この演算も順番を変えると結果が変わります）。

## 4. 素朴な方法

### 4.1. 毎回全部掛ける

キューを普通に持っておき、積を聞かれたら先頭から末尾まで順に掛けます。1 回 $O(n)$（$n$ はキューの長さ）なので、最悪 $Q$ 回 × $Q$ 個 $= 2.5 \times 10^{11}$ 回の演算になり、間に合いません。

### 4.2. セグメント木

$i$ 番目に追加した要素をセグメント木の位置 $i$ に置き、削除した位置は単位元にしておけば、全体の積は「先頭の位置から末尾の位置まで」の区間積で $O(\log Q)$ です。これで十分間に合いますが、

- 追加・削除のたびに $O(\log Q)$ かかる
- 長さ $Q$ の配列を先に用意する必要がある

という点で、もう少し速く・軽くしたくなります。以下では、積の取り方を工夫して、ならし $O(1)$ にします。

## 5. スタックなら簡単

いきなりキューを考える前に、**スタック** で同じことを考えます。スタックは末尾に入れて末尾から出すので、

> 各段に「底からその段までの積」を一緒に積んでおく

とすれば、全体の積は一番上の段の値を見るだけで $O(1)$ です。追加するときは「1 つ下の段の積 × 新しい要素」を積み、削除するときは一番上の段を捨てるだけです。

`a`, `b`, `c` を積むと次のようになります。

| 段（下から） | 要素 | 底からの積 |
| --- | --- | --- |
| 0 | a | "a" |
| 1 | b | "ab" |
| 2 | c | "abc" ← 全体の積 |

ここで `c` を捨てると、一番上は段 1 になり、全体の積は "ab" です。捨てた後の積を計算し直す必要がないのがポイントです。

**キューもスタック 2 本で作れる** ことが知られているので、この「積付きスタック」を 2 本使ってキューを作れば、全体の積もすぐ分かりそうです。

## 6. キュー版（SWAG）

### 6.1. スタック 2 本でキューを作る

キューの中身を「前半（先頭側）」と「後半（末尾側）」に分け、それぞれをスタックで持ちます。

- **後半スタック**：追加された要素をそのまま積む（一番上が末尾）。
- **前半スタック**：一番上が **先頭** になるように積む。

先頭を削除したいときは前半スタックの一番上を捨てます。前半スタックが空なら、後半スタックの中身を **全部** 前半スタックに移してから捨てます（後半スタックの一番上＝末尾から順に取り出して前半スタックに積むと、前半スタックの一番上が先頭になります）。

### 6.2. それぞれのスタックが持つ積

全体の積は「前半の積 × 後半の積」です（前半が先頭側なので左に来ます）。

- **後半スタック** は、積付きスタックそのものです。ただし必要なのは全体の積だけなので、各段の積は持たず、「後半全体の積」を 1 つだけ持てば足ります。
- **前半スタック** は、各段に「**その要素から、前半スタックの底まで** の積」を持ちます。前半スタックは一番上が先頭なので、上から下に向かって「先頭, 2 番目, 3 番目, …」と並んでいます。よって一番上の段の値は「先頭から前半の最後までの積」＝ **前半全体の積** です。

まとめると、持っているものは次の 4 つです。

| 名前 | 意味 |
| --- | --- |
| `back_val` | 後半の要素（追加された順、一番上が末尾） |
| `back_prod` | 後半全体の積 |
| `front_val` | 前半の要素（一番上が先頭） |
| `front_prod` | `front_prod[i]` = `front_val[i]` から前半スタックの底までの積 |

全体の積 ＝ `front_prod` の一番上（空なら単位元）× `back_prod` です。

### 6.3. 操作の手順

- **push(x)**（末尾に追加）
  1. `back_val` に x を積む。
  2. `back_prod` ← `back_prod` × x。
- **pop()**（先頭を削除）
  1. `front_val` が空なら、移し替えをする：`back_val` を上（末尾）から順に取り出し、取り出した要素を y として `front_val` に積み、`front_prod` に「y × （それまでの `front_prod` の一番上）」を積む（最初の 1 個は y そのもの）。最後に `back_val` を空、`back_prod` を単位元にする。
  2. `front_val` と `front_prod` の一番上を捨てる。
- **all_prod()**：`front_prod` の一番上 × `back_prod`。

移し替えで「取り出した要素 × それまでの積」と **左から** 掛けているのが大事です。取り出す順番は末尾 → 先頭なので、新しく積む要素はそれまでに積んだ要素より **前** にあるからです。

### 6.4. 例で追う

以下、スタックは左が底・右が一番上で書きます。

**push(a), push(b), push(c)**

```
front_val  = []            front_prod = []
back_val   = [a, b, c]     back_prod  = "abc"
全体の積 = "" + "abc" = "abc"
```

**pop()**：`front_val` が空なので移し替えます。

| 手順 | 取り出した要素 | `front_val` | `front_prod` に積む値 | `front_prod` |
| --- | --- | --- | --- | --- |
| 1 | c | [c] | "c" | ["c"] |
| 2 | b | [c, b] | "b" + "c" = "bc" | ["c", "bc"] |
| 3 | a | [c, b, a] | "a" + "bc" = "abc" | ["c", "bc", "abc"] |

一番上の a（先頭）と "abc" を捨てます。

```
front_val  = [c, b]        front_prod = ["c", "bc"]
back_val   = []            back_prod  = ""
全体の積 = "bc" + "" = "bc"        ← キューの中身 b, c の順
```

**push(d)**

```
front_val  = [c, b]        front_prod = ["c", "bc"]
back_val   = [d]           back_prod  = "d"
全体の積 = "bc" + "d" = "bcd"
```

**pop()**：`front_val` は空でないので、一番上の b を捨てるだけです。

```
front_val  = [c]           front_prod = ["c"]
back_val   = [d]           back_prod  = "d"
全体の積 = "c" + "d" = "cd"
```

以上の値は、ライブラリに文字列の連結を入れて実際に出力したものと一致します。

### 6.5. 実装

ライブラリの核心部分です（`M` はモノイド、`S` は値の型）。

```cpp
void push(const S &x) {
    back_val.push_back(x);
    back_prod = M::op(back_prod, x);           // 後半の積の右に掛ける
}

void pop() {
    if (front_val.empty()) move_back_to_front();
    front_val.pop_back();
    front_prod.pop_back();
}

S all_prod() const {
    if (front_prod.empty()) return back_prod;
    return M::op(front_prod.back(), back_prod); // 前半の積 × 後半の積
}

void move_back_to_front() {
    S acc = M::e();
    for (int i = (int)back_val.size() - 1; i >= 0; i--) {  // 末尾から順に
        acc = M::op(back_val[i], acc);                      // 左から掛ける
        front_val.push_back(back_val[i]);
        front_prod.push_back(acc);
    }
    back_val.clear();
    back_prod = M::e();
}
```

### 6.6. 計算量

pop の移し替えは 1 回で $O(n)$ かかることがありますが、**各要素は「後半に積まれる → 前半に移される → 捨てられる」の 3 回しか動きません**。$Q$ 回の操作で追加される要素は $Q$ 個以下なので、移し替えの合計は $O(Q)$ です。よって 1 回あたりならし $O(1)$ です。

## 7. デック版

### 7.1. 全部移すと遅くなる

両端から削除できるようにするため、キュー版と同じく「先頭側スタック」「末尾側スタック」を持ち、片方が空のときに削除が来たらもう片方から移すことにします。ただし、キュー版のように **全部** 移すと遅くなります。

全要素 $n$ 個が末尾側スタックにあるとき、

1. 先頭を削除 → 先頭側が空なので、末尾側を **全部** 先頭側に移す（$n$ 回）
2. 末尾を削除 → 末尾側が空になっているので、先頭側を **全部** 末尾側に移す（$n$ 回）
3. 先頭を削除 → また全部移す（$n$ 回）
4. …

と、削除のたびに $O(n)$ かかってしまいます。

### 7.2. 半分ずつに分ける

そこで、片方が空になったら **全要素を半分に分けて、両方のスタックを作り直す** ことにします。作り直した直後は両側に約半分ずつあるので、次にどちらかが空になるまでには、何回も削除が必要になります。

持つものは、キュー版の前半スタックを両側に用意した形です。

| 名前 | 意味 |
| --- | --- |
| `fv` | 先頭側の要素（一番上が先頭） |
| `fp` | `fp[i]` = `fv[i]` から先頭側スタックの底までの積 |
| `bv` | 末尾側の要素（一番上が末尾） |
| `bp` | `bp[i]` = 末尾側スタックの底から `bv[i]` までの積 |

全体の積 ＝ `fp` の一番上 × `bp` の一番上 です（片方が空ならもう片方だけ）。

### 7.3. 操作の手順

- **push_front(x)**：`fv` に x を積み、`fp` に「x × （`fp` の一番上）」を積む。
- **push_back(x)**：`bv` に x を積み、`bp` に「（`bp` の一番上）× x」を積む。
- **pop_front()**：`fv` が空なら作り直す（下記）。それから `fv`, `fp` の一番上を捨てる。
- **pop_back()**：`bv` が空なら作り直す。それから `bv`, `bp` の一番上を捨てる。
- **作り直し**：全要素を先頭から順に並べ、前半を先頭側、後半を末尾側に入れ直す（累積の積も作り直す）。要素数が奇数のときは、これから削除する側に多めに入れる。

### 7.4. 例で追う

**push_back で a, b, c, d**

```
fv = []                fp = []
bv = [a, b, c, d]      bp = ["a", "ab", "abc", "abcd"]
全体の積 = "abcd"
```

**pop_front()**：`fv` が空なので作り直します。並べると a, b, c, d。前半 a, b を先頭側、後半 c, d を末尾側に入れます。

```
fv = [b, a]            fp = ["b", "ab"]       ← 一番上の a が先頭
bv = [c, d]            bp = ["c", "cd"]
```

それから a を捨てます：`fv = [b]`、`fp = ["b"]`。全体の積 = "b" + "cd" = "bcd"。

**push_front(x)**：`fv = [b, x]`、`fp = ["b", "xb"]`。全体の積 = "xb" + "cd" = "xbcd"。

**pop_back() を 2 回**：`bv` から d、c を捨てます。全体の積 = "xb"。

**もう 1 回 pop_back()**：`bv` が空なので作り直します。並べると x, b。末尾側に 1 個入るように、先頭側に x、末尾側に b を入れてから、b を捨てます。全体の積 = "x"。

### 7.5. 計算量

ポテンシャル（「貯金」）として $\Phi = |\text{先頭側の要素数} - \text{末尾側の要素数}|$ を考えます。

- 追加と、作り直しをしない削除：$\Phi$ は高々 1 しか変わりません。
- 作り直し：直前は片側が空なので $\Phi = m$（$m$ は全要素数）。作り直した後は $\Phi \le 1$。作り直しのコスト $O(m)$ を、$\Phi$ の減少 $m - 1$ で払えます。

よって $Q$ 回の操作の合計は $O(Q)$、ならし $O(1)$ です。全部移す方法では作り直し後も $\Phi = m$ のままなので、この議論が使えません。

## 8. 正しさ

キューの中身を先頭から $x_1, \ldots, x_n$ とし、前半を $x_1, \ldots, x_k$、後半を $x_{k+1}, \ldots, x_n$ とします。

- `front_prod` の一番上 $= x_1 x_2 \cdots x_k$（移し替えで、前にある要素を左から掛けて作っているため）
- `back_prod` $= x_{k+1} \cdots x_n$（追加のたびに右から掛けているため）

なので `all_prod` は $x_1 \cdots x_n$ です。使ったのは結合法則だけで、交換法則は使っていません。デック版も同様です。

## 10. まとめ

- 積付きスタックなら全体の積は $O(1)$。キューは積付きスタック 2 本で作れる。
- 前半スタックには「その要素から底まで」の積を、前にある要素を **左から** 掛けて作る。これで非可換な演算でも正しい順番になる。
- デックでは、片側が空になったら **半分に分けて** 作り直すと、ならし $O(1)$ になる。
