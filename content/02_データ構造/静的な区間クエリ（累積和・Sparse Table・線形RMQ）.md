## 何ができるアルゴリズムか？

**配列が変わらない** とき、区間クエリを前計算して $O(1)$ で答える。

| 手法 | 前計算 | クエリ | 使える演算 |
| --- | --- | --- | --- |
| 累積和 | $O(n)$ | $O(1)$ | 逆元のある演算（和、xor など） |
| Sparse Table | $O(n \log n)$ | $O(1)$ | 冪等な演算（min, max, gcd, and, or） |
| 線形 RMQ（ブロック + ビットマスク） | $O(n)$ | $O(1)$ | min / max（とその位置） |

>[!問題] Static RMQ (Library Checker)
>長さ $N$ の数列に $Q$ 個のクエリ：$\min(a_l, \ldots, a_{r-1})$ を出力せよ。$N, Q \le 5 \times 10^5$

## 具体例で理解する

### なぜ min には累積和が使えないか

和は「$[0, r)$ の和 − $[0, l)$ の和」と引き算できた。min は「$[0, r)$ の min から $[0, l)$ の部分を取り除く」ことができない（取り除いた部分に最小値があったかどうか分からない）。そこで別の方法が要る。

### Sparse Table

**持っているもの**：全ての $k$（$2^k \le n$）と $i$ について、$t_{k,i} = \min(a_i, \ldots, a_{i + 2^k - 1})$（$i$ から長さ $2^k$ の区間の min）。

**作り方**：$t_{0,i} = a_i$。$t_{k,i} = \min(t_{k-1,i},\ t_{k-1,i + 2^{k-1}})$（長さ $2^k$ の区間を前半・後半の長さ $2^{k-1}$ の区間に分ける）。

$a = [5, 2, 8, 1, 9, 3, 7, 4]$ の場合：

| $k$（長さ $2^k$） | $i = 0$ | 1 | 2 | 3 | 4 | 5 | 6 | 7 |
| --- | --- | --- | --- | --- | --- | --- | --- | --- |
| 0（長さ 1） | 5 | 2 | 8 | 1 | 9 | 3 | 7 | 4 |
| 1（長さ 2） | 2 | 2 | 1 | 1 | 3 | 3 | 4 | |
| 2（長さ 4） | 1 | 1 | 1 | 1 | 3 | | | |

**クエリ $[l, r)$ の手順**：$2^k \le r - l$ となる最大の $k$ をとり、$\min(t_{k,l},\ t_{k, r - 2^k})$。

**例：$[1, 7)$**（長さ 6）：$k = 2$（長さ 4）。$[1, 5)$ と $[3, 7)$ の 2 つで区間全体を覆える（$[3, 5)$ は重なる）。$\min(t_{2,1}, t_{2,3}) = \min(1, 1) = 1$。

重なった $a_3, a_4$ を 2 回見ているが、min は同じ値を 2 回とっても変わらないので問題ない。和だと重なりを 2 回足してしまうので使えない。

### 線形 RMQ

Sparse Table は表が $n \log n$ 個で大きい。そこで 64 要素ずつのブロックに分けて、

- **ブロック間**：各ブロックの最小値（の位置）だけで Sparse Table を作る（$n / 64$ 要素なので小さい）。
- **ブロック内**：下の「単調スタック」をビットマスクで持つ。

**ブロック内で持っているもの**：各位置 $i$ について、ビットマスク $m_i$。「ブロックの先頭から $i$ まで左から見たとき、まだ『右に自分以下の値が来ていない』要素の位置」の集合。

作り方：左から順に、新しい値より **大きい** 要素をスタックから捨ててから、新しい位置を積む。

$a = [5, 2, 8, 1, 9, 3]$ の場合：

| $i$ | $a_i$ | 捨てるもの | スタック（= $m_i$ のビット） |
| --- | --- | --- | --- |
| 0 | 5 | | $\{0\}$ |
| 1 | 2 | 位置 0（5 > 2） | $\{1\}$ |
| 2 | 8 | | $\{1, 2\}$ |
| 3 | 1 | 位置 2（8）、位置 1（2） | $\{3\}$ |
| 4 | 9 | | $\{3, 4\}$ |
| 5 | 3 | 位置 4（9） | $\{3, 5\}$ |

**ブロック内の $[l, i]$ の min**：$m_i$ のうち $l$ 以上のビットで **最も下のもの** の位置。

- $[2, 5]$：$m_5 = \{3, 5\}$ で 2 以上の最小 → 位置 3 → $a_3 = 1$。実際 $\min(8, 1, 9, 3) = 1$。
- $[4, 5]$：4 以上の最小 → 位置 5 → $a_5 = 3$。実際 $\min(9, 3) = 3$。

正しい理由：$[l, i]$ の最小値（同じ値が複数あれば一番左）は、自分より右に自分より小さい値がないので捨てられずに残っている。それより左にある残りの要素は、もしあれば最小値以下のはずで、一番左の最小値という仮定に反する。よって $l$ 以上で一番左に残っている要素が最小値。「$l$ 以上で一番下のビット」は `ctz(m_i >> l)` の 1 命令。

**クエリの手順**：$[l, r)$ が 1 つのブロックに収まればブロック内の方法。またがるなら「左端のブロックの $l$ 以降」「間のブロック全体（Sparse Table）」「右端のブロックの $r-1$ まで」の 3 つの min。

## 証明・仕組み

### 累積和

$s_i = a_0 + \cdots + a_{i-1}$ とすると $\sum_{i=l}^{r-1} a_i = s_r - s_l$。引き算（逆元）が要るので min などには使えない。
2 次元なら $s_{i,j}$ = 左上 $[0,i) \times [0,j)$ の和として、包除原理で長方形の和を 4 項で求める。

### Sparse Table

$t_{k,i} = \mathrm{op}(a_i, \ldots, a_{i + 2^k - 1})$ を全ての $k, i$ について持つ（$t_{k,i} = \mathrm{op}(t_{k-1,i}, t_{k-1,i+2^{k-1}})$ で $O(n \log n)$）。

区間 $[l, r)$ は $2^k \le r - l$ となる最大の $k$ について、$[l, l+2^k)$ と $[r - 2^k, r)$ の **2 つの区間で覆える**（重なりがある）。演算が冪等（$x \cdot x = x$）なら重なった部分を 2 回数えても答えは変わらないので、$\mathrm{op}(t_{k,l}, t_{k, r-2^k})$ が答え。$k$ は `__builtin_clz` で $O(1)$。

和は冪等でないので使えない（重なりを 2 回足してしまう）。

### 線形 RMQ

Sparse Table はメモリが $O(n \log n)$ でキャッシュに乗りにくい。そこで 64 要素ずつのブロックに分ける。

- **ブロック間**：各ブロックの最小値の位置だけで Sparse Table を作る。要素数 $n/64$ なので $O(\frac{n}{64} \log n) = O(n)$。
- **ブロック内**：ブロック先頭から $i$ まで左から順に見たときの **単調スタック**（最小値の候補：右にある自分以下の値がまだ来ていないもの）を、ブロック内の位置のビットマスク $m_i$（64 bit）で持つ。

ブロック内の区間 $[l, i]$ の最小値の位置は、$m_i$ のうち $l$ 以上のビットで **最も下のもの**。理由：スタックに残っている要素は値が左から単調増加していて、$l$ 以上で最も左に残っている要素は、$[l, i]$ の中で自分より右に自分より小さい値がない＝区間の最小値。よって `ctz(m_i >> l)` で $O(1)$。

クエリは「左端のブロックの端数 + 間のブロック (Sparse Table) + 右端のブロックの端数」の 3 つの min。全部 $O(1)$。手元では Sparse Table とほぼ同じ速さで、メモリは $1/10$ 程度。
