ライブラリ：[static_range_lis.hpp](https://github.com/winter-2521/cp-library/blob/main/data_structure/static_range_lis.hpp)

## 1. 概要

本記事では、静的な数列 $a$ について、区間 $[l, r)$ の **最長増加部分列（LIS）の長さ** を、前計算 $O(n \log^2 n)$ のあと 1 回 $O(\log n)$ で答える方法を解説します。Tiskin による **Seaweed（海藻）法** と呼ばれる方法です。

全体の流れは次の通りです。

1. LIS を、格子の上を流れる「ひも」の行き先で表す（5〜6 節）。
2. ひもの行き先が分かれば、各クエリは長方形の点の個数で $O(\log n)$（6 節）。
3. ひもの行き先を、値で半分に分ける分割統治で求める（8 節）。
4. 分割統治の「合成」を、steady ant 法で $O(n \log n)$ で行う（9〜10 節）。

>[!問題] 問題 1：Static Range LIS Query（Library Checker）
>$\{0, \ldots, N-1\}$ の順列 $P$ に「$(P_l, \ldots, P_{r-1})$ の LIS の長さ」を $Q$ 回答えてください。（$N, Q \le 10^5$）

## 2. 前提知識

- LIS を二分探索で $O(n \log n)$ で求める方法
- 最長共通部分列（LCS）の DP
- 置換（$\{0, \ldots, n-1\}$ の並べ替え）と、その合成
- ウェーブレット行列（区間の中で値が $v$ 未満のものの個数）：[[ウェーブレット行列]]

## 3. 素朴な方法

- **クエリごとに LIS**：二分探索を使う LIS は $O(k \log k)$（$k = r - l$）。全体 $O(qn \log n) \approx 1.7 \times 10^{11}$ で間に合いません。
- **全区間を前計算**：左端 $l$ を決めて右に伸ばしながら LIS を更新すれば、$l$ ごとに $O(n \log n)$、全体 $O(n^2 \log n)$。$n = 10^5$ では無理です。

以下、例として $P = [1, 3, 0, 2]$（$n = 4$）を使います。区間ごとの LIS は次の通りです。

| | $r=1$ | $r=2$ | $r=3$ | $r=4$ |
| --- | --- | --- | --- | --- |
| $l=0$ | 1 | 2 | 2 | 2 |
| $l=1$ | | 1 | 1 | 2 |
| $l=2$ | | | 1 | 2 |
| $l=3$ | | | | 1 |

## 4. LIS は LCS

LIS（狭義増加部分列）は、「$P$」と「$0, 1, \ldots, n-1$」の **最長共通部分列（LCS）** と同じです。増加部分列は、値の小さい順に並んでいる部分列なので、$0, 1, \ldots, n-1$ の部分列にもなっているからです。

LCS は格子の上で考えられます。$n \times n$ の格子を作り、**列 $j$ = 位置 $j$**、**行 $v$ = 値 $v$**（上から $0, 1, \ldots$）とします。$P_j = v$ のマス $(v, j)$ を **一致マス** とします（順列なので、各行・各列にちょうど 1 つ）。

```
        列0 列1 列2 列3       (P = 1, 3, 0, 2)
行0      .   .   ●   .
行1      ●   .   .   .
行2      .   .   .   ●
行3      .   ●   .   .
```

LCS は、左上から右下へ「右か下」に進む道で、一致マスを斜めに通れる回数の最大値です。区間 $[l, r)$ の LIS は、列 $[l, r)$ だけの細い格子での LCS です。

## 5. 格子にひもを流す

ここに **ひも（seaweed）** を流します。

- 上の辺の各列から 1 本ずつ下向きに、左の辺の各行から 1 本ずつ右向きにひもが入ります。
- 各マスには上と左から 1 本ずつひもが入り、下と右に 1 本ずつ出ていきます。マスでは次のどちらかが起こります。
  - **交差**：上から来たひもは下へ、左から来たひもは右へ（まっすぐ進んで交差する）
  - **曲がる**：上から来たひもは右へ、左から来たひもは下へ（ぶつかって向きを変える）
- **一致マスでは曲がります**。
- 一致でないマスでは、2 本のひもが **まだ一度も交差していなければ交差** し、すでに交差したことがあれば曲がります（**同じ 2 本は 2 回交差しない**）。

マスを上の行から、各行は左から順に処理すると、例では次のようになります（実際にシミュレーションした結果）。

| | 列0 | 列1 | 列2 | 列3 |
| --- | --- | --- | --- | --- |
| 行0 | 交差 | 交差 | **一致**（曲がる） | 交差 |
| 行1 | **一致**（曲がる） | 交差 | 交差済み → 曲がる | 交差 |
| 行2 | 交差 | 交差 | 交差 | **一致**（曲がる） |
| 行3 | 交差 | **一致**（曲がる） | 交差済み → 曲がる | 交差済み → 曲がる |

上の辺の列 $j$ から入ったひもを $T_j$ と呼ぶと、出口は次のようになります。

| ひも | $T_0$ | $T_1$ | $T_2$ | $T_3$ |
| --- | --- | --- | --- | --- |
| 出口 | 下の辺の列 3 | 下の辺の列 2 | 右の辺（行 0） | 右の辺（行 2） |

## 6. LIS はひもの出口から分かる

$\mathrm{end}_j$ を「$T_j$ が下の辺に出る列（右の辺に出るなら $n$ 以上の値）」とすると、次が成り立ちます（Tiskin の定理）。

$$\mathrm{LIS}(P_l, \ldots, P_{r-1}) = (r - l) - \#\{\, j \in [l, r) : \mathrm{end}_j < r \,\}$$

つまり「区間の列から入ったひものうち、区間の列の中で下に抜けてしまったもの」の本数を、区間の長さから引いたものです。

例で確かめます（$\mathrm{end} = [3, 2, 7, 5]$ とします。右の辺の行 $i$ は $n + (n - 1 - i)$ と番号を付けています）。

| 区間 | $\mathrm{end}_j < r$ となる $j$ | 計算 | LIS |
| --- | --- | --- | --- |
| $[0, 4)$ | $j = 0\ (3)$, $j = 1\ (2)$ | $4 - 2$ | 2 ✓ |
| $[1, 4)$ | $j = 1\ (2)$ | $3 - 1$ | 2 ✓ |
| $[0, 3)$ | $j = 1\ (2)$ | $3 - 1$ | 2 ✓ |
| $[1, 3)$ | $j = 1\ (2)$ | $2 - 1$ | 1 ✓ |

$\#\{j \in [l, r) : \mathrm{end}_j < r\}$ は「点 $(j, \mathrm{end}_j)$ のうち $l \le j < r$ かつ $\mathrm{end}_j < r$ のものの個数」なので、$\mathrm{end}$ の列のウェーブレット行列で $O(\log n)$ です。

**この式が成り立つ理由（方針）**：列 $[l, r)$ だけの細い格子では、LCS の DP の表で「値が 1 増える場所」が、ちょうど「一致マスで曲がって右に抜けていくひも」に対応することが示せます。列 $[l, r)$ より左から入ってくるひもは、区間内のひもとは「まだ交差していないので交差する」だけで、区間内のひもの行き先に影響しません。詳しい証明は Tiskin の論文（参考文献）にあります。

## 7. 遅い方法：ひもを全部シミュレーション（$O(n^2)$）

5 節の表のように、マスを 1 つずつ処理すれば $\mathrm{end}$ が求まります。各マスでは、2 本のひもが交差済みかどうかを「ひもの番号の大小」で判定できます（入口の番号を、左の辺は下から $0, 1, \ldots$、上の辺は左から $n, n+1, \ldots$ と付けると、2 本がまだ交差していない ⇔ 左から来たひもの番号 < 上から来たひもの番号）。

しかし $n^2 = 10^{10}$ マスあるので間に合いません。ここからが高速化です。

## 8. 高速化 1：値で上下半分に分ける

### 8.1. 一致マスのない列は「透明」

行（値）を上半分（値 $< n/2$）と下半分に分けます。上半分の行だけを見ると、一致マスがあるのは $P_j < n/2$ の列だけです。

> 一致マスのない列では、上から入ったひもは **まっすぐ下に抜ける**。

上の辺から入ったばかりのひもは、その列のどのマスでも「左から来たひもとまだ交差していない」（番号が左から来たどのひもより大きい）ので、全部のマスで交差するからです。例では、上半分（行 0, 1）の列 1 と列 3 は、5 節の表で「交差」だけになっています。

### 8.2. 分割統治

そこで、

1. 上半分の行と、一致マスのある列だけを取り出した **半分の大きさの格子** で、ひもの行き先を再帰的に求める。
2. 取り出さなかった列は「まっすぐ下に抜ける」ひもとして、元の幅に戻す。
3. 下半分も同様。
4. 「上半分を通った結果」と「下半分を通った結果」を **つなぐ**（上半分の下の辺に出たひもが、下半分の上の辺から入る）。

とします。4. のつなぎ方が次の問題です。

## 9. つなぎ方：sticky 積

### 9.1. ひもの通り方は置換

ひもの通り方は、「左の辺と上の辺に並んだ $2n$ 本のひもの入口 → 下の辺と右の辺の出口」という **置換** で表せます。2 つの部分を順に通したときの置換は、普通の置換の合成では **ありません**。「前の部分ですでに交差した 2 本は、次の部分では交差しない」からです。

このルールでの合成を **sticky 積**（0-Hecke モノイドの積）と呼びます。

**例**：隣り合う 2 本のひもを交差させる操作を $s$ とします。$s$ を 2 回続けると、普通の置換なら元に戻ります（$s \cdot s = \mathrm{id}$）が、sticky 積では 2 回目は交差しないので $s \cdot s = s$ です。

### 9.2. sticky 積は (min, +) 積

置換 $\sigma$ を「点 $(i, \sigma(i))$ の集合」とみて、点の個数の 2 次元累積和

$$\sigma^\Sigma(i, k) = \#\{\, i' \ge i : \sigma(i') < k \,\}$$

を考えます。すると、$A$ を先に、$B$ を後に通したときの sticky 積 $C$ は

$$C^\Sigma(i, k) = \min_j \left( A^\Sigma(i, j) + B^\Sigma(j, k) \right)$$

で表せることが知られています（unit-Monge 行列の (min, +) 積）。これを $O(n \log n)$ で計算するのが **steady ant（着実な蟻）法** です。

## 10. steady ant 法

### 10.1. 中間の番号で半分に分ける

$A$ の出口 ＝ $B$ の入口を「中間の番号」と呼びます。中間の番号を半分 $[0, h)$ と $[h, n)$ に分けます。

1. 中間の番号が $[0, h)$ を通るひもだけを取り出して sticky 積を再帰的に求め、入口と出口の番号を元に戻したものを **赤い点** とします。
2. $[h, n)$ を通るものを **青い点** とします。

赤と青を合わせると、各入口（行）・各出口（列）にちょうど 1 点ずつあります。

### 10.2. 赤と青の境界

(min, +) 積の $\min_j$ を「$j \le h$ の部分」と「$j \ge h$ の部分」に分けると、それぞれが赤・青の再帰結果で書けます。2 つの差を計算すると、

$$\delta(i, k) = \#\{\text{青い点: 行} < i,\ \text{列} < k\} - \#\{\text{赤い点: 行} \ge i,\ \text{列} \ge k\}$$

になり、本当の答え $C$ は

- $\delta < 0$ の領域では **赤い点** と一致し、
- $\delta \ge 0$ の領域では **青い点** と一致する

ことが分かります。違いが出るのは、2 つの領域の **境界のマスだけ** です。

### 10.3. 蟻が境界を歩く

$\delta$ は $i$ についても $k$ についても単調に増えるので、境界は階段状の 1 本の道になります。各行 $i$ について「$\delta(i, k) \ge 0$ となる最小の $k$」を $K_i$ とすると、境界は $K_n \le K_{n-1} \le \cdots \le K_0$ をつないだ道です。

蟻が $(i, k) = (n, 0)$ から出発し、

- 上（$i - 1$）に進んでも $\delta \ge 0$ なら上へ、
- そうでなければ右（$k + 1$）へ

と歩くと、境界をたどって $(0, n)$ に着きます。$\delta$ は 1 歩ごとに「その行・列にある 1 点」を見て $\pm 1$ するだけで更新できるので、蟻の歩みは $O(n)$ です。

### 10.4. 境界のマスを直す

境界にまたがるマスについては、4 隅の $\delta$ から点があるかどうかを直接計算します（$C^\Sigma$ の 2 次元の差分）。$\delta$ は 1 歩で高々 1 しか変わらないので、境界の近くの $\delta$ は $-1, 0$ 付近に限られ、各マスは $O(1)$ で計算できます。

### 10.5. 例で追う

$A = [2, 0, 3, 1]$、$B = [1, 3, 0, 2]$（どちらも「入口 → 出口」）の sticky 積を考えます。$h = 2$ です。

- **赤い点**（中間が $[0, 2)$）：$A$ で中間 0, 1 に行く行は 1, 3。再帰で求めると、行 1 → 列 1、行 3 → 列 3。
- **青い点**（中間が $[2, 4)$）：行 0 → 列 0、行 2 → 列 2。

$\delta(i, k)$ の表（$i$ が行の番号、$k$ が列の番号）：

| | $k=0$ | $k=1$ | $k=2$ | $k=3$ | $k=4$ |
| --- | --- | --- | --- | --- | --- |
| $i=0$ | −2 | −2 | −1 | −1 | **0** |
| $i=1$ | −2 | −1 | **0** | 0 | 1 |
| $i=2$ | −1 | **0** | 0 | 0 | 1 |
| $i=3$ | −1 | **0** | 0 | 1 | 2 |
| $i=4$ | **0** | 1 | 1 | 2 | 2 |

太字が各行の境界 $K_i$ です（$K = [4, 2, 1, 1, 0]$）。左上の負の領域では赤、右下の 0 以上の領域では青が採用され、境界のマスを計算し直すと、結果は

$$C = [3, 1, 2, 0] \quad (\text{行 0 → 列 3、行 1 → 列 1、行 2 → 列 2、行 3 → 列 0})$$

になります。これは、$A$ と $B$ を隣接交換の列に分解して「まだ交差していなければ交差」で順に適用した結果と一致します（Python で確認しました）。

### 10.6. 計算量

steady ant は再帰が $\log n$ 段で各段 $O(n)$ なので $O(n \log n)$ です。8 節の値の分割統治も $\log n$ 段で、各段で大きさの合計 $O(n)$ の sticky 積をするので、全体 $O(n \log^2 n)$ です。

## 11. 実装の工夫

最初の実装は手元の最大ケースで 1.7 秒かかりました。

1. 再帰の中で毎回 `vector` を作っていたのをやめ、最初に確保した作業領域を **使い回す**（スタックのように確保・解放する）→ 0.66 秒
2. 値の分割統治の側でも作業領域を共有する → 0.58 秒
3. 大きさ 32 以下の sticky 積は再帰せず、**直接シミュレーション**（$B$ を隣り合う交差の列に分解して、$A$ の並びに「まだ交差していなければ交差」で適用する、$O(n^2)$）→ 0.4 秒

小さいサイズでの直接計算は次の通りです。

```cpp
if (n <= 32) {
    int at[32], tb[32], word[32 * 31 / 2], len = 0;
    for (int i = 0; i < n; i++) at[a[i]] = i, tb[b[i]] = i;   // at[位置] = その位置にいるひも
    for (int i = 0; i < n; i++)                                // b をバブルソートで隣接交換の列に分解
        for (int p = 0; p + 1 < n - i; p++)
            if (tb[p] > tb[p + 1]) swap(tb[p], tb[p + 1]), word[len++] = p;
    for (int t = len - 1; t >= 0; t--) {                       // 逆順に適用すると b になる
        int p = word[t];
        if (at[p] < at[p + 1]) swap(at[p], at[p + 1]);         // まだ交差していなければ交差
    }
    for (int x = 0; x < n; x++) res[at[x]] = x;
    return;
}
```

## 13. まとめ

- LIS は LCS で、LCS は格子の上を「2 回交差しない」ルールで流れるひもの行き先から分かる。区間 LIS は「区間内で下に抜けたひもの本数」を引くだけ。
- ひもの行き先は、値で上下半分に分けて再帰し、2 つの結果を sticky 積でつなげば求まる。一致のない列は透明（ひもがまっすぐ下に抜ける）なので、半分の大きさに縮められる。
- sticky 積は (min, +) 積で、中間の番号で半分に分けた赤と青の結果を、蟻が歩いた境界だけ直せば $O(n \log n)$。
