#データ構造 #区間クエリ #平方分割 #転倒数

ライブラリ：[static_range_inversions.hpp](https://github.com/winter-2521/cp-library/blob/main/data_structure/static_range_inversions.hpp)

## 何ができるアルゴリズムか？

静的な数列 $a$ について、区間 $[l, r)$ の **転倒数**（$l \le i < j < r$ かつ $a_i > a_j$ となる組 $(i, j)$ の個数）を $O(\sqrt n)$ で答える。クエリを先読みしなくてよい（オンライン）。

>[!問題] Static Range Inversions Query (Library Checker)
>長さ $N$ の数列に「$a_l, \ldots, a_{r-1}$ の転倒数」を $Q$ 回答えよ。$N, Q \le 10^5$

## 計算量

構築 $O(n \sqrt n)$、クエリ $O(\sqrt n)$、メモリ $O(n \sqrt n)$。

## 具体例で理解する

例：$a = [4, 2, 5, 1, 3, 6, 0]$（$n = 7$）、ブロックの大きさ $B = 3$。

```
位置   0 1 2 | 3 4 5 | 6
a      4 2 5 | 1 3 6 | 0
       ブロック0  ブロック1  ブロック2
```

### まず遅い方法

- **1 クエリずつ BIT**：区間を左から見て、「すでに見た値のうち自分より大きいものの個数」を BIT で数えて足す。1 回 $O((r-l) \log n)$、全体 $O(nq \log n)$ で間に合わない。
- **Mo's algorithm**：クエリを先読みして並べ替え、区間の端を 1 つずつ動かしながら BIT で転倒数を更新する。$O(n \sqrt q \log n) \approx 5 \times 10^8$ で間に合うが重く、オンラインでは使えない。

### アイデア：3 つの部分に分けて、組の種類ごとに数える

区間 $[l, r)$ を「左の端数 $P$」「間の完全なブロックたち $M$」「右の端数 $S$」に分けると、転倒の組 $(i, j)$ は次の 6 種類のどれか：

| $i$ の場所 | $j$ の場所 | 数え方 |
| --- | --- | --- |
| $P$ | $P$ | 前計算 `suf` |
| $S$ | $S$ | 前計算 `pre` |
| $M$ | $M$ | 前計算 `big` |
| $P$ | $M$ | 端数の各要素について「$M$ の中で自分より小さいものの個数」を足す |
| $M$ | $S$ | 端数の各要素について「$M$ の中で自分より大きいものの個数」を足す |
| $P$ | $S$ | $P$ と $S$ をそれぞれ値でソートしたリストをマージして数える |

どれも $O(B)$ か $O(1)$ でできれば、1 クエリ $O(B + n/B)$。

### 持っているもの

| 名前 | 意味 |
| --- | --- |
| `pre[i]` | $i$ のブロックの先頭から $i$ までの中の転倒数 |
| `suf[i]` | $i$ から $i$ のブロックの末尾までの中の転倒数 |
| `big[L][R]` | ブロック $L, \ldots, R-1$ の中の転倒数 |
| `lt[R][i]` | $i$ のブロックの **次のブロックから** ブロック $R-1$ までの中で、$a_i$ より小さいものの個数 |
| `gt[L][j]` | ブロック $L$ から $j$ のブロックの **1 つ前まで** の中で、$a_j$ より大きいものの個数 |
| ブロックごとのソート済みリスト | ブロックの (値, 位置) を値の昇順に並べたもの |

例の値（実際にライブラリで出力したもの）：

```
pre = [0, 1, 1 | 0, 0, 0 | 0]       (ブロック0: 4,2 で 1 個)
suf = [1, 0, 0 | 0, 0, 0 | 0]
big[0][2] = 6   (4 2 5 1 3 6 の転倒数)    big[1][2] = 0    big[1][3] = 3   (1 3 6 0)
lt[2] = [2, 1, 2 | ...]   例: lt[2][2] = ブロック1 (1,3,6) の中で 5 より小さいもの = 2
gt[1] = [..., ... | 6 の位置 → 3]   gt[1][6] = ブロック1 (1,3,6) の中で 0 より大きいもの = 3
```

`big` は $\mathrm{big}[L][R] = \mathrm{big}[L][R-1] + \mathrm{big}[L+1][R] - \mathrm{big}[L+1][R-1] + (\text{ブロック } L \text{ と } R-1 \text{ の間の組})$ で、包除原理で埋める。

### 操作の手順：query(l, r)

1. $l$ のブロック $l_b$、$r-1$ のブロック $r_b$ を求める。同じブロックなら、`pre` の差から「$[\text{先頭}, l)$ と $[l, r)$ の間の組」を引く（その組はソート済みリストをなめて数える）。
2. 違うブロックなら：
   - `suf[l]` + `pre[r-1]` + `big[l_b+1][r_b]`
   - $+ \sum_{i \in P}$ `lt[r_b][i]`
   - $+ \sum_{j \in S}$ `gt[l_b+1][j]`
   - $+$（$P$ の要素 $>$ $S$ の要素 の組）：ブロック $l_b$ と $r_b$ のソート済みリストを、位置が区間に入るものだけ見ながら 2 本のポインタでマージする。

### 例で追う：query(1, 7)（中身 2, 5, 1, 3, 6, 0）

$l_b = 0$、$r_b = 2$。$P$ = 位置 1, 2（値 2, 5）、$M$ = ブロック 1（値 1, 3, 6）、$S$ = 位置 6（値 0）。

| 部分 | 値 | 中身 |
| --- | --- | --- |
| $P$ の中 | `suf[1]` = 0 | (2, 5) は転倒でない |
| $S$ の中 | `pre[6]` = 0 | |
| $M$ の中 | `big[1][2]` = 0 | (1, 3, 6) |
| $P \times M$ | `lt[2][1]` + `lt[2][2]` = 1 + 2 = 3 | 2 > 1、5 > 1, 3 |
| $M \times S$ | `gt[1][6]` = 3 | 1, 3, 6 > 0 |
| $P \times S$ | 2 | 2 > 0、5 > 0 |

合計 **8**。実際に数えると (2,1), (2,0), (5,1), (5,3), (5,0), (1,0), (3,0), (6,0) の 8 個 ✓。

### 遅い版：値で引く表

最初に書いた版では、$P \times M$ を「値 $v$ 未満の要素が先頭 $b$ ブロックに何個あるか」の表 `less[b][v]` で数えていた（`less[r_b][a_i] - less[l_b+1][a_i]`）。これでも計算量は同じだが、端数の要素を順に見ると $a_i$ がばらばらなので **表のあちこちを読む**（キャッシュミス）。手元の最大ケースで 0.83 秒。

### 高速化：位置で引く表にする

`lt[R][i]` は位置 $i$ で引く表なので、端数の要素を位置の順に見ると **表を連続して読む** ことになり、キャッシュに乗る。$M \times S$ 側も同じ理由で `gt[L][j]` にした。さらにブロックの大きさを調整（$B = 1.25 \sqrt n$）して、手元 0.83 秒 → 0.52 秒になった。

`lt` の作り方：$\mathrm{lt}[R][i] = \mathrm{lt}[R-1][i] + (\text{ブロック } R-1 \text{ の中で } a_i \text{ より小さいもの})$。後ろの項は、全要素を値の昇順に見ながら、ブロック $R-1$ のソート済みリストのポインタを進めれば、$R$ ごとに $O(n)$ で全部の $i$ について求まる。`big` の「ブロック $L$ と $R-1$ の間の組」も $\sum_{i \in L} (\mathrm{lt}[R][i] - \mathrm{lt}[R-1][i])$ で求まる。

## 証明・仕組み

### 正しさ

転倒の組 $(i, j)$（$i < j$）は、$i$ と $j$ がそれぞれ $P, M, S$ のどこにあるかで上の 6 種類にちょうど 1 回ずつ分類される（$i < j$ なので「$M$ と $P$」のような逆順はない）。各表はその種類の組をちょうど数えている。

同じブロック内のクエリでは、$\mathrm{pre}[r-1] - \mathrm{pre}[l-1]$ は「$[\text{先頭}, r)$ の転倒数 − $[\text{先頭}, l)$ の転倒数」で、これは $[l, r)$ の中の組と「$[\text{先頭}, l)$ と $[l, r)$ の間の組」の和なので、後者を引けばよい。

### 計算量

- 構築：`lt`, `gt` が $O(n \cdot n/B)$、`pre`, `suf` が $O(n B)$、`big` が $O((n/B)^2 \cdot B) = O(n \cdot n/B)$。
- クエリ：端数 $O(B)$、マージ $O(B)$。
- メモリ：`lt`, `gt` で $2n \cdot n/B$ 個の int（$n = 10^5$ で約 200 MB）。
