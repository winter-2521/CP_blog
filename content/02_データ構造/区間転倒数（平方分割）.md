#データ構造 #区間クエリ #平方分割 #転倒数

ライブラリ：[static_range_inversions.hpp](https://github.com/winter-2521/cp-library/blob/main/data_structure/static_range_inversions.hpp)

## 1. 概要

本記事では、静的な数列 $a$ について、区間 $[l, r)$ の **転倒数**（$l \le i < j < r$ かつ $a_i > a_j$ となる組 $(i, j)$ の個数）を $O(\sqrt n)$ で答える方法を解説します。クエリを先読みしなくてよい（オンライン）方法です。

>[!問題] 問題 1：Static Range Inversions Query（Library Checker）
>長さ $N$ の数列に「$a_l, \ldots, a_{r-1}$ の転倒数」を $Q$ 回答えてください。（$N, Q \le 10^5$）

## 2. 前提知識

- 転倒数を BIT で数える方法：[[Fenwick Tree]]
- 平方分割（列を長さ $B$ のブロックに分ける考え方）：[[区間最頻値（平方分割）]]

## 3. 素朴な方法

### 3.1. クエリごとに BIT

区間を左から見て、「すでに見た値のうち自分より大きいものの個数」を BIT で数えて足すと、1 回 $O((r - l) \log n)$ です。全体 $O(nq \log n) \approx 1.7 \times 10^{11}$ で間に合いません。

### 3.2. Mo's algorithm

クエリを先読みして並べ替え、区間の端を 1 つずつ動かしながら BIT で転倒数を更新する方法です。$O(n \sqrt q \log n) \approx 5 \times 10^8$ で間に合いますが、重く、オンラインでは使えません。

以下では、平方分割で **オンラインかつ $\log$ の付かない** 方法を作ります。

## 4. 組を 6 種類に分ける

列を長さ $B$ のブロックに分け、区間 $[l, r)$ を「左の端数 $P$」「間の完全なブロックたち $M$」「右の端数 $S$」に分けます。転倒の組 $(i, j)$（$i < j$）は、$i$ と $j$ がどこにあるかで次の 6 種類のどれかです（$i < j$ なので、「$M$ と $P$」のような逆順はありません）。

| $i$ の場所 | $j$ の場所 | 数え方（この後で説明） |
| --- | --- | --- |
| $P$ | $P$ | 前計算 `suf` |
| $S$ | $S$ | 前計算 `pre` |
| $M$ | $M$ | 前計算 `big` |
| $P$ | $M$ | 端数の各要素について表を引いて足す |
| $M$ | $S$ | 端数の各要素について表を引いて足す |
| $P$ | $S$ | 2 つの端数をソート済みリストでマージ |

どれも $O(B)$ か $O(1)$ でできれば、1 クエリ $O(B + n/B)$ です。

## 5. 前計算する表

| 名前 | 意味 |
| --- | --- |
| `pre[i]` | $i$ のブロックの先頭から $i$ までの中の転倒数 |
| `suf[i]` | $i$ から $i$ のブロックの末尾までの中の転倒数 |
| `big[L][R]` | ブロック $L, \ldots, R-1$ の中の転倒数 |
| `lt[R][i]` | $i$ のブロックの **次のブロックから** ブロック $R-1$ までの中で、$a_i$ より小さいものの個数 |
| `gt[L][j]` | ブロック $L$ から $j$ のブロックの **1 つ前まで** の中で、$a_j$ より大きいものの個数 |
| ソート済みリスト | ブロックごとに (値, 位置) を値の昇順に並べたもの |

- `big` は包除原理で埋めます：$\mathrm{big}[L][R] = \mathrm{big}[L][R-1] + \mathrm{big}[L+1][R] - \mathrm{big}[L+1][R-1] + (\text{ブロック } L \text{ と } R-1 \text{ の間の組})$。
- `lt` は $R$ を 1 つずつ増やしながら、$\mathrm{lt}[R][i] = \mathrm{lt}[R-1][i] + (\text{ブロック } R-1 \text{ の中で } a_i \text{ より小さいもの})$ で作ります。後ろの項は、全要素を値の昇順に見ながら、ブロック $R-1$ のソート済みリストのポインタを進めれば、$R$ ごとに $O(n)$ で全ての $i$ について求まります。`gt` も同様です。
- `big` の「ブロック $L$ と $R-1$ の間の組」は $\sum_{i \in L} (\mathrm{lt}[R][i] - \mathrm{lt}[R-1][i])$ です。

## 6. クエリの手順

1. $l$ のブロック $l_b$、$r - 1$ のブロック $r_b$ を求める。
2. **同じブロック** なら：`pre[r-1] - pre[l-1]` は「$[\text{先頭}, r)$ の転倒数 − $[\text{先頭}, l)$ の転倒数」で、これは $[l, r)$ の中の組に「$[\text{先頭}, l)$ と $[l, r)$ の間の組」を足したものです。後者をソート済みリストをなめて数えて引きます。
3. **違うブロック** なら：
   - `suf[l]` + `pre[r-1]` + `big[l_b+1][r_b]`
   - $+ \sum_{i \in P}$ `lt[r_b][i]`
   - $+ \sum_{j \in S}$ `gt[l_b+1][j]`
   - $+$（$P$ の要素 $>$ $S$ の要素 の組）：ブロック $l_b$ と $r_b$ のソート済みリストを、位置が区間に入るものだけ見ながら 2 本のポインタでマージして数える。

## 7. 例で追う

$a = [4, 2, 5, 1, 3, 6, 0]$（$n = 7$）、$B = 3$ とします。

```
位置   0 1 2 | 3 4 5 | 6
a      4 2 5 | 1 3 6 | 0
     ブロック0  ブロック1  ブロック2
```

### 7.1. 表の値（ライブラリで出力したもの）

```
pre = [0, 1, 1 | 0, 0, 0 | 0]      (ブロック0 の 4 > 2 で 1 個)
suf = [1, 0, 0 | 0, 0, 0 | 0]

big[0][1] = 1    big[0][2] = 6    big[0][3] = 12
                 big[1][2] = 0    big[1][3] = 3

lt[2] = [2, 1, 2 | 0, 0, 0 | 0]    例: lt[2][2] = ブロック1 (1,3,6) の中で 5 より小さいもの = 2
lt[3] = [3, 2, 3 | 1, 1, 1 | 0]
gt[0] = [0, 0, 0 | 3, 2, 0 | 6]
gt[1] = [0, 0, 0 | 0, 0, 0 | 3]    例: gt[1][6] = ブロック1 (1,3,6) の中で 0 より大きいもの = 3
```

### 7.2. query(1, 7)

中身は $2, 5, 1, 3, 6, 0$。$l_b = 0$、$r_b = 2$ で、$P$ = 位置 1, 2（値 2, 5）、$M$ = ブロック 1（値 1, 3, 6）、$S$ = 位置 6（値 0）です。

| 部分 | 値 | 中身 |
| --- | --- | --- |
| $P$ の中 | `suf[1]` = 0 | (2, 5) は転倒でない |
| $S$ の中 | `pre[6]` = 0 | |
| $M$ の中 | `big[1][2]` = 0 | (1, 3, 6) |
| $P \times M$ | `lt[2][1]` + `lt[2][2]` = 1 + 2 = 3 | 2 > 1、5 > 1, 3 |
| $M \times S$ | `gt[1][6]` = 3 | 1, 3, 6 > 0 |
| $P \times S$ | 2 | 2 > 0、5 > 0 |

合計 **8** です。直接数えると $(2,1), (2,0), (5,1), (5,3), (5,0), (1,0), (3,0), (6,0)$ の 8 個で一致します。

## 8. 遅い版と高速化

### 8.1. 遅い版：値で引く表

最初の実装では、$P \times M$ を「値 $v$ 未満の要素が先頭 $b$ ブロックに何個あるか」の表 `less[b][v]` で数えていました（`less[r_b][a_i] - less[l_b+1][a_i]`）。計算量は同じですが、端数の要素を順に見ると $a_i$ がばらばらなので、**表のあちこちを読む** ことになり、キャッシュミスが多発します。手元の最大ケースで 0.83 秒かかりました。

### 8.2. 高速化：位置で引く表

`lt[R][i]` は **位置 $i$ で引く** 表なので、端数の要素を位置の順に見ると **表を連続して読む** ことになり、キャッシュに乗ります。$M \times S$ 側も同じ理由で `gt[L][j]` にしました。さらにブロックの大きさを $B = 1.25 \sqrt n$ に調整して、手元で 0.83 秒 → 0.52 秒になりました。

```cpp
long long res = suf[l] + pre[r - 1] + big[(size_t)(lb + 1) * (nb + 1) + rb];
const int *ltr = &lt[(size_t)rb * n], *gtl = &gt[(size_t)(lb + 1) * n];
for (int i = l; i < (lb + 1) * B; i++) res += ltr[i];   // 連続アクセス
for (int j = rb * B; j < r; j++) res += gtl[j];         // 連続アクセス
```

## 9. 計算量

- 前計算：`lt`, `gt` が $O(n \cdot n/B)$、`pre`, `suf` が $O(nB)$、`big` が $O(n \cdot n/B)$。
- クエリ：端数 $O(B)$、マージ $O(B)$。
- メモリ：`lt`, `gt` で $2n \cdot n/B$ 個の int（$n = 10^5$ で約 200 MB）。

【問題 2】区間 $[l, r)$ の「$i < j$ かつ $a_i < a_j$ の組」の個数を答えてください。
（ヒント：全体の組の数 $\binom{r-l}{2}$ から、転倒数と「$a_i = a_j$ の組」を引けばよいです。値を $-a_i$ にした数列の転倒数を数える方法もあります。）

## 11. まとめ

- 区間を「左の端数・間のブロック・右の端数」に分け、転倒の組を 6 種類に分けて、それぞれ前計算の表で数える。
- 端数 × ブロックは、位置で引く表 `lt` / `gt` にすると連続アクセスになって速い。
- 前計算 $O(n \sqrt n)$、クエリ $O(\sqrt n)$ で、クエリの先読みも $\log$ も要らない。
