#データ構造 #セグ木

ライブラリ：[dual_segment_tree.hpp](https://github.com/winter-2521/cp-library/blob/main/data_structure/dual_segment_tree.hpp)

## 何ができるアルゴリズムか？

区間に作用させて、**一点の値を取得する** だけなら、遅延セグ木より軽い双対セグ木で $O(\log n)$。作用は非可換でもよい（区間 1 次関数など）。

>[!問題] Range Affine Point Get (Library Checker)
>`0 l r b c`：$i \in [l, r)$ について $a_i \gets b a_i + c$、`1 i`：$a_i$ を出力。$N, Q \le 5 \times 10^5$

## 計算量

区間作用・一点取得とも $O(\log n)$。

## 具体例で理解する

### 遅延セグ木の「半分」だけを使う

[[遅延セグ木まとめ]] では、ノードに「値」と「まだ子に伝えていない作用（lazy）」の 2 つを持った。区間の値を **聞かない**（一点だけ聞く）なら、値は要らず lazy だけで足りる、というのが双対セグ木。

### 例：区間加算・一点取得

長さ 4 の配列（はじめ全て 0）に

1. $[0, 3)$ に $+3$
2. $[1, 4)$ に $+5$

をする。区間をノードに分解して、そのノードの lazy に足すだけ。

- $[0, 3)$ → ノード $[0,2)$ と $[2,3)$ に $+3$
- $[1, 4)$ → ノード $[1,2)$ と $[2,4)$ に $+5$

```
              [0,4): 0
       [0,2): +3        [2,4): +5
   [0,1):0  [1,2):+5  [2,3):+3  [3,4):0
```

$a_2$ を知りたければ、葉 $[2,3)$ から根まで登りながら lazy を全部足す：$3 + 5 + 0 = 8$。実際 $a_2$ には両方かかっているので $8$ で正しい。$a_0$ なら $0 + 3 + 0 = 3$。どちらも $O(\log n)$。

### 非可換だと「順番」が問題になる例

作用が「区間を $x$ にする（代入）」だとする。

1. $[0, 4)$ を $7$ にする → 根に「$=7$」
2. $[2, 3)$ を $2$ にする → 葉 $[2,3)$ に「$=2$」

$a_2$ は 2 であるべき。ところが葉から根へ「下 → 上」の順に作用を並べると「$=2$ → $=7$」で、後からかかった方が勝つ代入では 7 になってしまう。根の作用の方が **古い** のに、上にあるせいで新しいものとして扱われた。

そこで、作用をかける前に **通り道の古い作用を下に押し出しておく**（push）。2 の操作の前に、根の「$=7$」を子へ、さらに $[2,4)$ の「$=7$」を葉へ下ろしておけば、葉 $[2,3)$ には「$=7$ → $=2$」の順に正しく積まれる。こうすると「上のノードにある作用ほど新しい」が常に成り立ち、一点取得は「葉から根へ、古い順に合成」で正しくなる。

加算のように順番を変えても結果が同じ（可換）なら push は要らないが、このライブラリは常に push して非可換にも対応している。

## 証明・仕組み

セグ木の各ノードに「そのノードの区間全体にかかった作用（の合成）」だけを持つ（値は持たない）。

- **区間作用**：区間を $O(\log n)$ 個のノードに分解し、そのノードの作用に $f$ を合成する。
- **一点取得**：葉から根までのノードの作用を全て合成すれば、その位置にかかった作用の全体になる。

### 非可換のときの注意

作用が可換（加算など）なら、これだけで正しい。非可換だと **順番** が問題になる。位置 $i$ にかかった作用は時系列順に合成したいが、葉から根へのノードの作用は「上のノードが新しい」とは限らない（古い作用が根に、新しい作用が葉に近いノードにかかっていることがある）。

そこで区間作用の前に、**分解に使うノードの祖先の作用を子に下ろしておく**（遅延セグ木の push と同じ）。すると作用をかけるノードの祖先は全て空になるので、「祖先の作用は子孫の作用より新しい」が常に成り立つ。一点取得では葉から根に向かって「古い → 新しい」の順に合成すればよい。

push は境界の 2 本の経路だけなので $O(\log n)$。

### 遅延セグ木との違い

遅延セグ木は区間積を取るために各ノードに値も持ち、作用を値に反映する `mapping` が必要。双対セグ木は値を持たないので、作用のモノイドだけ書けばよい。区間積が要らないなら双対セグ木の方が速くて書きやすい。
