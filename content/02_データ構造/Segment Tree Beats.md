#データ構造 #セグ木 #ならし計算量

ライブラリ：[segment_tree_beats.hpp](https://github.com/winter-2521/cp-library/blob/main/data_structure/segment_tree_beats.hpp)

## 何ができるアルゴリズムか？

区間 chmin（$a_i \gets \min(a_i, x)$）・区間 chmax・区間加算と、区間和・区間 min・区間 max を、ならし $O(\log^2 n)$ で処理する。区間 chmin と区間和は普通の遅延セグ木には乗らない。

>[!問題] Range Chmin Chmax Add Range Sum (Library Checker)
>区間 chmin / 区間 chmax / 区間加算 / 区間和 を $Q$ 回処理せよ。$N, Q \le 2 \times 10^5$、$|a_i| \le 10^{12}$

## 計算量

ならし $O((n + q) \log^2 n)$。加算がなければ $O((n + q) \log n)$。

## 具体例で理解する

ここでは区間 chmin と区間和だけを考える（chmax は最小値側で左右反転したもの、加算は普通の遅延評価なので後回し）。

### 各ノードが持っているもの

普通の区間和のセグ木と同じ形の木で、各ノードが担当区間について次の 4 つを持つ。

| 名前 | 意味 |
| --- | --- |
| `sum` | 区間の和 |
| `max1` | 区間の最大値 |
| `cnt` | 最大値 `max1` に等しい要素の個数 |
| `max2` | 区間で **2 番目に大きい値**（`max1` より真に小さい値の中の最大）。なければ $-\infty$ |

$a = [5, 1, 7, 7]$ の初期状態：

```
                  根 [0,4)
           sum=20 max1=7 cnt=2 max2=5
            /                      \
      L [0,2)                     R [2,4)
  sum=6 max1=5 cnt=1 max2=1   sum=14 max1=7 cnt=2 max2=-∞
     /        \                  /         \
  [0]: 5    [1]: 1            [2]: 7     [3]: 7
```

（葉は値が 1 つなので `sum = max1 = その値`、`cnt = 1`、`max2 = -∞`。）

### 親の値を子 2 つから計算する（update）

親の 4 つの値は、子 L・R の値だけから計算できる。

- `sum` = L.sum + R.sum
- `max1` が L 側の方が大きいとき：`max1` = L.max1、`cnt` = L.cnt、`max2` = max(L.max2, R.max1)
- R 側の方が大きいとき：左右を入れ替えて同様
- 等しいとき：`max1` = L.max1、`cnt` = L.cnt + R.cnt、`max2` = max(L.max2, R.max2)

例：根は L.max1 = 5 < R.max1 = 7 なので `max1` = 7、`cnt` = R.cnt = 2、`max2` = max(L.max1, R.max2) = max(5, −∞) = 5。

### chmin($x$) をノードに直接かける（ノードで止める）

ノードについて `max2 < x < max1` が成り立っていれば、**$x$ より大きい要素は最大値の要素だけ** で、chmin($x$) で変わるのはそれら `cnt` 個が `max1` から $x$ になることだけ。なので子を見なくても

- `sum` -= (`max1` − $x$) × `cnt`
- `max1` = $x$（`cnt` と `max2` はそのまま）

とノードの値を直せる。これを **ノードで止める** と呼ぶ（子はまだ直さない）。

### chmin($l, r, x$) の手順

根から再帰的に次をする。

1. ノードの区間が $[l, r)$ と重ならない、または `max1` $\le x$（何も変わらない）なら **何もせず戻る**。
2. ノードの区間が $[l, r)$ に完全に含まれ、かつ `max2` $< x$ なら、**ノードで止める**（上の式）。戻る。
3. それ以外（区間が一部だけ重なる、または `max2` $\ge x$）なら、**push**（下で説明）してから **左右の子に再帰** し、戻ってきたら **update** で自分の値を子から計算し直す。

### push：止めたノードの情報を子に伝える

ノードで止めると、子の値は古いまま残る（例えば子の `max1` が 7 のままなのに、親の `max1` は 6）。子に降りる前に次を行う。

- 各子について、子の `max1` > 親の `max1` なら、子を「親の `max1` で chmin」する（子でもノードで止める式を使う）。

親でノードで止められたということは「親の区間で `max1` より大きかったのは最大値の要素だけ」なので、子でも必ず `max2` < 親の `max1` < 子の `max1` が成り立ち、子でもノードで止める式が使える。

### 例で追う

**操作 1：chmin(0, 4, 6)**（$a = [5, 1, 7, 7] \to [5, 1, 6, 6]$）

- 根：区間 $[0,4)$ は完全に含まれる。`max1` = 7 > 6、`max2` = 5 < 6 → **根で止める**。`sum` = 20 − (7 − 6) × 2 = 18、`max1` = 6。
- L と R には触らない。R は `max1` = 7、`sum` = 14 のまま（古い）。

```
                  根: sum=18 max1=6 cnt=2 max2=5
            L: sum=6 max1=5 ...       R: sum=14 max1=7 ...   ← R はまだ古い
```

根の `sum` = 18 は実際の $5 + 1 + 6 + 6 = 18$ と一致。

**操作 2：sum(2, 4)**（答えは $6 + 6 = 12$）

- 根：区間が一部だけ重なるので、子に降りる前に **push**。L.max1 = 5 は根の `max1` = 6 以下なので何もしない。R.max1 = 7 > 6 なので R を chmin(6)：R.sum = 14 − (7 − 6) × 2 = 12、R.max1 = 6。
- R：区間 $[2,4)$ が完全に含まれるので R.sum = **12** を返す。

**操作 3：chmin(0, 4, 4)**（$[5, 1, 6, 6] \to [4, 1, 4, 4]$）

- 根：`max1` = 6 > 4 だが `max2` = 5 $\ge$ 4（5 も 4 に変わる）→ 止められない。push（L.max1 = 5 ≤ 6、R.max1 = 6 ≤ 6 なので何もしない）して子に降りる。
  - L：`max1` = 5 > 4、`max2` = 1 < 4 → **L で止める**。L.sum = 6 − (5 − 4) × 1 = 5、L.max1 = 4。
  - R：`max1` = 6 > 4、`max2` = −∞ < 4 → **R で止める**。R.sum = 12 − (6 − 4) × 2 = 8、R.max1 = 4。
- 根を update：L.max1 = R.max1 = 4 で等しいので `max1` = 4、`cnt` = 1 + 2 = 3、`max2` = max(L.max2, R.max2) = max(1, −∞) = 1、`sum` = 5 + 8 = 13。

実際の和 $4 + 1 + 4 + 4 = 13$ と一致。葉 [0] は 5、葉 [2], [3] は 7 のまま古いが、そこまで降りるときに push で直される（例えば sum(2, 3) を聞くと、R から葉への push で葉 [2] が 4 になる）。

### なぜ降りすぎないのか

手順 3 で降りるのは「区間の境界にかかるノード」（普通のセグ木と同じく $O(\log n)$ 個）か、「`max2` $\ge x$ のノード」。後者では **最大値と 2 番目の値が両方 $x$ になって 1 つにまとまる** ので、そのノードの区間に含まれる値の種類が 1 つ以上減る（操作 3 の根では $\{1, 5, 6\} \to \{1, 4\}$）。

値の種類数は全ノードで合計しても初めは $O(n \log n)$ 以下で、chmin だけなら増えることはない。種類数が減るたびにしか余計に降りないので、余計に降りる回数は全体で $O(n \log n)$ 回まで（ならし計算量）。

### 区間加算と chmax

- **区間加算**：ノードに「まだ子に伝えていない加算量」を持ち、`sum` += 加算量 × 要素数、`max1`・`max2` にも加算量を足す（大小関係は変わらない）。push では加算を先に子に伝えてから、上の chmin の push をする。
- **chmax**：最小値側について同じものを持って左右反転。値が 1〜2 種類しかないノードでは「最大値と最小値が同じ要素」になるので、片方を変えたらもう片方も直す。

## 証明・仕組み

### なぜ遅延セグ木に乗らないか

区間和だけ持っていると、chmin($x$) で和がいくつ減るかが分からない（$x$ より大きい要素がいくつあり、いくつ大きいかは和からは分からない）。

### 最大値と 2 番目の最大値を持つ

各ノードに **最大値 $m_1$、2 番目に大きい値 $m_2$（狭義）、最大値の個数 $c$**、和を持つ。chmin($x$) をノードに適用するとき：

- $m_1 \le x$：何も変わらない。終了。
- $m_2 < x < m_1$：変わるのは最大値の要素だけで、それらが全て $x$ になる。和は $(m_1 - x) \cdot c$ 減り、$m_1 = x$。**このノードで止められる**（子にはタグとして「最大値は $x$ 以下」を後で伝える）。
- $x \le m_2$：子に降りて再帰する。

chmax も最小値側を同様に持てば対称。

### ならし計算量（加算なし）

ポテンシャル $\Phi$ = 「各ノードの部分木に含まれる値の種類数」の総和、とする。初期値は $O(n \log n)$。

3 つ目の場合（$x \le m_2$ で降りる）、そのノードでは $m_1$ と $m_2$ が両方 $x$ になるので種類数が 1 以上減る。つまり「余計に降りたノード」ごとに $\Phi$ が 1 以上減る。区間の境界の経路（普通のセグ木と同じ $O(\log n)$ 個）以外で降りるノードは全てこの場合なので、全体で $O((n + q) \log n)$。

加算があると境界の経路上で種類数が増えうる（1 回で $O(\log n)$ ノード × 各 $O(\log n)$）ので、全体 $O((n + q) \log^2 n)$ になる（Jiry 氏の解析）。

### タグの伝え方

push では、子の最大値が親の最大値より大きければ「子の最大値を親の最大値にする」（子では必ず 2 つ目の場合になる）。加算は通常の遅延評価。最大値と最小値が同じ要素（ノードの値が 1 種類・2 種類のとき）は、最大値側を変えたら最小値側も更新するなど、細かい場合分けが要る。
