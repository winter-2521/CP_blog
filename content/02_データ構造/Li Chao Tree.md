ライブラリ：[li_chao_tree.hpp](https://github.com/winter-2521/cp-library/blob/main/data_structure/li_chao_tree.hpp)

## 1. 概要

本記事では、直線を追加しながら「ある $x$ での最小値」を答えるデータ構造 **Li Chao Tree** を解説します。

- 直線 $y = ax + b$ を追加する
- $x \in [l, r)$ の範囲だけで定義された **線分** を追加する
- ある $x$ で、追加された直線（線分）の $y$ の最小値を求める

をどれも $O(\log C)$（線分の追加は $O(\log^2 C)$）で処理します。$C$ は $x$ の候補の個数です。いわゆる Convex Hull Trick（CHT）と同じことができますが、**直線の傾きや問い合わせる $x$ に順番の制限がなく**、線分も扱えるのが特徴です。

>[!問題] 問題 1：Line Add Get Min（Library Checker）
>$N$ 本の直線 $y = a_i x + b_i$ があります。「直線 $y = ax + b$ を追加」「$x = p$ での $y$ の最小値を出力」を $Q$ 回処理してください。（$N, Q \le 2 \times 10^5$、$|a|, |p| \le 10^9$、$|b| \le 10^{18}$）

>[!問題] 問題 2：Segment Add Get Min（Library Checker）
>問題 1 の直線が、$x \in [l, r)$ だけで定義された線分になります。$x = p$ を通る線分がなければ `INFINITY` を出力してください。（$-10^9 \le l < r \le 10^9$）

## 2. 前提知識

- セグメント木（区間を半分ずつに分けた二分木、区間を $O(\log n)$ 個のノードに分けること）：[[セグメント木（モノイド）]]
- 1 次関数のグラフ（直線）

## 3. 素朴な方法

追加された直線を全部覚えておき、問い合わせのたびに全部の直線で $ax + b$ を計算して最小を取ります。1 回 $O(\text{直線の本数})$ なので、$2 \times 10^5$ 本・$2 \times 10^5$ 回で $4 \times 10^{10}$ 回の計算になり、間に合いません。

## 4. 2 本の直線は 1 回しか交わらない

Li Chao Tree の鍵は次の性質です。

> 2 本の直線 $f, g$ は高々 1 点でしか交わらない。したがって、ある範囲 $[lo, hi)$ で「$f$ の方が小さい部分」は、範囲の **左端側か右端側の一方に寄った区間** になる。

例えば $f(x) = x$、$g(x) = -x + 6$ を $x \in [0, 8)$ で比べると、交点は $x = 3$ で、$x < 3$ では $f$ の方が小さく、$x > 3$ では $g$ の方が小さくなります。「$f$ が小さい部分」が真ん中だけ、ということはありません。

## 5. Li Chao Tree の構造

$x$ の範囲（例えば $[0, 8)$）をセグメント木のように半分ずつに分けた木を作り、**各ノードに直線を高々 1 本** 置きます。

- ノードに置かれた直線は、「そのノードの範囲のどこかで最小になる候補」です。
- $x$ での最小値は、**根から $x$ の葉までの道にあるノードの直線を全部見て、その最小** を取れば求まります（道の長さは $\log C$）。

### 5.1. 直線の追加

ノード（範囲 $[lo, hi)$、真ん中 $m$）にすでに直線 $g$ があるところへ、新しい直線 $f$ が来たとします。

1. **真ん中 $m$ で比べ、勝った（小さい）方をノードに残す**。負けた方を手元に持つ（以下これを $f$ と呼び直す）。
2. 手元の $f$ は $m$ で負けているので、4 節の性質から、$f$ が勝ちうるのは **交点がある側の半分だけ** です。
   - 左端 $lo$ での勝敗と、$m$ での勝敗が **違う** なら、交点は左半分 → 左の子へ $f$ を降ろす。
   - **同じ** なら、交点は右半分にあるかもしれない → 右端 $hi - 1$ でも $f$ が負けるなら、$f$ はこの範囲のどこでも勝てないので捨てる。勝つなら右の子へ降ろす。
3. 降ろした先の子でも同じことを繰り返す。子にまだ直線がなければ、そこに置いて終わり。

1 本の直線は根から 1 本の道を降りるだけなので、$O(\log C)$ です。

### 5.2. 例で追う

$x$ の範囲を $[0, 8)$ とします。根の真ん中は 4、左の子 $[0, 4)$ の真ん中は 2 です。

**手順 1：$y = -x + 6$ を追加**

根に何もないので置きます。

```
根 [0,8): y = -x + 6
```

**手順 2：$y = x$ を追加**

根で比べます。

| 比べる $x$ | 新しい $f$ ($y = x$) | 根の $g$ ($y = -x+6$) | 勝ち |
| --- | --- | --- | --- |
| 真ん中 4 | 4 | 2 | $g$ |
| 左端 0 | 0 | 6 | $f$ |

真ん中では $g$ の勝ちなので根は $g$ のまま。手元の $f$ は左端では勝ち・真ん中では負けで **違う** ので、交点は左半分 → 左の子 $[0, 4)$ へ。子がないので置きます。

```
根 [0,8): y = -x + 6
  └ 左 [0,4): y = x
```

**手順 3：$y = 2$ を追加**

根で比べます。

| 比べる $x$ | $f$ ($y = 2$) | $g$ ($y = -x+6$) | 勝ち |
| --- | --- | --- | --- |
| 真ん中 4 | 2 | 2 | 同点（$f$ は「勝っていない」） |
| 左端 0 | 2 | 6 | $f$ |

左端で勝ち・真ん中で勝っていないので違う → 左の子 $[0, 4)$ へ。

左の子で比べます。

| 比べる $x$ | $f$ ($y = 2$) | $g$ ($y = x$) | 勝ち |
| --- | --- | --- | --- |
| 真ん中 2 | 2 | 2 | 同点 |
| 左端 0 | 2 | 0 | $g$ |
| 右端 3 | 2 | 3 | $f$ |

左端・真ん中とも勝っていないので同じ → 右端を見ると勝つので右の子 $[2, 4)$ へ。子がないので置きます。

```
根 [0,8): y = -x + 6
  └ 左 [0,4): y = x
       └ 右 [2,4): y = 2
```

（この形は、ライブラリで実際に追加したときのノードの中身と一致します。）

### 5.3. 最小値の取得

**get(3)**：根 $[0,8)$ → 左 $[0,4)$ → 右 $[2,4)$ と降り、それぞれの直線の $x = 3$ での値 $3, 3, 2$ の最小 **2** が答えです。3 本の直線の $x = 3$ での値は $3, 3, 2$ なので正しいです。

**get(5)**：根だけ（右の子はない）。$-5 + 6 = $ **1**。3 本の値は $1, 5, 2$ なので正しいです。$y = 2$ は $[2, 4)$ にしか置かれていませんが、$x = 5$ では根の $y = -x + 6$ に負けることが根で確かめられているので、見なくてよいのです。

## 6. 線分の追加

線分 $[l, r)$ は、セグメント木の区間クエリと同じように $[l, r)$ を $O(\log C)$ 個のノードの範囲に分け、**それぞれのノードで直線として** 5.1 の追加をします。1 つのノードの範囲の中では線分は直線と同じだからです。各ノードで $O(\log C)$ かかるので、全体 $O(\log^2 C)$ です。

例：範囲 $[0, 8)$ に線分 $y = 1\ (x \in [1, 6))$ を追加すると、$[1, 6) = [1, 2) \cup [2, 4) \cup [4, 6)$ の 3 つのノードに $y = 1$ が置かれます。

```
根 [0,8): なし
  ├ [0,4): なし
  │   ├ [0,2): なし
  │   │   └ [1,2): y = 1
  │   └ [2,4): y = 1
  └ [4,8): なし
      └ [4,6): y = 1
```

## 7. 2 つの実装：動的版と座標指定版

### 7.1. 動的版（遅い方）

$x$ の範囲が $[-10^9, 10^9]$ のように広いと、全ノードを最初に作ることはできません。そこで **必要になったノードだけ作る**（動的セグメント木と同じ）のが `DynamicLiChaoTree` です。直線の追加では新しいノードは高々 1 個ですが、線分の追加では 6 節の例のように、**途中の道のノードも全部作る** 必要があります。上の例では線分 1 本で 7 個のノードができました。$x$ の範囲が $2 \times 10^9$ だと、1 本で最大 100 個程度のノードを作ることになります。

問題 2 を動的版で解くと、手元で 0.9 秒・メモリ 400 MB かかりました。

### 7.2. 座標指定版（速い方）

最小値を聞かれる $x$ が **先に全部分かる** なら（入力を全部読んでから処理してよいなら）、それらの $x$ だけを葉にした完全二分木を **配列で** 持てばよく、ノードを作る必要がありません（`LiChaoTree`）。

- 聞かれる $x$ をソートして重複を除いたものを $xs_0 < xs_1 < \cdots$ とし、葉 $i$ が $xs_i$ を担当します。
- ノードの「真ん中」「左端」「右端」は、葉の番号ではなく **対応する $xs$ の値** で比べます。2 直線が 1 回しか交わらないことは、$x$ が飛び飛びでも同じなので、5.1 の議論はそのまま成り立ちます。
- 線分 $[l, r)$ は、二分探索で「$xs_i \in [l, r)$ となる番号 $i$ の範囲」に直してから、配列のセグメント木と同じ要領で分けます。

問題 2 を座標指定版で解くと、手元で 0.15 秒・メモリ 24 MB になりました（約 6 倍速い）。ただし「途中の答えを見てから次の入力が決まる」ような、先読みできない問題では使えないので、そのときは動的版を使います。

### 7.3. 実装

追加の核心部分です（`better(a, b)` は「$a$ の方が良い（最小値版なら $a < b$）」）。

```cpp
// ノード v (範囲 [lo, hi)) に直線 f を入れる (座標指定版)
void insert(int v, int lo, int hi, Line f) {
    while (true) {
        Line &g = d[v];
        int m = (lo + hi) >> 1;
        bool bl = better(f(xs[lo]), g(xs[lo])), bm = better(f(xs[m]), g(xs[m]));
        if (bm) swap(f, g);                     // 真ん中で勝った方をノードに残す
        if (hi - lo == 1) return;
        if (bl != bm) v = 2 * v, hi = m;        // 交点は左半分
        else if (better(f(xs[hi - 1]), g(xs[hi - 1]))) v = 2 * v + 1, lo = m;  // 右半分で勝ちうる
        else return;                            // どこでも勝てない
    }
}
```

## 8. 正しさ

**主張**：$x$ での真の最小値を与える直線 $f^*$ は、捨てられていなければ $x$ の道の上のどこかのノードに置かれている。捨てられたり別の側に降ろされたりした場合は、$x$ でそれ以上に良い直線が道の上にある。

直線が子に降ろされるのは、5.1 の手順 2 で「その直線が勝ちうるのは降ろした側の半分だけ」と分かったときだけです。したがって、降ろされなかった側の $x$ では、その直線はノードに残った直線に負けています。捨てられる場合も同様です。よって、道の上の直線の最小値が真の最小値です。

## 10. まとめ

- 2 直線は 1 回しか交わらないので、真ん中で負けた直線が勝ちうるのは片側の半分だけ。これで各ノードに直線 1 本を置くセグメント木が作れる。
- 最小値は根から葉までの道の直線を全部見ればよい。
- 線分は区間を $O(\log C)$ 個のノードに分けて、各ノードで直線として入れる。
- 問い合わせる $x$ が先に分かるなら、配列で持つ座標指定版の方がずっと速い。
