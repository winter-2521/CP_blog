#データ構造 #平衡二分木 #ならし計算量

ライブラリ：[dynamic_sequence.hpp](https://github.com/winter-2521/cp-library/blob/main/data_structure/dynamic_sequence.hpp)

## 1. 概要

本記事では、**列** に対して

- 任意の位置への挿入・任意の位置の削除
- 区間 $[l, r)$ の **反転**
- 区間への作用（区間加算、区間 1 次関数など）と区間の積（区間和など）

をならし $O(\log n)$ で処理する方法として、**Splay 木** を使った実装を解説します。遅延セグメント木は長さが変わらない列しか扱えず、反転もできません。それを平衡二分木でできるようにしたものです。

>[!問題] 問題 1：Range Reverse Range Sum（Library Checker）
>長さ $N$ の数列に「$[l, r)$ を反転」「$[l, r)$ の和を出力」を $Q$ 回処理してください。（$N, Q \le 2 \times 10^5$）

>[!問題] 問題 2：Dynamic Sequence Range Affine Range Sum（Library Checker）
>数列に「位置 $i$ に $x$ を挿入」「位置 $i$ を削除」「$[l, r)$ を反転」「$[l, r)$ の各要素を $b a_i + c$ に」「$[l, r)$ の和 mod 998244353」を $Q$ 回処理してください。（$N, Q \le 5 \times 10^5$）

## 2. 前提知識

- 二分探索木と、その **通りがけ順**（左の子 → 自分 → 右の子の順に並べること）
- 遅延評価（遅延セグメント木で「まだ子に伝えていない操作」を持つこと）：[[遅延セグ木まとめ]]

## 3. 素朴な方法

列を配列で持つと、挿入・削除は要素をずらすので $O(n)$、反転も $O(r - l)$ です。$N, Q = 5 \times 10^5$ では最悪 $2.5 \times 10^{11}$ 回の操作になり、間に合いません。

## 4. 列を二分木で持つ

### 4.1. 位置を通りがけ順で表す

二分木の **通りがけ順が列の順番になるように** 要素を並べます。例えば列 $[a, b, c, d, e]$ は、次のような木で表せます。

```
        c
      /   \
     a     e
      \   /
       b d
```

通りがけ順に読むと $a, b, c, d, e$ です。木の形は 1 通りではなく、通りがけ順さえ合っていれば何でもよいことに注意してください。

### 4.2. $k$ 番目の要素を探す

各ノードに **部分木のノード数 `sz`** を持たせておけば、列の $k$ 番目（0-indexed）は根から次のように降りて見つかります。

- 左の子の `sz` が $k$ より大きい → 左の子へ
- ちょうど $k$ → 自分が答え
- 小さい → $k$ から（左の子の `sz` + 1）を引いて右の子へ

値ではなく「左に何個あるか」が位置を表しているので、挿入や削除で他の要素の位置が自動的にずれます（キーを書き換える必要がありません）。

### 4.3. 区間が 1 つの部分木になっていれば

区間 $[l, r)$ の要素が、ちょうど **ある 1 つの部分木** にまとまっていれば、

- 区間の和：その部分木の根に「部分木全体の和 `sum`」を持たせておけば $O(1)$
- 区間の反転：部分木の **全ノードで左右の子を入れ替える** と通りがけ順が逆になる。全部やると遅いので、根に「反転予定」の印を付け、子に降りるときに 1 段ずつ伝える（遅延評価）
- 区間への作用：同じく根に作用を載せて遅延させる

とできます。問題は次の 2 つです。

1. 木が偏ると深さが $O(n)$ になり、$k$ 番目を探すのも遅くなる。
2. 「区間がちょうど 1 つの部分木になる」ように、どうやって木の形を変えるか。

Splay 木は、**回転** と **splay 操作** でこの 2 つを同時に解決します。

## 5. 回転

ノード $x$ とその親 $y$ について、**通りがけ順を保ったまま** $x$ を $y$ の位置に持ち上げる操作を回転と呼びます。$x$ が $y$ の左の子のとき：

```
        y                x
       / \              / \
      x   C    →       A   y
     / \                  / \
    A   B                B   C
```

$x$ の右の子だった $B$ が、$y$ の左の子に付け替わります。通りがけ順はどちらも $A, x, B, y, C$ で変わりません。$x$ が右の子のときは左右対称です。

回転で子が変わるのは $x$ と $y$ だけなので、回転の後は $y$、$x$ の順に `sz` と `sum` を子から計算し直せば十分です。

## 6. Splay 操作

**splay(x)** は、回転を繰り返して $x$ を根まで持ち上げる操作です。$x$ の親を $y$、祖父を $z$ として、$x$ が根になるまで次を繰り返します。

| 名前 | 状況 | 操作 |
| --- | --- | --- |
| zig | $y$ が根（祖父がいない） | $x$ を 1 回回転 |
| zig-zig | $x$ と $y$ が **同じ向き**（どちらも左の子、またはどちらも右の子） | **先に $y$ を回転**、次に $x$ を回転 |
| zig-zag | 向きが違う | $x$ を 2 回回転 |

zig-zig で「先に親 $y$ を回す」のが Splay 木の肝です。これが計算量を保証します（8 節）。

## 7. 区間の取り出しと反転

### 7.1. 番兵

列の **両端に番兵** L, R（値は単位元）を置きます。これで「区間の 1 つ左」「1 つ右」の要素が必ず存在します。番兵込みの列では、元の列の $i$ 番目は $i + 1$ 番目になります。

### 7.2. 区間 $[l, r)$ を 1 つの部分木にする手順

1. 元の列の $l - 1$ 番目（番兵込みで $l$ 番目）のノード $A$ を探し、**根まで splay** する。
2. 元の列の $r$ 番目（番兵込みで $r + 1$ 番目）のノード $B$ を探し、**根の右の子になるまで splay** する（祖父が根になったら止める）。
3. すると、$A$ より右かつ $B$ より左の要素、つまり元の列の $[l, r)$ が、**ちょうど $B$ の左の子の部分木** になる。

ノードを探すときは、根から `sz` を見て降りながら、**通るノードの印を子に伝えます（push）**。

- `rev` が付いていたら：各子の左右の子を入れ替え（`sum` と `rsum` も入れ替え）、子に `rev` を付け、自分の `rev` を消す。
- 作用 `lz` があれば：各子に作用させ、自分の `lz` を消す。

### 7.3. 持っているもの

| 名前 | 意味 |
| --- | --- |
| `ch[0]`, `ch[1]`, `p` | 左の子・右の子・親 |
| `sz` | 部分木のノード数 |
| `val` | このノードの値 |
| `sum` | 部分木の値を通りがけ順に掛けたもの |
| `rsum` | 逆順に掛けたもの（積が非可換で、反転するときだけ必要） |
| `rev` | 反転の印：「自分の左右の子はもう入れ替えた。子の部分木の **中** はまだ」 |
| `lz` | 子にまだ伝えていない作用 |

### 7.4. 例で追う：reverse(1, 4)

列 $[a, b, c, d, e]$ を考えます。値は文字、積は **文字列の連結** にします（反転で順番が変わったことが見えるように）。番兵込みで 7 ノードを、最初はバランスよく組みます。

```
              c (sum="abcde")
            /                \
     a (sum="ab")          e (sum="de")
      /      \               /      \
     L        b             d        R
```

reverse(1, 4) は、元の列の $[1, 4)$ ＝ $b, c, d$ を反転して $[a, d, c, b, e]$ にする操作です。

**手順 1**：元の列の 0 番目＝番兵込み 1 番目＝ $a$ を根まで splay します。$a$ の親 $c$ が根なので zig（1 回回転）です。

```
       a (sum="abcde")
      / \
     L   c (sum="bcde")
        / \
       b   e (sum="de")
          / \
         d   R
```

$a$ の右の子だった $b$ が、$c$ の左の子に付け替わりました。

**手順 2**：元の列の 4 番目＝番兵込み 5 番目＝ $e$ を、根 $a$ の右の子になるまで splay します。$e$ の親 $c$ の親がちょうど根 $a$ なので、$e$ を 1 回回転して止めます。

```
       a (sum="abcde")
      / \
     L   e (sum="bcde")
        / \
       c   R
      / \
     b   d          ← c の部分木 = {b, c, d} = 元の列の [1, 4)
```

**手順 3**：$c$ の部分木を反転します。$c$ の左右の子を入れ替え、`sum` と `rsum` を入れ替え（"bcd" と "dcb"）、`rev` を付けます。

```
       a (sum="adcbe")
      / \
     L   e (sum="dcbe")
        / \
       c   R
  (sum="dcb", rev)
      / \
     d   b
```

最後に $e$、$a$ の `sum` を子から計算し直します。通りがけ順は L, a, d, c, b, e, R で、確かに反転できています。$c$ の子 $d$, $b$ の中（さらにその子）の入れ替えはまだしていません。次にそこを通るときの push で行います。

（以上の木の形と `sum` は、ライブラリで実際に実行して出力したものと一致します。）

### 7.5. 挿入と削除

- **insert(i, x)**：空の区間 $[i, i)$ を 7.2 の方法で取り出すと、$B$ の左の子が空になっています。そこに新しいノードを付け、$B$、$A$ の `sz`・`sum` を計算し直します。
- **erase(i)**：区間 $[i, i+1)$ を取り出すと、$B$ の左の子が削除するノード 1 個だけになるので、切り離します。

### 7.6. 実装

区間を取り出す部分と反転の部分です。

```cpp
// [l, r) が「根の右の子の左の子」の部分木になるようにして，根の右の子を返す
int range(int l, int r) {
    int a = kth(l);          // 番兵込みで l 番目 (= 元の列の l-1 番目)．降りながら push する
    splay(a, 0);             // 根まで
    int b = kth(r + 1);      // 番兵込みで r+1 番目 (= 元の列の r 番目)
    splay(b, a);             // a の子になるまで
    return b;
}

void reverse(int l, int r) {
    if (r - l <= 1) return;
    int rr = range(l, r);
    toggle(d[rr].ch[0]);     // 左右の子を入れ替えて rev の印を付ける
    update(rr), update(root);
}

void toggle(int t) {
    swap(d[t].ch[0], d[t].ch[1]);
    if constexpr (!COMMUTATIVE) swap(d[t].sum, d[t].rsum);
    d[t].rev ^= 1;
}
```

和のように **可換な** 積なら、反転しても部分木の積は変わらないので `rsum` は要りません。ライブラリではテンプレート引数 `COMMUTATIVE = true`（デフォルト）のとき `rsum` を持たず、少し速くしています。

## 8. 計算量

### 8.1. 遅い方法：単回転だけで根に上げる

「$x$ を根に持ってくる」だけなら、zig-zig の場合も $x$ を 2 回回転すればよさそうに見えます（親を先に回さない）。しかしこれは遅くなります。

1 から 7 が左の子に一本道で連なった木（深さ 7）で、一番下の 1 を根に上げてみます（実際にシミュレーションした結果）。

```
単回転だけ               Splay（zig-zig で親を先に回す）
1                        1
 \                        \
  7                        6
 /                        / \
6                        4   7
/                       / \
5                      2   5
/                       \
4                        3
/
3
/
2
（深さ 7 のまま）         （深さ 5）
```

単回転だけだと、2〜7 は一本道のまま残ります。続けて次に深い 2 を探すとまた深さ 7 近くあり、これを繰り返すと毎回 $O(n)$、全体 $O(n^2)$ になります。

Splay では、2〜7 の部分が「2 つおきに枝分かれした形」に折りたたまれています。長さ $n$ の一本道なら、深さはおよそ半分になります。この「**アクセスした道がおよそ半分に縮む**」性質のおかげで、ならし $O(\log n)$ になります。

### 8.2. ならし計算量の証明（概略）

ノード $v$ の部分木の大きさを $s(v)$ とし、ポテンシャルを $\Phi = \sum_v \log_2 s(v)$ とします。

**アクセス補題**：根が $t$ の木でノード $x$ を splay するとき、「回転の回数 + $\Phi$ の増加」は $3(\log_2 s(t) - \log_2 s(x)) + 1 \le 3 \log_2 n + 1$ 以下。

証明の要点は、zig-zig・zig-zag 1 回分（2 回の回転）の「回転の回数 + $\Phi$ の増加」が $3(\log s'(x) - \log s(x))$ 以下になることです（$s'$ は回転後）。zig-zig では、回転後の $x$ の部分木が元の祖父 $z$ の部分木全体になり、回転前の $x$ の部分木と回転後の $z$ の部分木が互いに重ならないので、$\log$ の性質 $\log a + \log b \le 2 \log \frac{a + b}{2}$ から「2」が出てきて、回転 2 回分のコストを払えます。単回転だけの方法ではこの不等式が使えず、8.1 の例のように払えません。

これを足し合わせると splay 1 回はならし $O(\log n)$ で、挿入・削除・区間操作はどれも splay 2 回 + $O(1)$ なので、ならし $O(\log n)$ です。

## 9. 正しさ

- **回転**：通りがけ順を変えないので、列は変わりません。
- **反転の印**：「部分木の全ノードで左右を入れ替える」は、上から 1 段ずつ行ってもまとめて行っても結果は同じです。ノードに降りる前に必ず push するので、降りた先のノードはいつも正しい向きになっています。
- **作用**：遅延セグメント木と同じです。作用が積と可換（`mapping(f, op(a, b)) = op(mapping(f, a), mapping(f, b))`）なら、部分木の `sum` に直接作用させてよいです。

## 11. まとめ

- 列を「通りがけ順が列の順番」になる二分木で持ち、部分木の大きさで位置を表す。
- 区間 $[l, r)$ は「$l-1$ 番目を根に、$r$ 番目を根の右の子に splay」すると 1 つの部分木になり、その根に反転・作用を遅延で載せられる。
- zig-zig で親を先に回すことで、アクセスした道が半分に縮み、ならし $O(\log n)$ になる。
