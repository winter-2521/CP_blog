#データ構造 #平衡二分木 #ならし計算量

ライブラリ：[dynamic_sequence.hpp](https://github.com/winter-2521/cp-library/blob/main/data_structure/dynamic_sequence.hpp)

## 何ができるアルゴリズムか？

**列** に対して、次の操作をならし $O(\log n)$ で処理する。

- 任意の位置への挿入・任意の位置の削除
- 区間 $[l, r)$ の **反転**
- 区間への作用（区間加算・区間 1 次関数など、遅延セグ木に乗るもの）
- 区間の積（区間和など）

遅延セグ木は「長さが変わらない列」しか扱えず、反転もできない。それを平衡二分木（ここでは **Splay 木**）でできるようにしたもの。

>[!問題] Range Reverse Range Sum (Library Checker)
>長さ $N$ の数列に「$[l, r)$ を反転」「$[l, r)$ の和」を $Q$ 回処理せよ。$N, Q \le 2 \times 10^5$

>[!問題] Dynamic Sequence Range Affine Range Sum (Library Checker)
>数列に「位置 $i$ に挿入」「位置 $i$ を削除」「$[l, r)$ を反転」「$[l, r)$ の各要素を $b a_i + c$ に」「$[l, r)$ の和 mod 998244353」を $Q$ 回処理せよ。$N, Q \le 5 \times 10^5$

## 計算量

各操作ならし $O(\log n)$（$n$ はそのときの列の長さ）。

## 具体例で理解する

### まず遅い方法

列を配列で持つと、挿入・削除・反転はどれも $O(n)$（要素をずらす・入れ替える）。$N, Q = 5 \times 10^5$ だと $2.5 \times 10^{11}$ 回で間に合わない。

### アイデア 1：列を「位置がキーの二分探索木」で持つ

二分木の **通りがけ順（左の子 → 自分 → 右の子）** が列の順番になるように要素を並べる。各ノードに **部分木のノード数 `sz`** を持たせておけば、「列の $k$ 番目」は根から

- 左の子の `sz` が $k$ より大きい → 左へ
- ちょうど $k$ → 自分
- 小さい → $k$ から（左の `sz` + 1）を引いて右へ

と降りれば見つかる。値そのものではなく「左に何個あるか」が位置になっているので、挿入・削除で他の要素の位置が自動的にずれる（キーを書き換えなくてよい）。

さらに、**列の区間 $[l, r)$ がちょうど 1 つの部分木になっている** なら、

- 区間の和：その部分木の根に「部分木全体の和 `sum`」を持たせておけば $O(1)$。
- 区間の反転：部分木の **全てのノードで左右の子を入れ替える** と通りがけ順が逆になる。全部やると遅いので、根に「反転予定」の印を付けておき、後で子に降りるときに 1 段ずつ伝える（遅延セグ木の遅延評価と同じ）。
- 区間への作用：同じく根に作用を載せて遅延させる。

問題は 2 つ。木が偏ると深さが $O(n)$ になって遅いことと、「区間がちょうど 1 つの部分木になる」ようにどうやって木の形を変えるか。Splay 木は **回転** と **splay 操作** で両方を解決する。

### 持っているもの

各ノードが持つもの：

| 名前 | 意味 |
| --- | --- |
| `ch[0]`, `ch[1]`, `p` | 左の子・右の子・親（なければ 0） |
| `sz` | 部分木のノード数 |
| `val` | このノードの値 |
| `sum` | 部分木の値を通りがけ順に掛けたもの（区間和なら和） |
| `rsum` | 逆順に掛けたもの（積が非可換で反転するときだけ必要） |
| `rev` | 反転の印：「自分の左右の子はもう入れ替えた。**子の部分木の中はまだ**」 |
| `lz` | 子にまだ伝えていない作用 |

さらに列の **両端に番兵** L, R（値は単位元）を置く。これで「区間の 1 つ左」「1 つ右」が必ず存在する。

例：列 $[a, b, c, d, e]$。値は文字、積は **文字列の連結** にする（反転で順番が変わったことが目で見える）。番兵込みで 7 ノード、作った直後はバランスよく組む：

```
            c (sz=7, sum="abcde")
          /                    \
    a (sz=3, sum="ab")      e (sz=3, sum="de")
     /        \               /        \
   L          b              d          R
```

通りがけ順は L, a, b, c, d, e, R ＝ 番兵の間に元の列が並んでいる。

### 回転

ノード $x$ とその親 $y$ について、**通りがけ順を保ったまま** $x$ を $y$ の位置に上げる操作。$x$ が $y$ の左の子のとき：

```
        y                x
       / \              / \
      x   C    →       A   y
     / \                  / \
    A   B                B   C
```

$x$ の右の子 $B$ が $y$ の左の子に付け替わる。通りがけ順はどちらも A, x, B, y, C。回転のあと、$y$ の `sz`・`sum` を子から計算し直す（$x$ は最後にまとめて直す）。

### splay(x)：x を根まで持ち上げる

$x$ が根になるまで、$x$ の親 $y$、祖父 $z$ の形によって次をする。

- **zig**：$y$ が根（祖父がいない）→ $x$ を 1 回回転。
- **zig-zig**：$x$ と $y$ が **同じ向き**（どちらも左の子、またはどちらも右の子）→ **先に $y$ を回転**、次に $x$ を回転。
- **zig-zag**：向きが違う → $x$ を 2 回回転。

zig-zig で「先に親を回す」のが Splay 木の肝（後で説明）。

### 区間 $[l, r)$ を 1 つの部分木にする

1. 列の $l - 1$ 番目（番兵込みでは $l$ 番目）のノード $A$ を探して **根まで splay**。
2. 列の $r$ 番目（番兵込みでは $r + 1$ 番目）のノード $B$ を探して、**根の右の子になるまで splay**（祖父が根になったら止める）。
3. すると、$A$ より右・$B$ より左の要素 ＝ 列の $[l, r)$ が、**ちょうど $B$ の左の子の部分木** になる。

ノードを探すときは根から `sz` を見て降り、**通るノードで印を子に伝える（push）**：

- `rev` が付いていたら、各子の左右を入れ替えて（`sum` と `rsum` も入れ替えて）子に `rev` を付け、自分の `rev` を消す。
- `lz` があれば各子に作用させ、自分の `lz` を消す。

### 例で追う：reverse(1, 4)（$[a, b, c, d, e] \to [a, d, c, b, e]$）

**手順 1**：列の 0 番目 = 番兵込み 1 番目 = $a$ を根まで splay。$a$ の親 $c$ は根なので zig（1 回回転）。

```
      a (sum="abcde")
     / \
    L   c (sum="bcde")
       / \
      b   e (sum="de")
         / \
        d   R
```

（$a$ の右の子だった $b$ が $c$ の左の子に付け替わった。）

**手順 2**：列の 4 番目 = 番兵込み 5 番目 = $e$ を、根 $a$ の右の子になるまで splay。$e$ の親 $c$ の親が根 $a$ なので、$e$ を 1 回回転して止める。

```
      a (sum="abcde")
     / \
    L   e (sum="bcde")
       / \
      c   R
     / \
    b   d       ← c の部分木 = {b, c, d} = 列の [1, 4)
```

**手順 3**：$c$ の部分木を反転：$c$ の左右の子を入れ替え、`sum` と `rsum` を入れ替え（"bcd" ↔ "dcb"）、`rev` を付ける。

```
      a (sum="adcbe")
     / \
    L   e (sum="dcbe")
       / \
      c   R
   (sum="dcb", rev)
     / \
    d   b
```

最後に $e$、$a$ の `sum` を子から計算し直す。通りがけ順は L, a, d, c, b, e, R で、確かに反転できている。$c$ の子 $d$, $b$ の中身（さらにその子）の入れ替えはまだしていない — 次にそこを通るときの push で行う（$d$, $b$ は子がないので実質何もしない）。

**挿入 insert(i, x)**：区間 $[i, i)$（空の区間）を上の方法で取り出すと、$B$ の左の子が空になっているので、そこに新しいノードを付けて $B$、$A$ の `sz`・`sum` を直す。
**削除 erase(i)**：区間 $[i, i+1)$ を取り出すと $B$ の左の子が削除するノード 1 個だけになるので、切り離す。

### 遅い方法 2：単回転だけで根に上げる

「$x$ を根に持ってくる」だけなら、zig-zig でも $x$ を 2 回回転すればよさそうに見える（親を先に回さない）。しかしこれだと遅い。

列 $1, 2, \ldots, n$ が「全て左の子に連なった一本道」になっているとき（深さ $n$）、一番下の $1$ を単回転だけで根に上げると、木は「根 $1$ の右に、$n, n-1, \ldots, 2$ が左に連なった一本道」になる。続けて次に深い $2$ を探しても、また深さ $n$ 近くある。これを繰り返すと毎回 $O(n)$ かかり、全体 $O(n^2)$。

zig-zig で親を先に回すと、一本道を上るたびに **道の長さがおよそ半分に折りたたまれる**。$n = 7$ の左一本道で一番下の $1$ を splay すると：

```
単回転だけ:               Splay (zig-zig):
1                          1
 \                          \
  7                          6
 /                          / \
6                          4   7
/                         / \
5                        2   5
...                       \
(深さ 7 のまま)             3
```

単回転だけだと深さ 7 のまま（2〜7 が一本道で残る）だが、Splay では深さ 5 になり、2〜7 の部分が「2 つおきに枝分かれした形」に折りたたまれている。一本道が長いほど効果は大きく、長さ $n$ の一本道は深さ約 $n/2$ になる。この「アクセスした道が半分に縮む」性質のおかげで、ならし $O(\log n)$ になる。

## 証明・仕組み

### ならし計算量（概略）

ノード $v$ の部分木の大きさを $s(v)$ とし、ポテンシャルを $\Phi = \sum_v \log_2 s(v)$ とする。

**アクセス補題**：根が $t$ の木でノード $x$ を splay するときの「回転の回数 + $\Phi$ の増加」は $3(\log s(t) - \log s(x)) + 1 \le 3 \log n + 1$。

証明の要点は、zig-zig・zig-zag 1 回ぶん（2 回転）のならしコストが $3(\log s'(x) - \log s(x))$ 以下になること。zig-zig では回転後の $x$ が元の祖父 $z$ の部分木全体を持ち、元の $x$ の部分木と回転後の $z$ の部分木が互いに重ならないので、$\log$ の凹性 $\log a + \log b \le 2 \log \frac{a+b}{2}$ から 2 が出てきて、回転の実コスト 2 を払える。単回転だけの方法ではこの不等式が使えず、上の一本道の例のように払えない。

これを足し合わせると、1 回の splay はならし $O(\log n)$。挿入・削除・区間操作はどれも splay 2 回 + $O(1)$ なのでならし $O(\log n)$。

### 遅延評価が正しい理由

- 反転の印：「部分木の全ノードで左右を入れ替える」は、上から 1 段ずつ行っても、まとめて行っても同じ結果。ノードに降りる前に必ず push するので、降りた先のノードはいつも正しい向き。
- 作用：遅延セグ木と同じ。作用が積と可換（`mapping(f, op(a, b)) = op(mapping(f, a), mapping(f, b))`）なら部分木の `sum` に直接作用させられる。
- 非可換な積で反転するときは、部分木を逆順に読んだ積 `rsum` が必要（反転したら `sum` と `rsum` を入れ替える）。和のように可換な積なら要らないので、ライブラリでは `COMMUTATIVE = true`（デフォルト）なら `rsum` を持たずに少し速くしている。

### 回転で `sz`・`sum` が正しく保たれる理由

回転で子が変わるのは $x$ と $y$ の 2 ノードだけで、他のノードの部分木（の集合）は変わらない。なので $y$、$x$ の順に子から計算し直せばよい。
