#データ構造 #セグ木 #区間をsetで管理

ライブラリ：[range_assign_segment_tree.hpp](https://github.com/winter-2521/cp-library/blob/main/data_structure/range_assign_segment_tree.hpp)

## 何ができるアルゴリズムか？

**任意のモノイド**（非可換でもよい）の列に対して、区間代入と区間積を処理する。遅延セグ木と違い、作用付きモノイドを考えなくてよい。

>[!問題] Range Set Range Composite (Library Checker)
>1 次関数の列に対して、`0 l r c d`：$i \in [l, r)$ について $f_i \gets cx + d$、`1 l r x`：$f_{r-1}(\cdots f_l(x))$。$N, Q \le 5 \times 10^5$

## 計算量

区間代入・区間積とも、ならし $O(\log n)$ 回の `op`（セグ木の更新 + 冪の計算）。

## 証明・仕組み

### 遅延セグ木で解こうとすると

区間代入を作用にすると、長さ $L$ のノードに「全て $x$」を作用させた値は $x^L$。1 次関数の合成なら $x^L$ は $O(\log L)$ 回の合成で計算できるが、push のたびにこれをやると重い（あるいは作用に冪を持たせる工夫が要る）。

### 値が等しい連続部分（ラン）でまとめる

列を「値が等しい連続部分」に分けて持つ（いわゆる **区間を set で管理する** テク、Chtholly Tree / ODT）。

- ランの先頭位置の集合を [[64分木（FastSet）]] で持ち、各先頭 $s$ にそのランの値 $v_s$ を持つ。
- セグ木の位置 $s$（ランの先頭）に $v_s^{(\text{ランの長さ})}$、それ以外の位置に単位元 $e$ を置く。

すると、ランの境界で切れている区間 $[l, r)$ の積は、セグ木の `prod(l, r)` そのもの（単位元は無視され、各ランの $v^{\text{長さ}}$ が順に掛かる）。

**区間代入** $[l, r) \gets x$：

1. 位置 $l$ と $r$ でランを切る（ランを 2 つに分け、セグ木の 2 か所を更新）。
2. $[l, r)$ の内側にあるランの先頭を全て消す（セグ木のその位置を $e$ に）。
3. $l$ を値 $x$、長さ $r - l$ のランにする（セグ木の位置 $l$ に $x^{r-l}$）。

**区間積** $[l, r)$：両端のランからはみ出す端数は $v^k$ を直接計算し、間はセグ木の区間積。ランを切らないので状態は変わらない。

### ならし計算量

1 回の代入で新しくできるランは高々 3 個（切った 2 つ + 代入したもの）。ランは作られた後に 1 回しか消えないので、手順 2 で消すランの総数は $O(n + q)$。消すごとにセグ木の更新 $O(\log n)$ なので全体でならし $O((n + q) \log n)$。

冪 $x^k$ は繰り返し二乗法で $O(\log k)$ 回の `op`。

## 例題・類題

- [Range Set Range Composite (Library Checker)](https://judge.yosupo.jp/problem/range_set_range_composite)
- [Codeforces 896C - Willem, Chtholly and Seniorious](https://codeforces.com/contest/896/problem/C)：区間をsetで管理するテク（ODT）の元ネタ。ランダムな区間代入があるとランの数が少なく保たれる。
- 「区間を塗る」「区間の色を全部同じにする」操作がある問題全般。各ランに対して何かを集計する（色ごとの個数を BIT で持つ、など）。
