## 何ができるアルゴリズムか？

区間への作用（区間加算・区間代入・区間 1 次関数など）と区間積（和・min・max など）を、どちらも $O(\log n)$ で処理する。

>[!問題] Range Affine Range Sum (Library Checker)
>`0 l r b c`：$i \in [l, r)$ について $a_i \gets b a_i + c$、`1 l r`：$\sum_{i=l}^{r-1} a_i \bmod 998244353$。$N, Q \le 5 \times 10^5$

## 計算量

区間作用・区間積・一点更新・二分探索 (`max_right` / `min_left`) とも $O(\log n)$。

## 具体例で理解する

ここでは「普通のセグ木（一点更新・区間和）は分かる」という前提で、区間加算・区間和の遅延セグ木を例に、何を持ち、どう動くかを小さな例で追う。

### 普通のセグ木で区間加算をするとどうなるか

$a = [1, 2, 3, 4, 5, 6, 7, 8]$ の区間和のセグ木で「$[2, 6)$ の各要素に $+10$」をしたい。普通のセグ木には一点更新しかないので、$a_2, a_3, a_4, a_5$ を 1 つずつ更新すると合計 $O(\text{区間の長さ} \times \log n)$。区間が長いと 1 回で $O(n \log n)$ かかってしまう。

### 各ノードが持っているもの

| 名前 | 意味 |
| --- | --- |
| `sum` | 担当区間の和（ただし **祖先に残っている lazy は反映されていない**） |
| `len` | 担当区間の要素数 |
| `lazy` | 「担当区間の全要素に、あとで足す必要がある量」。まだ子に伝えていない |

はじめは全ノードの `lazy` = 0。

```
                    [0,8) sum=36
          [0,4) sum=10           [4,8) sum=26
     [0,2) sum=3  [2,4) sum=7   [4,6) sum=11  [6,8) sum=15
     1     2     3     4       5     6       7     8
```

### 3 つの基本操作

- **ノードに $+x$ を直接かける**：`sum` += $x$ × `len`、`lazy` += $x$。子には触らない。
- **push(v)**：v の `lazy` を 2 つの子に「直接かける」。その後 v の `lazy` = 0。
- **update(v)**：v の `sum` = 左の子の `sum` + 右の子の `sum`（普通のセグ木と同じ）。

### 区間加算 $[l, r)$ に $+x$ の手順

1. $[l, r)$ を普通のセグ木と同じく $O(\log n)$ 個のノードに分解する。
2. 分解に使うノードの **祖先を、根から順に push** しておく（理由は「よくある疑問」）。
3. 分解したノードそれぞれに $+x$ を直接かける。
4. 分解したノードの祖先を、**下から順に update** する。

### 区間和 $[l, r)$ の手順

1. 分解に使うノードの祖先を、根から順に push する。
2. 分解したノードの `sum` を足す。

### 例で追う

**操作 1：$[2, 6)$ に $+10$**

$[2, 6)$ はノード $[2,4)$ と $[4,6)$ に分解される。祖先（根・$[0,4)$・$[4,8)$）の `lazy` は 0 なので push しても何も起きない。

- $[2,4)$ に $+10$ を直接かける：`sum` = 7 + 10 × 2 = 27、`lazy` = 10。
- $[4,6)$ に $+10$ を直接かける：`sum` = 11 + 10 × 2 = 31、`lazy` = 10。
- 下から update：$[0,4)$ の `sum` = 3 + 27 = 30、$[4,8)$ = 31 + 15 = 46、根 = 30 + 46 = 76。

```
                    [0,8) sum=76
          [0,4) sum=30           [4,8) sum=46
     [0,2) sum=3  [2,4) sum=27   [4,6) sum=31  [6,8) sum=15
                  lazy=10        lazy=10
     1     2     3     4       5     6       7     8    ← 葉はまだ古い
```

実際の配列 $[1, 2, 13, 14, 15, 16, 7, 8]$ の和は 76 で、根と一致。触ったのは $O(\log n)$ 個のノードだけ。

**操作 2：$[3, 5)$ の和**（答えは $14 + 15 = 29$）

$[3, 5)$ は葉 $[3,4)$ と葉 $[4,5)$ に分解される。祖先を根から push する。

- 根・$[0,4)$・$[4,8)$：`lazy` = 0 なので何も起きない。
- $[2,4)$ を push：子の葉 $[2,3)$ に $+10$ → 13、葉 $[3,4)$ に $+10$ → 14。$[2,4)$ の `lazy` = 0。
- $[4,6)$ を push：葉 $[4,5)$ → 15、葉 $[5,6)$ → 16。

分解した葉の `sum` を足す：$14 + 15 = 29$。正しい。

### 作用が「加算」以外のとき：合成が必要

あるノードに `lazy`「$+10$」が残っているところに、さらに「$\times 2$」がかかったとする。子に伝えるときは「先に $+10$、次に $\times 2$」を 1 つにまとめた $x \mapsto 2(x + 10) = 2x + 20$ を伝えればよい。このように **作用を 1 つにまとめる操作（合成）** が必要。

1 次関数 $x \mapsto bx + c$ は何回重ねても 1 次関数（$x \mapsto b_2(b_1 x + c_1) + c_2 = (b_1 b_2) x + (b_2 c_1 + c_2)$）なので、`lazy` は $(b, c)$ の 2 数で持てる。ノードに直接かけるときは `sum` = `sum` × $b$ + $c$ × `len`。これが Range Affine Range Sum。

一般には、遅延セグ木に必要なのは次の 3 つ：

- ノードの値どうしをまとめる演算（update 用。和なら足し算）
- 作用をノードの値に直接かける方法（`sum` += $x$ × `len` など）
- 作用どうしの合成（`lazy` に新しい作用を重ねるため）

### 遅延セグ木に乗らない例

「区間の各要素を $\min(a_i, 5)$ にする」（chmin）と区間和を考える。ノード $[0,4)$ の `sum` が 10 だと分かっていても、chmin 後の和は分からない（$[1,2,3,4]$ なら 10 のまま、$[0,0,0,10]$ なら 5）。**ノードの値だけから、作用をかけた後の値が計算できない** ので乗らない。これを扱うのが [[Segment Tree Beats]]（ノードに最大値・2 番目の最大値なども持たせて、計算できる場合だけノードで止める）。

### よくある疑問

- **Q. 区間加算の前にも push するのはなぜ？** — 作用の順番を守るため。例えば「代入」の場合、上のノードに古い「$=7$」が残ったまま下のノードに新しい「$=2$」をかけると、あとで古い「$=7$」が push されて新しい値を上書きしてしまう。先に古い作用を下ろしておけば、新しい作用は必ず古い作用より「後」に積まれる。加算だけなら順番は関係ないが、汎用の実装では常に push する。
- **Q. 分解したノードより下の値は古いままで大丈夫？** — そのノードより下を見るときは必ず途中で push するので、見る時点では正しい値になっている。見ない限り古くても困らない、というのが「遅延」の考え方。

## 証明・仕組み

### 必要な構造（作用付きモノイド）

- 値のモノイド $(S, \cdot, e)$
- 作用の集合 $F$ と、合成 $f \circ g$（先に $g$、次に $f$）、恒等写像 $\mathrm{id}$（$F$ もモノイド）
- 作用 $\mathrm{mapping}(f, x)$ で、**積と可換**：$f(x \cdot y) = f(x) \cdot f(y)$

最後の条件が肝。これがあると「区間全体の積に作用させた結果」が「各要素に作用させてから積をとった結果」と一致するので、区間全体を表すノードの値に作用を直接適用できる。

### 遅延評価

各ノードに値と「まだ子に伝えていない作用」`lz` を持つ。

- 区間作用：区間を $O(\log n)$ 個のノードに分解し、各ノードの値に作用を適用、`lz` に合成する（子には伝えない）。
- そのノードより下を見る必要が出たら（区間の境界がノードの内側にあるとき）、`lz` を子 2 つに適用して空にする（push）。
- 区間作用・区間積の前に、境界の 2 本の経路を上から push する。作用後は境界の経路を下から更新する。

push は経路上だけなので $O(\log n)$。

### よく使う作用付きモノイドの例

| 用途 | 値 | 作用 | mapping |
| --- | --- | --- | --- |
| 区間加算・区間和 | (和, 長さ) | 加える値 $c$ | (和 $+ c \cdot$ 長さ, 長さ) |
| 区間 1 次関数・区間和 | (和, 長さ) | $(b, c)$ | (和 $\cdot b + c \cdot$ 長さ, 長さ) |
| 区間加算・区間 min | min | $c$ | min $+ c$ |
| 区間代入・区間和 | (和, 長さ) | 代入値（なし含む） | (値 $\cdot$ 長さ, 長さ) |

和を持つときに **長さも値に含める** のがポイント（作用の結果が長さに依存するため）。

### 「積と可換」にならない作用

区間 chmin・区間和のように、作用の結果が値の要約（和）だけからは決まらないものは乗らない。→ [[Segment Tree Beats]]
