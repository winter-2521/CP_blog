#データ構造 #区間クエリ #簡潔データ構造

ライブラリ：[wavelet_matrix.hpp](https://github.com/winter-2521/cp-library/blob/main/data_structure/wavelet_matrix.hpp)

## 何ができるアルゴリズムか？

**静的な** 数列に対して、次を $O(\log \sigma)$（$\sigma$ は値の種類数）で求める。

- 区間 $[l, r)$ の $k$ 番目に小さい値
- 区間内の $x$ 未満の値の個数（区間 × 値の範囲の長方形の点の個数）
- 区間内の $x$ 未満の最大値・$x$ 以上の最小値

>[!問題] Range Kth Smallest (Library Checker)
>長さ $N$ の数列に $Q$ 個のクエリ：$(a_l, \ldots, a_{r-1})$ のうち $k+1$ 番目に小さい値を出力せよ。$N, Q \le 2 \times 10^5$

## 計算量

構築 $O(n \log \sigma)$、各クエリ $O(\log \sigma)$。メモリは $n \log \sigma$ ビット + α。

## 具体例で理解する

### 値の上のビットから順にふるい分ける

$a = [5, 2, 7, 1, 3]$（3 bit で書ける）で考える。

| 値 | 5 | 2 | 7 | 1 | 3 |
| --- | --- | --- | --- | --- | --- |
| 2 進 | 101 | 010 | 111 | 001 | 011 |

**段 2（一番上のビット）**：各値の bit 2 を並べる → $B_2 = 1\,0\,1\,0\,0$。0 の個数 $z_2 = 3$。次の段のために「bit 2 が 0 のもの → 1 のもの」の順に、元の順番を保って並べ替える：

$$[2, 1, 3 \mid 5, 7]$$

**段 1**：上の列の bit 1 → $B_1 = 1\,0\,1\,0\,1$、$z_1 = 2$。並べ替え：$[1, 5 \mid 2, 3, 7]$

**段 0**：上の列の bit 0 → $B_0 = 1\,1\,0\,1\,1$。

記録するのは各段のビット列 $B_h$ と 0 の個数 $z_h$ だけ。

### 区間 $k$ 番目の例

$a_1, a_2, a_3 = [2, 7, 1]$（区間 $[1, 4)$）で 2 番目に小さい値（0-indexed で $k = 1$）を求める。答えは $\{1, 2, 7\}$ の 2 番目 = 2。

**段 2**：$B_2$ の区間 $[1, 4)$ は $0\,1\,0$。0（上のビットが 0、つまり小さい側）が 2 個。$k = 1 < 2$ なので答えは 0 の側にある → 答えの bit 2 は **0**。
次の段での位置：0 の側は列の先頭から詰めてあるので、区間 $[1, 4)$ の 0 たちは「位置 1 より前にある 0 の個数（$B_2[0] = 1$ なので 0 個）」から始まる → 次の区間は $[0, 2)$（中身は $[2, 1]$）。

**段 1**：$B_1$ の区間 $[0, 2)$ は $1\,0$。0 が 1 個。$k = 1 \ge 1$ なので答えは 1 の側 → 答えの bit 1 は **1**。$k = 1 - 1 = 0$。
1 の側は $z_1 = 2$ 番目から始まり、区間より前に 1 は 0 個 → 次の区間は $[2, 3)$（中身は $[2]$）。

**段 0**：$B_0$ の区間 $[2, 3)$ は $0$。0 が 1 個、$k = 0 < 1$ → 答えの bit 0 は **0**。

答えは $010_2 = 2$。各段で「区間内の 0 の個数」が分かればよく、それは「$[0, r)$ の 1 の個数 $-$ $[0, l)$ の 1 の個数」から求まる。ビット列の 1 の個数（rank）は前計算 + popcount で $O(1)$ なので、全体 $O(\text{ビット数})$。

（実際のライブラリでは値を座標圧縮してからこれを行うので、ビット数は値の種類数の $\log$。）

### 「$x$ 未満の個数」も同じ要領

上のビットから $x$ のビットと比べながら降りる。$x$ のビットが 1 の段で「0 の側に行った要素」は、その段より上のビットが $x$ と同じで、この段のビットが $x$ より小さいので、全部 $x$ 未満。それを数えて 1 の側に進む。

## 証明・仕組み

値を座標圧縮して $[0, 2^L)$ の整数にし、上のビットから順に処理する。

**構築**：段 $h = L-1, \ldots, 0$ について、現在の列の各値の第 $h$ ビットを並べたビット列 $B_h$ を記録し、列を「第 $h$ ビットが 0 のもの（順番を保って）→ 1 のもの」に並べ替えて次の段へ。$B_h$ の 0 の個数を $z_h$ とする。

**rank**：$B_h$ の $[0, i)$ の 1 の個数 $\mathrm{rank}_1(i)$ が $O(1)$ で求まるようにしておく（64 bit ごとに累積の個数を持ち、端数は popcount）。

**区間の移動**：段 $h$ で区間 $[l, r)$ にある要素は、次の段では

- ビット 0 のもの → $[l - \mathrm{rank}_1(l),\ r - \mathrm{rank}_1(r))$
- ビット 1 のもの → $[z_h + \mathrm{rank}_1(l),\ z_h + \mathrm{rank}_1(r))$

に（相対順序を保って）まとまっている。安定な並べ替えなので「$[l, r)$ にあった要素のうちビット 0 のもの」は次の段で連続し、その位置は $l$ より前にあるビット 0 の個数で決まる。

**$k$ 番目**：上のビットから、区間内のビット 0 の個数 $c$ を見て、$k < c$ なら答えのこのビットは 0（0 の側へ）、そうでなければ 1（$k \mathrel{-}= c$ して 1 の側へ）。各段 $O(1)$。

**$x$ 未満の個数**：$x$ のビットを上から見て、$x$ のビットが 1 の段では「ビット 0 の側に行った要素」は全て $x$ 未満なので数えて、1 の側へ進む。0 の段では 0 の側へ。

**前後の値**：$x$ 未満の個数 $c$ を求め、$c - 1$ 番目（$x$ 未満の最大値）や $c$ 番目（$x$ 以上の最小値）を $k$ 番目で求める。

### ウェーブレット木との違い

ウェーブレット木は値の範囲で二分木を作るが、ウェーブレット行列は各段を 1 本のビット列にまとめる（並べ替え方を工夫している）ので、ポインタが不要で実装もメモリも軽い。

## 例題・類題

- [Range Kth Smallest (Library Checker)](https://judge.yosupo.jp/problem/range_kth_smallest)
- [POJ 2104 - K-th Number](http://poj.org/problem?id=2104)：区間 $k$ 番目の古典。[[永続遅延セグメント木]]（永続セグ木）でも解ける。
- [ABC339 G - Smaller Sum](https://atcoder.jp/contests/abc339/tasks/abc339_g)：強制オンラインで「区間内の $x$ 以下の値の和」。各段に「ビット 0 の側に行った値の累積和」を持たせれば同じ要領で和も求まる。
- 区間内の値の個数（区間 × 値の範囲の長方形の点の個数）を答える問題全般。点の座標を $x$ でソートして $y$ を列にすれば、長方形内の点の個数がオンラインで求まる。
