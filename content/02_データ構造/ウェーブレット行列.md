ライブラリ：[wavelet_matrix.hpp](https://github.com/winter-2521/cp-library/blob/main/data_structure/wavelet_matrix.hpp)

## 何ができるアルゴリズムか？

**静的な** 数列に対して、次を $O(\log \sigma)$（$\sigma$ は値の種類数）で求める。

- 区間 $[l, r)$ の $k$ 番目に小さい値
- 区間内の $x$ 未満の値の個数（区間 × 値の範囲の長方形の点の個数）
- 区間内の $x$ 未満の最大値・$x$ 以上の最小値

>[!問題] Range Kth Smallest (Library Checker)
>長さ $N$ の数列に $Q$ 個のクエリ：$(a_l, \ldots, a_{r-1})$ のうち $k+1$ 番目に小さい値を出力せよ。$N, Q \le 2 \times 10^5$

## 計算量

構築 $O(n \log \sigma)$、各クエリ $O(\log \sigma)$。メモリは $n \log \sigma$ ビット + α。

## 具体例で理解する

### アイデア：値の上のビットから順にふるい分ける

区間 $k$ 番目を求めたい。値を 2 進数で見て、**一番上のビットが 0 の値は、1 の値より必ず小さい**。区間内に「上のビットが 0 の値」が $c$ 個あれば、$k < c$ なら答えはその中にあり（上のビットは 0）、そうでなければ 1 の値の中の $(k - c)$ 番目。これを下のビットまで繰り返せば答えのビットが上から 1 つずつ決まる。

問題は「区間内で上のビットが 0 の値がいくつあるか」と「次のビットに進むとき、注目している値たちが列のどこにあるか」を速く知ること。

### 持っているもの

値のビット数を $L$ とし、段 $h = L-1, \ldots, 0$ ごとに：

| 名前 | 意味 |
| --- | --- |
| $B_h$ | ビット列。段 $h$ の時点の列の各値の、第 $h$ ビットを並べたもの |
| $z_h$ | $B_h$ の 0 の個数 |

段 $h$ の列は、1 つ上の段の列を「第 $h+1$ ビットが 0 のもの → 1 のもの」の順に、**元の順番を保ったまま** 並べ替えたもの（一番上の段は元の配列）。保存するのは $B_h$ と $z_h$ だけで、列そのものは保存しない。

$B_h$ の「$[0, i)$ にある 1 の個数」$\mathrm{rank}_h(i)$ が $O(1)$ で求まるようにしておく（64 ビットごとに累積の個数を前計算し、端数は popcount）。

### 例：$a = [5, 2, 7, 1, 3]$（3 bit）

| 値 | 5 | 2 | 7 | 1 | 3 |
| --- | --- | --- | --- | --- | --- |
| 2 進 | 101 | 010 | 111 | 001 | 011 |

- **段 2**：列 $[5, 2, 7, 1, 3]$。bit 2 → $B_2 = 1\,0\,1\,0\,0$、$z_2 = 3$。
  次の列（0 のもの → 1 のもの）：$[2, 1, 3 \mid 5, 7]$
- **段 1**：列 $[2, 1, 3, 5, 7]$。bit 1 → $B_1 = 1\,0\,1\,0\,1$、$z_1 = 2$。
  次の列：$[1, 5 \mid 2, 3, 7]$
- **段 0**：列 $[1, 5, 2, 3, 7]$。bit 0 → $B_0 = 1\,1\,0\,1\,1$。

### 区間が次の段のどこに移るか

段 $h$ で区間 $[l, r)$ を見ているとき、その中の値は次の段で

- 第 $h$ ビットが **0** のもの → $[\,l - \mathrm{rank}_h(l),\ r - \mathrm{rank}_h(r)\,)$
- 第 $h$ ビットが **1** のもの → $[\,z_h + \mathrm{rank}_h(l),\ z_h + \mathrm{rank}_h(r)\,)$

に、まとまって並んでいる。理由：0 のものは列の先頭から順番を保って詰められるので、区間の 0 たちの手前には「位置 $l$ より前にある 0（$l - \mathrm{rank}_h(l)$ 個）」だけが来る。1 のものは $z_h$ 番目以降に同様に詰められる。

### kth_smallest(l, r, k) の手順

答え `res` = 0。$h = L-1, \ldots, 0$ について：

1. 区間内の 0 の個数 $c$ = $(r - \mathrm{rank}_h(r)) - (l - \mathrm{rank}_h(l))$。
2. $k < c$ なら：答えの第 $h$ ビットは 0。区間を 0 の側へ移す。
3. そうでなければ：答えの第 $h$ ビットは 1（`res` に足す）。$k$ -= $c$。区間を 1 の側へ移す。

### 例で追う：$[1, 4)$（中身 $[2, 7, 1]$）で 0-indexed の $k = 1$（答えは 2）

| 段 | 区間 | $B_h$ の区間部分 | 0 の個数 $c$ | 判定 | 答えのビット | 次の区間 |
| --- | --- | --- | --- | --- | --- | --- |
| 2 | $[1, 4)$ | $0\,1\,0$ | 2 | $k=1 < 2$ → 0 側 | 0 | $[1-1,\ 4-2) = [0, 2)$ |
| 1 | $[0, 2)$ | $1\,0$ | 1 | $k=1 \ge 1$ → 1 側、$k = 0$ | 1 | $[2+0,\ 2+1) = [2, 3)$ |
| 0 | $[2, 3)$ | $0$ | 1 | $k=0 < 1$ → 0 側 | 0 | |

答え $010_2 = 2$。（段 1 の区間 $[0,2)$ の中身は $[2, 1]$、段 0 の区間 $[2,3)$ の中身は $[2]$ で、確かに追えている。）

各段で rank を 2 回求めるだけなので $O(L)$。実際のライブラリでは値を座標圧縮してから行うので、$L$ は値の種類数の $\log$。

### 「$x$ 未満の個数」も同じ要領

上のビットから $x$ のビットと比べながら降りる。$x$ の第 $h$ ビットが 1 の段では、区間内で第 $h$ ビットが 0 の値は（上のビットは $x$ と同じで）$x$ より小さいので全部数え、1 の側へ進む。$x$ のビットが 0 の段では 0 の側へ進むだけ。

## 証明・仕組み

値を座標圧縮して $[0, 2^L)$ の整数にし、上のビットから順に処理する。

**構築**：段 $h = L-1, \ldots, 0$ について、現在の列の各値の第 $h$ ビットを並べたビット列 $B_h$ を記録し、列を「第 $h$ ビットが 0 のもの（順番を保って）→ 1 のもの」に並べ替えて次の段へ。$B_h$ の 0 の個数を $z_h$ とする。

**rank**：$B_h$ の $[0, i)$ の 1 の個数 $\mathrm{rank}_1(i)$ が $O(1)$ で求まるようにしておく（64 bit ごとに累積の個数を持ち、端数は popcount）。

**区間の移動**：段 $h$ で区間 $[l, r)$ にある要素は、次の段では

- ビット 0 のもの → $[l - \mathrm{rank}_1(l),\ r - \mathrm{rank}_1(r))$
- ビット 1 のもの → $[z_h + \mathrm{rank}_1(l),\ z_h + \mathrm{rank}_1(r))$

に（相対順序を保って）まとまっている。安定な並べ替えなので「$[l, r)$ にあった要素のうちビット 0 のもの」は次の段で連続し、その位置は $l$ より前にあるビット 0 の個数で決まる。

**$k$ 番目**：上のビットから、区間内のビット 0 の個数 $c$ を見て、$k < c$ なら答えのこのビットは 0（0 の側へ）、そうでなければ 1（$k \mathrel{-}= c$ して 1 の側へ）。各段 $O(1)$。

**$x$ 未満の個数**：$x$ のビットを上から見て、$x$ のビットが 1 の段では「ビット 0 の側に行った要素」は全て $x$ 未満なので数えて、1 の側へ進む。0 の段では 0 の側へ。

**前後の値**：$x$ 未満の個数 $c$ を求め、$c - 1$ 番目（$x$ 未満の最大値）や $c$ 番目（$x$ 以上の最小値）を $k$ 番目で求める。

### ウェーブレット木との違い

ウェーブレット木は値の範囲で二分木を作るが、ウェーブレット行列は各段を 1 本のビット列にまとめる（並べ替え方を工夫している）ので、ポインタが不要で実装もメモリも軽い。

## 例題・類題

- [Range Kth Smallest (Library Checker)](https://judge.yosupo.jp/problem/range_kth_smallest)
- [POJ 2104 - K-th Number](http://poj.org/problem?id=2104)：区間 $k$ 番目の古典。[[永続遅延セグメント木]]（永続セグ木）でも解ける。
- [ABC339 G - Smaller Sum](https://atcoder.jp/contests/abc339/tasks/abc339_g)：強制オンラインで「区間内の $x$ 以下の値の和」。各段に「ビット 0 の側に行った値の累積和」を持たせれば同じ要領で和も求まる。
- 区間内の値の個数（区間 × 値の範囲の長方形の点の個数）を答える問題全般。点の座標を $x$ でソートして $y$ を列にすれば、長方形内の点の個数がオンラインで求まる。
