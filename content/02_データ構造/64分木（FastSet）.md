#データ構造 #高速化

ライブラリ：[fast_set.hpp](https://github.com/winter-2521/cp-library/blob/main/data_structure/fast_set.hpp)

## 何ができるアルゴリズムか？

$[0, n)$ の整数の集合に対して、挿入・削除・存在判定・「$i$ 以上の最小の要素」・「$i$ 以下の最大の要素」を $O(\log_{64} n)$ で処理する。$n = 10^6$ でも 4 段なので、`std::set` より 1 桁速い。

>[!問題] Predecessor Problem (Library Checker)
>$[0, N)$ の整数からなる集合 $S$ に対して、挿入・削除・存在判定・$k$ 以上の最小の要素・$k$ 以下の最大の要素 を $Q$ 回処理せよ。$N, Q \le 10^7$ 程度

## 計算量

| 操作 | 計算量 |
| --- | --- |
| 構築 | $O(n / 64)$（初期要素ありなら $O(n)$） |
| 挿入・削除 | $O(\log_{64} n)$ |
| 存在判定 | $O(1)$ |
| next / prev | $O(\log_{64} n)$ |
| メモリ | 約 $n / 8$ バイト |

## 証明・仕組み

64 分木を「各段がビット列」の形で持つ。

- 最下段 `seg[0]` は長さ $n$ のビット列で、$i$ ビット目が「$i \in S$」。
- `seg[h+1]` の $j$ ビット目は「`seg[h]` の $j$ 番目の 64 bit ワードが 0 でない」。

$n = 10^6$ なら段の長さは $10^6 \to 15625 \to 245 \to 4 \to 1$ ワードで 4〜5 段。

**挿入**：最下段のビットを立て、そのワードが元々 0 だったら上の段のビットも立てる…と上がる。元々 0 でなければ上の段は既に立っているので打ち切る。削除も同様（ワードが 0 になったときだけ上に伝える）。

**next($i$)**：最下段の $i$ を含むワードを $i$ 以上だけ見るようシフトして、0 でなければ `ctz`（最下位の 1 の位置）で答えが出る。0 なら、上の段で「$i$ のワードより右にある、空でないワード」を同じ方法で探し、見つかったらそこから下の段へ `ctz` で降りる。各段で $O(1)$ のビット演算なので $O(\text{段数})$。prev は `clz` で対称に。

`std::set` は平衡二分木で $\log_2 n \approx 20$ 回のポインタ追跡（キャッシュミス）があるが、こちらは数回の配列アクセスで済む。

## 例題・類題

- [Predecessor Problem (Library Checker)](https://judge.yosupo.jp/problem/predecessor_problem)
- [ABC228 D - Linear Probing](https://atcoder.jp/contests/abc228/tasks/abc228_d)：「まだ埋まっていない位置で $h$ 以上の最小のもの」を求める。未使用の位置の集合を持てば `next` 一発（末尾を超えたら `next(0)`）。
- 「まだ使われていない番号のうち最小のもの」「次の空き」を繰り返し求める問題全般（区間を塗るときに塗られていない位置だけを訪れる、など）。
- 順位（$k$ 番目、$x$ 以下の個数）も必要なら [[順序付き集合（ブロックAVL木）]] を使う。
